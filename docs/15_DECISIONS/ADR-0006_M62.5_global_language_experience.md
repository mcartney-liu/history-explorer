# ADR-0006 — M62.5 Global Language Experience System: Freeze-Scope Revision

## ADR Number

ADR-0006

## Title

M62.5 Global Language Experience System — Freeze-Scope Revision (i18n/l10n + Emoji-Free Hardening)

## Status

Accepted (2026-07-30, PO-approved via the vM-series harvest route — explicit "按方案A去做，并把M62.5发掉").

## Context

M62.5 (Global Language Experience System) is a **pure-frontend** milestone inserted
between M62 (vM62, `68cd0fa`) and M63. It delivers:

- **i18n runtime** (`data/locale.tsx`): `LocaleProvider` + `useLocale` with live
  switching across zh/en/ja, resource loading + fallback wired through
  `lib/preferences.ts`.
- **l10n resources** (`locales/{zh,en,ja}/*`): namespace skeletons externalizing
  UI copy from hardcoded strings.
- **Terminology layer** (`getTermLabel`): consistent proper-noun rendering (W4
  Proper Name Display Policy).
- **Language UX** (`LanguageSwitcher.tsx`): replaces the inline toggle in
  `AppShell.tsx`; preference persisted via `lib/preferences.ts` (localStorage).
- **W10 R14 closure**: the full vitest suite migrated to locale-aware assertions
  (Chinese under `<LocaleProvider>`); 941/941 green.

During the W10 migration and a follow-up full-project health review, two freeze
boundary items surfaced that require a **Freeze Revision Gate**:

1. **W10 test files outside the allowlist.** The 4 component-level integration
   tests migrated in W10 (`frontend/src/components/__tests__/CrossTopicBridge`,
   `ExplorationJourney`, `ExplorationPathTree`, `RecommendationPanel`) live under
   `frontend/src/components/__tests__/`, which was NOT in the SCOPE_ALLOWLIST
   (only `frontend/src/__tests__/` was). These are the inevitable locale-aware
   companions of the M62.5 i18n externalization — same gate as the already
   allowlisted `frontend/src/__tests__/`.
2. **Emoji-free hardening (Gate 2).** A full-project scan (tightened
   `emoji-scan.mjs`) revealed 13 production/test files still using symbol glyphs
   as functional icons — `★☆✓✗⚠○◷●` — which violate P0-1. This included 3
   *pre-existing* real-emoji violations (`EntityHero`, `EntityInsightCard`,
   `EventNarrativeJourney`) that hid in the old scanner's Geometric-Shapes blind
   spot, predating M62.5. The registry was extended with `star`/`warning`/
   `circle`/`cross`/`time-period` and those files migrated to SVG.

Freeze boundary impact: **Backend / schema / API / new-dependency / LLM / Neo4j /
GIS / login-permission: NONE.** Runtime stays `0.13.0`; ENTITY_TYPES=8 /
RELATIONSHIP_TYPES=18 untouched. All changes are within the existing
`entity/` / `components/` / `__tests__` allowlist prefixes plus one new
directory-prefix entry.

## Decision

1. **Extend `scripts/freeze-check.mjs` SCOPE_ALLOWLIST** with the directory
   prefix `frontend/src/components/__tests__/` (test-only). This is a scope
   *confirmation* of the already-approved M62.5 gate, not a new gate — symmetric
   with the existing `frontend/src/__tests__/` entry. Editing `scripts/`
   itself is exempt from the freeze check (allowlist mechanics).
2. **Tighten `scripts/emoji-scan.mjs`** — extend the emoji regex to the
   Geometric Shapes block (`25A0–25FF`) and remove the dingbat carve-out
   (`★☆✓✗⚠○`), so `★☆✓✗⚠○◷●` are all enforced as P0-1 violations. This closes
   the regression blind spot that let the 3 pre-existing violations hide.
3. **Extend the canonical SVG registry** (`frontend/src/components/ui/Icon.tsx`)
   with `star` / `warning` / `circle` / `cross` / `time-period` (all rendered as
   real `<svg><path>`, `filled` supported for the solid dot/cross states). Every
   icon renders a `<path>` so the `m62-icon-registry` guardrail stays valid.
4. **Migrate 13 files** off symbol glyphs to the registry — production:
   `ResearchBookmarkButton`, `ResearchDimensionCard`, `ResearchLibrary`,
   `ResearchReport`, `DiscoverPage`, `EntityHero`, `EntityInsightCard`,
   `EventNarrativeJourney`; plus the 4 W10 component tests and 1 assertion in
   `ResearchReport.test.tsx` / `ResearchBookmarkButton.test.tsx` /
   `ResearchLibrary.test.tsx` / `DiscoverPage.test.tsx` that asserted the old
   glyphs.

## Alternatives

- **Ship M62.5 with the 4 W10 tests left un-allowlisted** — rejected: the freeze
  guard would fail and block the release; the tests are the approved i18n
  companions, not out-of-scope work.
- **Leave the 3 pre-existing emoji violations for a later cleanup** — rejected per
  PO's 方案A: vM62.5 must be a *truly* emoji-free baseline ("过了门禁 ≠ 真的
  emoji-free" was the exact gap identified in the health review), so they are
  fixed in this same gate.
- **Add a brand-new gate for each new file** — rejected: ballooning the allowlist
  with per-file entries is the governance smell flagged in the health report; the
  directory-prefix approach keeps it coarse and auditable.

## Consequences

- vM62.5 ships with freeze-check EXIT 0, emoji-scan EXIT 0, tsc EXIT 0, and
  vitest 941/941 green — a clean, verified emoji-free baseline.
- The emoji-guard now covers the Geometric Shapes block; future `◷ ● ○` style
  regressions are caught in CI (not just the standalone script).
- SCOPE_ALLOWLIST grew by exactly one directory-prefix entry — minimal,
  auditable scope change. No architecture-baseline revision is required beyond
  this documentation; the freeze *policy* is unchanged, only confirmed wider.
