## 1. 信息架构总纲

### 1.1 一个容器、四条主干、两层底座

### 1.2 三条结构原则

| 原则 | 内容 | 服务的 Exit Criteria |
|------|------|--------------------|
| P-A 单容器 | 全部 30 个触点在同一 Session 内可达；不存在需要离开才能完成的能力 | 不跳出产品 |
| P-B 语法恒定 | 四条主干共用同一探索语法：**锚点 → 关系 → 理由 → 推进**。主干之间换的是提问角度，不是操作方式 | 不出现多个产品感 |
| P-C 常驻不换台 | 常驻层六项在主干切换时**不重置、不消失、不改变含义**。用户切换主干不等于开始一次新探索 | 无体验断裂 |

> **主干不是模式，不是频道，不是产品线。** P1-01 §5.1 已排除「Mode ×5」为能力；本文的四主干是**用户提问角度的分类**，不是五个 Mode 的改名，也不是四个独立产品。

## 2. 四条主干定义

### 2.1 Explore（探索）—— 「这是什么，它和什么相连」

| 项 | 内容 |
|----|------|
| 心智问题 | 我面前是什么？它和什么连着？我还能往哪走？ |
| 主属触点 | TP-01 事实落地面（C01）· TP-02 关系展开面（C02）· TP-03 边界续走位（C03）· TP-04 时间对齐轴（C04）· TP-05 地点锚定位（C05）· TP-24 定向直达（C24）· TP-25 问题锚（C25）· TP-26 起跳台（C26）· TP-27 停滞接住（C27） |
| 入口条件 | 首访默认落点；或从任一主干携带「我想看看这个对象本身」的意图返回 |
| 退出条件 | 用户从「是什么」转向「为什么」（→ Understand）、转向「别处怎么样」（→ Compare），或走尽当前主题（→ TP-03 续走新主题） |
| 首屏心智约束 | 首屏由 TP-26 起跳台承担，**不由 TP-24 检索主导**（R6 / ADR-0014 D2）。检索作为常在但不抢戏的次级直达通道 |

### 2.2 Understand（理解）—— 「为什么会这样，这凭什么可信，这对我什么意义」

| 项 | 内容 |
|----|------|
| 心智问题 | 为什么会这样？谁说的、依据多硬？这个机制对我理解整体有什么用？ |
| 主属触点 | TP-10 机制陈述面（C10）· TP-11 连接理由行（C11）· TP-12 人话转译（C12）· TP-13 意义入口（C13）· TP-06 来源分级刻度（C06）· TP-07 证据强度刻度（C07）· TP-08 溯源清单与异议叙述（C08） |
| 入口条件 | 用户在 Explore 中对某条关系或某个结论产生「为什么 / 凭什么」之问 |
| 退出条件 | 机制被说清且意义被建立 → 转 Compare 检验普遍性，或经 TP-16 推进回 Explore |
| 内部权威顺序 | TP-12（AI Gateway）> TP-10（Causal）> TP-11（模板短语），高阶不可用时低阶以自身身份出场（ADR-0015 D4；细则见 B1 §3.2） |

> **真相刻度归属说明**：TP-06 / TP-07 / TP-08 归属 Understand 主干，但**呈现位置在任一结论处**，包括 Explore 与 Compare 主干下的结论。归属定义的是「它回答哪一类问题」，不是「它只在某一处出现」。这是 C2 落点得以贴住每一条结论、而用户又不必为查证换主干的关键（B1 §5.2 第 1 条）。

### 2.3 Compare（对比）—— 「同时期别处怎么做的，差别为什么产生」

| 项 | 内容 |
|----|------|
| 心智问题 | 别的文明同期在做什么？为什么不一样？哪些是普遍规律、哪些是特例？ |
| 主属触点 | TP-14 对比台（C14） |
| 从属出场 | TP-04 时间对齐轴（同时性前提）· TP-13 意义入口（对比结论的落点）· TP-03 跨主题连通（对比对象的结构来源）· 真相刻度三件套（对比结论同样要挂刻度） |
| 入口条件 | **两个并列入口**：① 从 Understand 自发触发（用户对某文明形成初步理解后想比较）；② **导航级独立入口**——用户不必先完成任何理解，可直接以「我想比较」进入（C3 落点） |
| 退出条件 | 对比结论形成 → 落 TP-13 成为理解结构，或转化为新的探索起点回 Explore |

**C3 落点（ADR-0015 D3 / R5）逐条落实：**

| 要求 | 本架构的落实 |
|------|------------|
| C14 提为 P0 | Compare 是四条主干之一，与 Explore / Understand 同级，不是 Explore 的子级 |
| 导航有独立入口 | 用户可从常驻层直接进入 Compare，无前置条件；不要求先选定实体 |
| 首访路径有入口 | B2 首访旅程 T4 段落安排 Compare 出场；且 T1 段落即让用户知道「这里可以比较」，避免比较需求出现时找不到门 |
| 供给不足的诚实处理 | 对比台以「可对比对象成对存在」为出场条件；不成对时呈现已知边界说明 + TP-16 补齐动作，不做空入口（B1 §9 F-3） |

> **主干容量说明**：Compare 主属触点仅 1 项，Mirror 仅 2 项，而 Explore 有 9 项。**主干的分量由它回答的心智问题决定，不由触点计数决定。** C14 是四场用研三场自发提出的最强差异点（P1-01 C14），把它压回 Explore 的子级就是把最强需求藏起来。

### 2.4 Mirror（镜像）—— 「我是怎么走的，我对什么反复回头」

| 项 | 内容 |
|----|------|
| 层位 | **L4.5 只读投影出口**（ADR-0015 D2），Runtime 之上、Experience 之下 |
| 心智问题 | 这一次我走了什么路？我反复回到哪些维度？我惯用哪种推进方式？ |
| 主属触点 | TP-22 镜像出口（C22）· TP-19 成长刻度（C19） |
| 原料来源 | TP-20 轨迹链 · TP-15 认知状态 · TP-19 四项增量。**只读，不写回** |
| 入口条件 | 会话内已积累可被照见的轨迹；在离场意图处主动出场 |
| 退出条件 | **反射即终点。无出边。** |

**Mirror 的四条导航级防火墙（C4 落点，守 ADR-0013 D3）：**

| 防火墙 | 导航层含义 |
|--------|-----------|
| 无出边至 TP-16 | Mirror 页内不得出现任何「下一步去看 X」；用户想继续，走常驻层回 Explore，而不是由镜像牵引 |
| 不作 ExplorationPolicy 输入 | 导航上不存在「Mirror → Policy」这条路径；A1 §2 输入契约中也无镜像字段 |
| 只反射本次会话 | Phase 2 不持久化（ADR-0015 D6），导航语义上 Mirror 是「本次探索的回望」，不是「你的长期画像」 |
| 解读权归用户 | Mirror 给结构不给结论，不评级、不打分用户本人 |

> **为什么 Mirror 必须是主干而不是一个附属出口**：Article 0 第二句是三层定位之一，且是 P1-00 判定「交付率为零」的那一层。若把它挂成某个次级位置，它会被首访用户完全错过，第二句在体验上继续为零。作为主干意味着它在导航中始终可见、离场必经。

## 3. 探索语法恒定（「不出现多个产品感」的机制）

四条主干的**动作序列完全同构**，只有提问角度不同：

| 语法步 | Explore | Understand | Compare | Mirror |
|--------|---------|-----------|---------|--------|
| 锚点 | 一个历史实体 | 一条结论 | 一组可比对象 | 用户自己的一段轨迹 |
| 关系 | 它连向谁 | 它依据什么 | 它们在何处分岔 | 这些锚点如何串起来 |
| 理由 | 为什么连（TP-11） | 为什么可信（TP-06/07/08） | 为什么不同（TP-13） | 为什么你反复回来（用户自答） |
| 推进 | TP-16 下一步 | TP-16 下一步 | TP-16 下一步 | **无推进（终点）** |

**用户学会一次，四处通用。** 这一同构性由 C29（TP-29 探索语法恒定）在能力层承载，由 C30（TP-30 一致性承诺）在治理层守护。Mirror 在「推进」一格为空，是唯一且刻意的差异，且这一差异本身就是它作为终点的语义表达。

补充三条防多产品感的约束：

1. **术语全局唯一**（TP-28 / C28）：同一历史对象在四主干下名称一致，关系语义在四主干下含义一致。
2. **定位不换台**（TP-23 / C23）：主干切换时，「我从哪来、为什么来、这一步价值」的叙述连续，不重置为空。
3. **不引入第五种入口范式**：任何未来能力必须归入四主干之一或常驻层，不得新开一条主干。新开主干需走 Freeze Revision Gate。

## 4. C1 落点：「下一步」的导航语义（ExplorationAction，非推荐）

> 依据 ADR-0015 D1 + A2 契约。TP-16 是常驻层触点，四主干下均在场。

### 4.1 导航层的五种推进动作

TP-16 呈现的是 A2 `ExplorationAction`，其 `actionType` 五值直接对应导航去向：

| actionType | 用户读到的意思 | 导航去向 |
|-----------|--------------|---------|
| `open_dimension` | 你还没看过这个维度 | Explore 主干（新维度锚点） |
| `follow_cause` | 这条因果链你还缺一环 | Understand 主干（TP-10） |
| `deep_continue` | 当前这条线还能再深 | 停留在当前主干，锚点下沉 |
| `compare_context` | 别处同期是另一种做法 | **Compare 主干**（TP-14） |
| `reflect` | 你手上的东西可以收一收了 | Understand 收束，或引向 Mirror 的出场时机 |

### 4.2 导航层的四条命名与呈现红线

| 红线 | 内容 |
|------|------|
| 命名 | 导航语汇中禁用「推荐 / 猜你喜欢 / 相关内容 / 其他用户也看了」。使用「下一步探索 / 继续深入 / 换个角度看」 |
| 理由可读 | 每个下一步必须携带 `rationale.text`，用户能读到「为什么是它」；`ruleId` + `triggeredDimension` 在审计态可查（A2 §4.2） |
| 缺口可见 | 下一步必须表达它补的是哪个缺口，并以 `coverageBeforeAfter.delta` 表达补多少 |
| 唯一出口 | 全产品只有 TP-16 一个「下一步」出口。旧 `/recommendations` 端点在导航架构中**无任何位置**（A3 §2；守 P1-05 §6 硬约束 1） |

### 4.3 TP-16 与 TP-24 / TP-27 的分工

| 触点 | 用户处境 | 输入信号 |
|------|---------|---------|
| TP-24 定向直达 | 我知道我要找什么 | 用户已有目标名词 |
| TP-27 停滞接住 | 我停下了，不知道现在该做什么动作 | 停滞状态（确定性引导，禁个性化、禁打分） |
| TP-16 下一步探索 | 我这一段做完了，不知道下一段去哪 | 认知缺口（`coverageRatio` / `missingDimensions` / `missingConnections`） |

三者输入信号互不相同，永不互相替代，也不得互相伪装。TP-27 给的是**动作提示**（确定性模板），TP-16 给的是**方向决策**（规则可审计）——这条区分守住 C27 不滑向 X01。

## 5. 常驻层六项的导航职责

| 触点 | 能力 | 在导航中回答 | 主干切换时的行为 |
|------|------|------------|----------------|
| TP-23 | C23 | 我在哪、我从哪来、我为什么在这、这一步值什么 | 叙述连续，From/Why/Value 不清空 |
| TP-20 | C20 | 我走过的锚点链与关系链 | 累加，不因换主干而分叉成两条 |
| TP-15 | C15 | 我覆盖了什么、还缺什么 | 全局唯一状态，不按主干各算一份 |
| TP-18 | C18 | 上一段留下的缺口 | 会话内延续（会话态，ADR-0015 D6） |
| TP-16 | C16 | 下一步去哪 | 四主干下均在场，语义一致 |
| TP-28 | C28 | 用什么语言、什么术语说 | 切换语言不改变认知对象身份 |

**常驻层是「不跳出产品」与「无断裂」的日常保证**：用户在任何位置都不会失去坐标，因此不需要退出去重新找路。

## 6. 隐性底层五项的导航职责

| 触点 | 能力 | 导航层作用 | 缺席时用户的感受 |
|------|------|-----------|----------------|
| TP-09 | C09 | 保证任何一条导航路径都不指向断链 | 点进去是空的，直接离场 |
| TP-17 | C17 | 保证认知状态在任何路径下可复现 | 进度忽高忽低，产品像在骗人 |
| TP-21 | C21 | 保证同一决策在不同位置的表达粒度得当 | 到处是生硬模板，读不下去 |
| TP-29 | C29 | 保证换主题、换领域时语法不变 | 每个主题像一个新产品（多产品感的直接来源） |
| TP-30 | C30 | 保证术语、关系语义、禁区不悄悄漂移 | 产品前后自相矛盾 |

## 7. 主干间转移矩阵（体验连续性的导航证明）

行 = 从，列 = 到。每格给出转移的触发者与携带物。

| 从 \ 到 | Explore | Understand | Compare | Mirror |
|---------|---------|-----------|---------|--------|
| **Explore** | TP-03 续走 / TP-16 `deep_continue` | 用户问「为什么、凭什么」；TP-16 `follow_cause` | TP-16 `compare_context`；或常驻层直入 | 离场意图触发 |
| **Understand** | TP-16 `open_dimension`，携带新维度 | TP-10 → TP-13 内部推进 | 意义建立后自发比较；TP-16 `compare_context` | 离场意图触发 |
| **Compare** | 对比结论转为新探索起点，回 TP-01 | 对比结论落 TP-13 建立意义 | 换一组对比对象 | 离场意图触发 |
| **Mirror** | 用户经**常驻层**自行返回 | 用户经**常驻层**自行返回 | 用户经**常驻层**自行返回 | — |

> **Mirror 行的写法是刻意的**：Mirror 不主动把用户送去任何地方。用户想继续，是他自己走常驻层回去，不是镜像牵引他去。这一格的写法即 ADR-0013 D3 防火墙在导航层的具体形态。
>
> 全表无空格：任意两主干之间都有明确的转移方式与携带物，故**不存在导航死角**。

**计数校验**：Explore 9 + Understand 7 + Compare 1 + Mirror 2 + 常驻层 6 + 隐性底层 5 = **30**。并集 = C01–C30，交集为空，无遗漏、无重复。

## 9. 导航守则（供 Phase 3 交互架构继承，本阶段只作约束不作设计）

1. **单容器守则**：任何能力不得以「离开本产品去完成」的方式设计。
2. **主干守则**：只有四条主干；新增能力归入现有主干或常驻层，新开主干须走 Freeze Revision Gate。
3. **首屏守则**：首屏心智由 TP-26 承担；TP-24 检索可在场但不得主导（R6 / ADR-0014 D2）。
4. **下一步守则**：全产品唯一「下一步」出口是 TP-16，契约来源唯一为 A2 `ExplorationAction`；禁用推荐语汇。
5. **对比守则**：Compare 必须可直入，不得退化为某个实体的下级功能。
6. **镜像守则**：Mirror 无出边；不得成为任何决策的输入；只反射本次会话。
7. **刻度守则**：真相刻度三件套贴住结论出现，不要求用户换主干或跳外部去查证。
8. **常驻守则**：常驻层六项在主干切换时不重置、不消失、不改义。
