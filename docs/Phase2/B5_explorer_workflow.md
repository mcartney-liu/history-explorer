## 1. 两条路径的区分

用户在一次会话里同时走两条路，二者常被混为一谈，混淆的直接后果就是把「点得多」当成「懂得多」。

| 项 | 理解路径 Understanding Path | 探索路径 Exploration Path |
|----|---------------------------|--------------------------|
| 方向 | 纵向（深度） | 横向（广度） |
| 回答 | 我对这件事理解到什么程度 | 我走过了哪些地方 |
| 单位 | 认知阶段 stage | 锚点与关系 |
| 状态载体 | `understandingStage` + `coverageRatio`（C15） | `exploredAnchors` + 锚点链 / 关系链（C20） |
| 推进物 | 机制、意义、可信度 | 跳转 |
| 走完的样子 | 能讲出来龙去脉，并知道它多可信 | 轨迹上有一串带 From/Why 的锚点 |
| 失控的样子 | 停在 FACT 阶段反复看事实，理解不长 | 跳了几十个点，一个都说不出为什么 |

**两条路径必须同时被度量**，否则产品会奖励错误行为。只度量探索路径 = 奖励乱点；只度量理解路径 = 奖励在原地深挖而不出主题。

## 2. 统一工作流模型

### 2.1 四阶段主脊（沿用既有 `understandingStage` 口径，不另造）

```
        ┌───────────────────────── 一次 Explorer Session ─────────────────────────┐
        │                                                                          │
  进场 →│  FACT  ────→  CONTEXT  ────→  UNDERSTANDING  ────→  SYNTHESIS            │→ 离场
        │  这是什么      它处在什么     为什么会这样        这意味着什么             │
        │               关系里         这凭什么可信         别处是不是也这样         │
        │     ▲            ▲               ▲                    ▲                 │
        │     └────────────┴───────────────┴────────────────────┘                 │
        │              推进机制（跨阶段，驱动 stage 迁移）                            │
        │       TP-15 状态 · TP-16 下一步 · TP-17 投影 · TP-18 记忆                 │
        │       TP-20 轨迹 · TP-23 定位 · TP-27 停滞接住 · TP-28 术语               │
        │                                                                          │
        │              恒在保障（不迁移，全程生效）                                   │
        │       TP-09 无死路 · TP-21 表达粒度 · TP-29 语法恒定 · TP-30 一致性        │
        └──────────────────────────────────────────────────────────────────────────┘
                                          │
                                          ▼  （仅 SYNTHESIS 之后、离场之时）
                                   TP-22 镜像出口（L4.5 终点，无回边）
```

### 2.2 两条路径在四阶段中的合流点

四阶段是**理解路径**的刻度。探索路径不是另一条平行线，它是**理解路径每次推进时在结构上留下的位移**。二者合流于唯一一处：**TP-16 下一步（ExplorationAction）**。

这是本文的核心模型：

| ExplorationAction 的 actionType | 理解路径发生什么 | 探索路径发生什么 |
|-------------------------------|----------------|----------------|
| `deep_continue` | 当前阶段内加深，`coverageRatio` 上升 | **不移动**（同锚点下沉） |
| `open_dimension` | 覆盖维度 +1，可能推进到下一阶段 | 移动到新维度的锚点 |
| `follow_cause` | 因果连接 +1，通常推进至 UNDERSTANDING | 移动到因果链的对端 |
| `compare_context` | 通常推进至 SYNTHESIS | 横向跨到对照语境（可跨主题） |
| `reflect` | 收束当前所得，stage 定格 SYNTHESIS | **不移动** |

**读表要点**：五种动作里，两种（`deep_continue` / `reflect`）**不产生位移**。这一点是「探索 ≠ 点击」的工作流级证明——系统给出的下一步有五分之二不要求用户跳走。一个以停留时长为目标函数的系统不会这样设计。

## 3. 工作流节点表（TP-01 … TP-30 全量）

### 3.1 FACT 阶段：这是什么（6 节点）

| 节点 | 能力 | 属哪条路径 | 该节点做什么 | 迁出条件 |
|------|------|-----------|------------|---------|
| TP-26 起跳台 | C26 | 探索路径起点 | 把好奇翻译成第一次跳转 | 用户选定第一个锚点 |
| TP-25 问题锚 | C25 | 理解路径起点 | 把好奇落成整次探索的语义锚 | 问题成型 |
| TP-24 定向直达 | C24 | 探索路径（次级入口） | 已知目标者直达；**不产生理解** | 命中并转入 TP-01 |
| TP-01 事实落地面 | C01 | 理解路径 | 给出带来源标注与结构化时间的事实 | 事实需求满足 |
| TP-02 关系展开面 | C02 | 两者交汇 | 事实连出结构，第一次位移的来源 | 用户转问「为什么」 |
| TP-05 地点锚定位 | C05 | 探索路径（降级态） | 以具名地点作为可跳转锚点接住空间之问 | 转回 TP-02 |

### 3.2 CONTEXT 阶段：它处在什么关系里、这凭什么可信（6 节点）

| 节点 | 能力 | 属哪条路径 | 该节点做什么 | 迁出条件 |
|------|------|-----------|------------|---------|
| TP-04 时间对齐轴 | C04 | 理解路径 | 建立先后与同时性，为 SYNTHESIS 的对比备料 | 时间疑问解答 |
| TP-03 边界续走位 | C03 | 探索路径 | 主题走尽时跨出去，避免撞墙 | 落到新主题锚点 |
| TP-11 连接理由行 | C11 | 理解路径 | 与连线同时出场，说清「为什么被放在一起」 | 用户接受或否定 |
| TP-06 来源分级刻度 | C06 | 理解路径（真值） | 「谁说的」，三级口径全局唯一 | 用户形成来源判断 |
| TP-07 证据强度刻度 | C07 | 理解路径（真值） | 「凭什么」，有序刻度 | 用户认可或保留意见 |
| TP-08 溯源与异议叙述 | C08 | 理解路径（真值） | 「有没有人不同意」，无异议须明说 | 整体可信度判断形成 |

### 3.3 UNDERSTANDING 阶段：为什么会这样（3 节点）

| 节点 | 能力 | 属哪条路径 | 该节点做什么 | 迁出条件 |
|------|------|-----------|------------|---------|
| TP-10 机制陈述面 | C10 | 理解路径 | 说清机制、后果、置信度 | 机制被说清 |
| TP-12 人话转译 | C12 | 理解路径 | 结构转可读语言，引用须校验；失败即降级并降身份 | 转译产出并通过校验 |
| TP-13 意义入口 | C13 | 理解路径 | 回答「这对我理解整体有什么用」，长出理解结构 | 理解框架成型 |

### 3.4 SYNTHESIS 阶段：这意味着什么、别处是不是也这样（3 节点）

| 节点 | 能力 | 属哪条路径 | 该节点做什么 | 迁出条件 |
|------|------|-----------|------------|---------|
| TP-14 对比台 | C14 | 两者交汇 | 跨文明对照，区分普遍规律与特例；**P0 独立入口，可从任一阶段直入** | 对比结论形成 |
| TP-19 成长刻度 | C19 | 度量两条路径 | 汇总本次会话的认知结构变化（§5 会话态口径） | 成长快照产出 |
| TP-22 镜像出口 | C22 | 反射两条路径 | **L4.5 只读投影终点**（§6） | 反射即终点，无迁出 |

### 3.5 推进机制：跨阶段，驱动 stage 迁移（8 节点）

| 节点 | 能力 | 在工作流中的职责 |
|------|------|----------------|
| TP-15 认知状态读数 | C15 | 持续维护 `understandingStage` / `coverageRatio` / `missingDimensions` / `missingConnections`——**推进的唯一合法输入**（A1 §2） |
| TP-16 下一步探索 | C16 | 依 A1 规则短路产出 `Decision<ExplorationAction>`，同时决定理解路径是否推进与探索路径是否位移（§4） |
| TP-17 投影通道 | C17 | 把理解结构以只读投影送入运行时，运行时不直连知识图谱；保证状态可复现可回放 |
| TP-18 会话记忆延续 | C18 | 让后一段接得住前一段的缺口；**会话态，会话结束即销毁**（ADR-0015 D6） |
| TP-20 轨迹链 | C20 | 记录探索路径的锚点链与关系链，携带 From/Why；是 TP-22 的唯一原料 |
| TP-23 定位常驻条 | C23 | 每次位移都回答「我在哪、从哪来、为何来、这一步值什么」 |
| TP-27 停滞接住 | C27 | 停滞时给**动作提示**（确定性，禁个性化）；若停滞的是方向则交棒 TP-16 |
| TP-28 术语恒等 | C28 | 保证同一认知对象跨阶段、跨语言身份不变，理解可累积 |

### 3.6 恒在保障：不迁移，全程生效（4 节点）

| 节点 | 能力 | 缺席时工作流在哪里坏掉 |
|------|------|---------------------|
| TP-09 无死路保证 | C09 | 任一位移指向不存在的对象，探索路径断裂 |
| TP-21 表达粒度调节 | C21 | 每个节点的输出都生硬到用户接不住，理解路径卡在 FACT |
| TP-29 探索语法恒定 | C29 | 跨主题时用户要重学一套工作流，等于每次都从头开始 |
| TP-30 一致性承诺 | C30 | 阶段定义或术语语义中途漂移，前面走的路作废 |

## 4. 认知推进机制（C16 决策 + C18 记忆）

### 4.1 推进的唯一合法输入

```
   TP-17 投影通道（C17）
        │  只读投影，运行时不直连知识图谱
        ▼
   TP-15 认知状态（C15）
        │  coverageRatio / missingDimensions / missingConnections / understandingStage
        ▼
   TP-16 推进决策（C16）—— 按 A1 §4 规则短路
        │  输出 Decision<ExplorationAction>（A2）
        ▼
   理解路径推进 + 探索路径位移（§2.2 映射表）
        │
        ▼
   TP-20 轨迹（C20）累加 · TP-18 记忆（C18）保持缺口 · TP-15 状态更新
        └────────────────── 回到 TP-15，形成闭环
```

**闭环中不存在的输入**（工作流级的红线）：

| 不得作为输入 | 依据 |
|------------|------|
| 点击率、停留时长、流行度 | M88.0 §8.2；X01 定义 |
| 相似用户行为、协同过滤 | M88.0 §8.2 |
| 图相似度四权重打分 | A1 §1 明确拒绝口径 |
| LLM 对方向的判断 | M88.0 §8.2；C21 只管表达不管方向 |
| **TP-22 镜像的输出** | ADR-0013 D3 防火墙；B4 §5.5 |

### 4.2 A1 规则 → 工作流迁移的完整映射

| A1 规则 ruleId | 触发条件 | actionType | 理解路径 | 探索路径 |
|---------------|---------|-----------|---------|---------|
| `exploration-open-dimension` | `missingDimensions` 非空 | `open_dimension` | 维度 +1 | 位移至新维度锚点 |
| `exploration-follow-cause` | `missingConnections` 非空 | `follow_cause` | 连接 +1，趋向 UNDERSTANDING | 位移至因果对端 |
| `exploration-reflect` | `understandingStage == UNDERSTANDING` | `reflect` | 收束至 SYNTHESIS | 不位移 |
| `exploration-deep-continue` | `coverageRatio < 1.0` | `deep_continue` | 当前阶段加深 | 不位移 |
| `exploration-default` | 兜底 | `deep_continue` | 当前阶段加深 | 不位移 |

**规则优先级即认知优先级**：先补维度（广度缺口）、再补因果（深度缺口）、再收束、最后加深。这个顺序本身就是一句产品主张——**缺口优先于偏好**。

### 4.3 用户可读的推进理由（A2 字段 → 用户感受）

| A2 字段 | 用户读到 | 为什么必须有 |
|---------|---------|------------|
| `actionType` | 这是哪一类推进 | 让用户知道自己处在什么阶段 |
| `targetEntity` | 去哪 | 有具体去处才叫方向 |
| `rationale.text` | 为什么是它 | 理由必须可复述，否则等于「相关」二字 |
| `rationale.ruleId` + `triggeredDimension` | （审计态可查） | 满足 M88.0 §8.3(b) 可追溯，也是产品敢说「不是推荐」的凭据 |
| `coverageBeforeAfter.delta` | 走完能补多少 | 让用户看见自己在补什么，而不是被牵着走 |

### 4.4 C18 认知记忆在工作流中的确切职责

| 项 | 内容 |
|----|------|
| 职责 | 让**同一会话内**的后一段接得住前一段留下的缺口 |
| 不是 | 不是跨会话人格记忆（Phase 2 不持久化，ADR-0015 D6） |
| 生命周期 | 会话内第一次形成理解时开始，会话结束即销毁 |
| 与 C20 的分工 | C20 记「我走过哪些锚点」（探索路径的事实），C18 记「哪些缺口还没补」（理解路径的欠账） |
| 体验层诚实要求 | 不得暗示系统长期记得用户（B4 EC-18 违约表现） |

### 4.5 拒绝也是有效结束

用户拒绝某个下一步方向，是一个**有效的工作流终止**（C16 定义），不是失败：

- 系统不得换个说法再推一次同一方向——反复推送就是转化优化，即 X01。
- 拒绝后的正确接续：回到 TP-15 更新状态，由下一条规则产出不同类型的动作；若规则耗尽，交棒 TP-27 给确定性动作提示。
- 用户直接离场也是合法结束路径，此时 TP-19 + TP-22 仍应完成一次成长快照与反射。

## 5. 成长度量（C19）：会话态口径

> 依据 ADR-0015 D6（Phase 2 不持久化）+ P1-01 C19（`continuityScore` 依赖跨会话数据，真实运行中恒为退化值）。

### 5.1 北极星公式与本期可得性

`understandingGrowthScore = depthDelta + dimensionDelta + connectionDelta + continuityScore`

| 分量 | 度量什么 | 由哪个工作流事件产生 | 本期是否可得 |
|------|---------|-------------------|------------|
| `depthDelta` | 理解路径的纵向推进 | `deep_continue` 与阶段迁移 | **可得** |
| `dimensionDelta` | 覆盖维度的增加 | `open_dimension` | **可得** |
| `connectionDelta` | 因果连接的增加 | `follow_cause` | **可得** |
| `continuityScore` | 跨会话的连续性 | 需跨会话数据 | **不可得**（C18 无持久化） |

### 5.2 会话态口径的三条硬性规定

| # | 规定 | 违反的后果 |
|---|------|-----------|
| 1 | 只呈现本次会话内可信的三项增量 | —— |
| 2 | `continuityScore` **明示为「跨会话能力尚未开启」**，不伪造数值 | 用户被一个假分数误导，产品在最高判据上撒谎 |
| 3 | 不把 `continuityScore` 静默按 0 计入总分 | 总分被系统性低估，且用户不知道为什么低 |

### 5.3 度量对象是认知结构，不是用户行为

三项增量全部读自认知状态（C15）与理解投影（C17），**没有一项读自点击、时长或页面数**。这是 C19 与「参与度指标」的根本区别：

| 度量的是 | 本产品 | 参与度体系 |
|---------|-------|-----------|
| 主语 | 用户脑中的结构变化 | 用户在产品里的行为量 |
| 增长意味着 | 他更懂了 | 他待得更久 |
| 优化它会导致 | 产品去补用户的缺口 | 产品去延长用户的停留 |

### 5.4 与最高判据的连接

ADR-0013 D1 的最高判据是「用户离场时能否回答『你觉得自己变聪明了吗』」。C19 提供的是这个主观问题的**客观佐证**：用户在 TP-22 看到的不只是一句自我感觉，还有本次会话确实新增了多少维度、多少连接、深了几层。

**但 C19 不替用户回答这个问题。** 分数是刻度，判断权在用户——这一点与 §6 的镜像原则一致。

## 6. 认知镜像（C22）：L4.5 只读投影，终点不是中间层

> 依据 ADR-0015 D2 + ADR-0013 D3。**C4 落点在工作流层的完整表述。**

### 6.1 在工作流中的确切位置

```
   [ 工作流闭环 ]  TP-15 → TP-16 → 推进 → TP-20 / TP-18 → TP-15 → …
                         │
                         │  （闭环之外、之后；仅离场时）
                         ▼
   TP-19 成长刻度（C19）─────┐
   TP-20 轨迹链（C20）───────┼──→  TP-22 镜像出口（C22, L4.5）
   TP-15 认知状态（C15）─────┘            │
                                         ▼
                                    （无出边）
```

**三点必须同时成立**：

1. **TP-22 在闭环之外**：它不是循环的一个节点，它是循环停下之后才出现的一次回望。
2. **TP-22 只有入边**：入边来自 C20 / C15 / C19，全部是用户自己的东西。
3. **TP-22 没有出边**：它不指向 TP-16，不指向任何阶段，不指向任何主干。

### 6.2 「终点不是中间层」在工作流层的四条判据

| 判据 | 成立的样子 | 违反的样子 |
|------|-----------|-----------|
| 数据流向单向 | 轨迹 → 结构化 → 呈现给用户 | 轨迹 → 模型 → 内容投喂 |
| 不参与决策 | A1 §2 的输入契约中没有任何镜像字段 | ExplorationPolicy 读取镜像结果调权重 |
| 不牵引位移 | 镜像里不出现任何「所以你应该去看 X」 | 镜像成为一个变相的推荐位 |
| 解读权归用户 | 给结构不给结论，不贴学习者类型标签 | 系统替用户定义他是谁 |

任一条违反，Mirror 就从终点变成中间层，产品即滑向 ADR-0013 D3 与 M88 战略第九节共同列为最大风险的推荐系统。

### 6.3 镜像反射什么（工作流视角）

镜像把两条路径分别反射回去，且只陈述、不评判：

| 反射项 | 原料 | 用户可能自己读出什么 |
|--------|------|-------------------|
| 你这一次走过的锚点链 | C20 探索路径 | 「原来我一直在绕这一块」 |
| 你反复回到的维度 | C15 + C20 | 「我对制度演化比对战争更感兴趣」——**兴趣的自我发现** |
| 你惯用的推进方式 | C16 动作类型的分布 | 「我总是先追因果，很少横向比较」——**方法的自我发现** |
| 你这一次的结构增量 | C19 三项 Delta | 「我确实新建了几条连接」 |

中间两项正是 Article 0 第二句的两个词：**兴趣**与**学习方法**。ADR-0013 D5.3 把兴趣发现从「产品目标」上升为「待解决的大问题」——人很难靠自己发现兴趣所在，而镜像是产品在这件事上唯一的出手方式，且它出手的方式是**把镜子举起来，不是替他做决定**。

### 6.4 会话态诚实

Phase 2 不持久化，镜像反射的是「**这一次探索**里，你……」。不得暗示长期记忆、不得给出跨会话人格判断。跨会话镜像列 v2（ADR-0015 D6）。

## 7. 工作流不变量（Invariants）

以下八条在任何路径、任何变体下都必须成立。它们是本工作流的可验证内核。

| # | 不变量 | 违反即 |
|---|-------|-------|
| I-1 | 任一时刻，用户能回答「我在哪、从哪来、为何在此」（TP-23 恒在） | 认知结构无法沉淀（M81a 四场共踩） |
| I-2 | 推进的输入只有认知状态，绝不含行为指标 | 滑向 X01 |
| I-3 | 每一次位移都在轨迹上留痕并携带 From/Why | 镜像失去原料，第二句塌掉 |
| I-4 | 每一条结论旁都可得真相刻度三件套 | 第三句退回后台质量属性 |
| I-5 | 用户拒绝方向是有效结束，系统不重推 | 转化优化，即 X01 |
| I-6 | Mirror 只有入边，没有出边 | Mirror 成为中间层（ADR-0013 D3） |
| I-7 | 四阶段与探索语法在任何主题下相同 | 产生多产品感 |
| I-8 | 停滞总有接住：动作停滞→TP-27，方向停滞→TP-16 | 探索链断裂即离场（S004 十二分钟） |
