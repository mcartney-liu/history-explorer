# M86.1.0 — Explorer Runtime Context Design
### Strict Read-Only / Context Definition（非实现）

> 模式声明：严格只读。定义 Explorer Runtime Context 的语义边界、生命周期、与现有层的关系、不应包含的内容。不写代码、不定义数据结构实现、不设计 API。基于 M85.11.1 ~ M86.0 全链路输入。这是 M86 所有 Experience Layer 的共同语义基础——Context 定义错误，后续全部建在沙上。

---

## 第一部分：Context 定义（冻结）

> **Explorer Runtime Context = 当前用户为了理解某个问题，正在经历的一段认知过程状态。**

它不是：用户行为日志、页面状态、路由状态、浏览历史。

它是：**用户理解状态的运行时表示。** 系统通过它知道——用户正在理解什么、已经理解了哪些、当前处于哪个认知阶段、还有哪些缺口未闭合。

---

## 第二部分：Context 最小模型（8 字段）

```
ExplorerRuntimeContext {

  exploration_id        // 一次理解旅程的标识
  user_question         // 用户真正想理解的问题
  understanding_goal    // 这条线最终要帮用户理解什么
  current_focus         // 用户当前正在理解什么
  previous_focus        // 用户刚才理解了什么
  relation_reason       // 为什么从 previous 到 current
  cognitive_stage       // 当前认知阶段
  unresolved_gap        // 当前理解结构中尚未闭合的缺口

}
```

### 字段详解

**exploration_id**：一次理解旅程的标识。不是页面 session，不是用户登录态。例如：`为什么罗马能成为帝国？` 是一条 Exploration。可关联 `ExplorationPackage.slug`，但不依赖 Package 存在。

**user_question**：用户真正想理解的问题，用人的语言。例如：`为什么一些文明能够扩张并长期维持？`。不是 `package_id=m77-package-03`。来源：Curator 预写的 `seed_topic` 或用户自主输入。不由 AI 生成。

**understanding_goal**：这条线最终要帮用户理解什么——产品对用户的承诺。例如：`理解军事、经济、治理如何共同形成帝国扩张能力。`。来源：Curator 预写的 `exploration_goals`（Package 数据中已有）。不由 AI 生成。是 Orientation Layer 的核心文案来源 + Understanding Layer 的判断基准。

**current_focus**：用户当前正在理解的对象。例如：`罗马道路系统`。映射到 Entity 但不存系统标识——存"用户理解概念"。

**previous_focus**：用户刚才理解的对象。例如：`罗马军团组织`。与 current_focus + relation_reason 构成 Navigation Contract 的 From 部分。

**relation_reason**：为什么从 previous 到 current——认知推进的理由。例如：`军团扩张需要后勤支持，道路系统解释了这种支持如何实现。`。来源：Entity 间的关系数据（`RelatedEntity.relation_type` + 语义描述）。不由 AI 临时生成——应来自 Causal Layer 已有数据。

**cognitive_stage**：当前认知阶段。可选值：`FACT` / `EXPLANATION` / `CONNECTION` / `UNDERSTANDING` / `NEW_QUESTION`。决定系统当前应提供什么。

**unresolved_gap**：理解结构中尚未闭合的缺口。例如：用户理解了罗马为什么崛起，自然浮现——`罗马为什么最终无法维持这种扩张模式？`。不是算法推荐。是 Question Transition Layer 的核心输入。

## 第三部分：Context 生命周期

### 创建
- 用户选定探索方向时创建（Curiosity → Orientation 阶段）
- `exploration_id` 生成，`user_question` 和 `understanding_goal` 从 Curator 预写数据填充

### 更新
- 每次跳转到新对象时更新（previous_focus ← current_focus，current_focus ← 新对象，relation_reason 从关系数据填充，cognitive_stage 按认知推进更新）
- 理解闭环时更新（cognitive_stage → UNDERSTANDING，unresolved_gap 从理解结构推导）

### 完成
- 用户主动结束探索或产生 New Question 并选择不继续时，Context 进入完成态
- 数据保留（作为 Workspace Understanding Memory 来源），但不活跃

### 销毁
- 不在 M86 范围内讨论。当前 Context 为内存态，持久化留给 M87+

## 第四部分：Context 与 8 个 Experience Layer 的关系

### Context → Curiosity Entry Layer
- Context 创建时 user_question 从用户选择填充。Curiosity Entry 不读 Context（它在 Context 创建之前）

### Context → Orientation Layer
- 读取 user_question + understanding_goal，展示定位承诺。不写入 Context

### Context → Navigation Context Layer
- **Context 的核心消费者**。每次跳转读取 previous_focus + current_focus + relation_reason，展示 Navigation Contract
- 每次跳转同时更新 Context

### Context → Understanding Layer
- 读取 cognitive_stage + understanding_goal，判断是否达到 UNDERSTANDING
- 到达 UNDERSTANDING 时触发理解闭环展示，更新 unresolved_gap

### Context → Companion Visibility Layer
- AI Companion 读取 Context（user_question + current_focus + cognitive_stage），知道"用户在理解什么"
- AI 对话不再是通用问答，而是服务于当前理解推进的上下文对话

### Context → Seeds Visibility Layer
- 理解种子与 current_focus + cognitive_stage 关联
- FACT 阶段展示"这个对象为什么重要"的种子；CONNECTION 阶段展示"它和什么相关"的种子

### Context → Workspace Context Layer
- Workspace 读取 Context 完整历史（previous_focus 链 + relation_reason 链），展示为"我理解过什么"
- 不是全局堆积，是当前 Exploration 的理解轨迹

### Context → Question Transition Layer
- 读取 unresolved_gap，显形为 New Question
- 用户选择继续 → 创建新 Exploration，旧 Context 进入完成态

## 第五部分：Context 不应包含什么（防污染边界）

- ❌ **系统标识**：entity_id、package_id、route_path。Context 只存用户理解概念
- ❌ **行为指标**：点击次数、停留时长、浏览页面数。Context 只存认知状态
- ❌ **AI 生成内容**：AI 临时生成的解释、推荐、总结。relation_reason 来自 Causal Layer 已有数据
- ❌ **用户个人信息**：用户 ID、偏好、历史所有探索。跨 Exploration 记忆由 Workspace 管理
- ❌ **UI 状态**：哪个 tab 打开、哪个面板展开、滚动位置。Context 是语义层

---

## 第六部分：EP-006（冻结）

> **Explorer Runtime Context 是所有 Experience Layer 的唯一语义来源。**

任何 Experience Layer 不能自己推断用户状态——必须读取同一个 Context。否则未来必然出现 AI 认为用户在理解 A，Workspace 展示 B，Understanding 判断 C——产品再次碎裂。

---

## 第七部分：Context 与 Engine Layer 隔离

```
Engine Layer（不感知 Context）
  ├── Entity / CausalObject / Relationship 数据
  ├── AI Gateway
  └── 现有路由
        ↑ 读取数据，不写入 Context

Experience Layer（读写 Context）
  ├── Curiosity Entry / Orientation
  ├── Navigation Context / Understanding
  ├── Companion / Seeds / Workspace Visibility
  └── Question Transition
```

- Engine Layer 不感知 Context 的存在——继续提供能力，不受影响
- Experience Layer 只通过 Context 理解用户状态——不从 Engine 推断，不从 UI 推断
- Context 的更新由 Experience Layer 在用户认知推进时写入——不由 Engine 层写入
