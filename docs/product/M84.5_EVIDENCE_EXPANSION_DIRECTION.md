| -------- | -------- | -------- | -------- | ---------- | ---- |
| co-001 科举→文官 | co-004 秦制→郡县制 | 制度演进 | Semantic | medium | 中央集权制度的连续演化 |

| co-009 罗马法→法律 | co-004 秦制→郡县制 | 文明对比 | Semantic | low | 罗马法系 vs 中华法系 |

关系性质：
- KG：两个 CausalObject 的 cause/effect Entity 在 KG 中存在直接 Relationship → 这是 KG 层关系，不需要 Semantic Layer 重复

**关键约束**：

- 这不是 `related_causal_objects` 字段的实现
- 不写入代码
- 不进入 runtime
- 仅用于 M85 Entry Evidence（E4：Curator 确认 ≥3 个稳定关系模式）

## 4. Explorer Observation — 三级信号模型

### 4.1 观察什么

重点不是 "用户点击了什么"，而是用户有没有产生跨对象探索的认知需求。

### 4.2 Strong Signal

用户主动表达：

> "这个和刚才那个有什么关系？"

> "有没有类似的制度？"

> "为什么这里没有刚才那种解释？"

**含义**：Explorer 已经将 CausalObject 视为可关联的理解单元。不仅需要单对象解释，还需要跨对象理解。

**对应路线**：

```
Strong Signal
    ↓
M85 Semantic Relationship（related_causal_objects）
```

### 4.3 Weak Signal

用户连续打开多个 CausalObject，但没有表达关系需求。

**含义**：Explorer 对 CausalObject 有兴趣，但当前不需要系统帮助建立跨对象理解。

**对应路线**：

```
Weak Signal
    ↓
优化 Navigation（CausalObject 之间的发现性）
非 Semantic Layer 的关系模型
```

### 4.4 No Signal

用户看完一个 CausalObject 后继续实体探索即可，不主动寻找其他 CausalObject。

**含义**：单 CausalObject 已满足 Explorer 的探索需求。跨对象探索不是当前 Explorer 的认知模式。

**对应路线**：

```
No Signal
    ↓
保持单对象模型（CausalObject 是独立 Exploration Object）
不引入跨对象关系
```

### 4.5 信号采集规则

| 规则 | 说明 |
| --- | --- |
| 不引导 | 不提示 "还有其他相关解释"，不暗示跨对象关系 |
| 不设计实验 | 不设对照组，不设 H0/H1，不运行 Validation Protocol |
| 只记录自然行为 | 用户在没有系统引导下的自发行为 |
| 定性优先 | 用户的口头表达（"这个和刚才那个…"）比点击数据更有价值 |

## 6. M85 Entry Criteria 为什么需要 E5？

这是 M85.0 Gate 后 PO 补充的最关键约束。

### 6.1 三种可能的关系

CausalObject A 和 CausalObject B 之间的关系，有三种完全不同的架构归属：

**可能性 A：知识关系（KG Layer）**

```
印刷术 → 知识传播 → 教育普及
```

两个 CausalObject 的 cause/effect Entity 在 KG 中已存在直接 Relationship。这不是 Semantic Layer 需要额外建立的——KG 已经回答了。如果 M85 基于这种关系做 Multi-hop，等于在 Semantic Layer 重建 KG。

**可能性 B：解释关系（Semantic Layer）**

```
科举制度解释中国官僚体系形成
        ↕
中央集权解释帝国治理模式
```

两个 CausalObject 的解释逻辑相关，但 KG 层不存在直接连接。这是 Semantic Layer 的真正价值：curator 的策展判断建立了 KG 不包含的理解关联。

**可能性 C：探索路径（Explorer Interaction Layer）**

```
秦制 → 郡县制
        ↓
系统提示："你可能还想了解：为什么罗马没有形成类似制度？"
```

这是 Explorer 层的导航判断，不是架构层的关系。curator 认为 Explorer 可能对对比感兴趣。

### 6.2 E5 的判定逻辑

```
E5 合格 = 在 Curator Relationship Candidates 中，
          至少 3 个关系对的性质为 Semantic（非 KG、非 Explorer Navigation）

这确保了 M85 的 related_causal_objects 不会成为：
- KG 的重复（可能性 A）
- 推荐引擎的伪装（可能性 C）
```

## 7. M84.5 的深层价值

### 7.1 回答一个核心问题

> Explorer 的最小探索单位是什么？

```
现在：
  Entity → CausalObject

未来可能（但不能提前假设）：
  Entity → CausalObject → CausalObject Cluster
```

M84.5 的价值不只是增加 10 个 CausalObject。而是通过数据扩展和自然观察，判断 Explorer 是否将 CausalObject 视为独立探索单位，还是已经开始将它们关联为理解集群。

### 7.2 治理能力的演进

```
M83 建立的是：
  实验治理能力（如何验证假设）

M84 验证的是：
  架构治理能力（如何保护边界）

M84.5 实际验证的是：
  边界等待能力（如何让证据先成熟，而非技术先行动）
```

**边界等待能力**是平台长期演进非常重要的一种能力：不是所有合理方向都立即实现。有些方向需要让证据先成熟。

M84.5 的整个阶段就是这种能力的实践——HOLD 不是不做，是有条件地做。条件是证据，不是技术可行性。
