## A. API Contract

### `PathCandidate.to_dict()` — 新增 `causal_statements` 字段

```json
{
  "nodes": ["china_v1:idea-keju", "china_v1:idea-wenguan"],
  "steps": [...],
  "score": 0.85,
  "score_breakdown": {...},
  "explanation": "Concept '科举制度' —[led_to →]→ Concept '文官体系' | [high] 科举制度通过...",
  "causal_statements": [
    {
      "cause_id": "china_v1:idea-keju",
      "effect_id": "china_v1:idea-wenguan",
      "mechanism": "科举制度通过标准化考试选拔文官...",
      "consequence": "文官体系的确立使中国形成了世界上最早的职业官僚制度...",
      "confidence": "high",
      "evidence_refs": ["ec-cn-001", "ec-cn-002"]
    }
  ]
}
```

### Backward Compatibility

| 场景 | 行为 |
| --- | --- |
| 无 `causal_adapter` | `causal_statements` 字段**不存在**于输出中（旧客户端不受影响） |
| 有 `causal_adapter` + 匹配 CS | `causal_statements` 存在，包含结构化 CS dicts |
| 有 `causal_adapter` + 无匹配 CS | `causal_statements` 为 `[]`（空数组） |

### 字段规范

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cause_id` | `str` | KG Entity GID |
| `effect_id` | `str` | KG Entity GID |
| `mechanism` | `str \| null` | 因果机制文本 |
| `consequence` | `str \| null` | 因果后果文本 |
| `confidence` | `"high"` \| `"medium"` \| `"low"` \| `null` | 策展者置信度 |
| `evidence_refs` | `str[]` | Evidence Claim ID 列表 |

## C. Integration Design

```
ExplorationEngine.find_connections(src, tgt)
  └── _explain_path(steps)
        ├── 1. 构建 structural path text
        ├── 2. 查询 Adapter → 收集 CausalStatement
        ├── 3. 序列化为 list[dict]（P1.5 结构化输出）
        └── 4. 返回 (text, list[dict])
            ↓
PathCandidate(..., explanation=text, causal_statements=list[dict])
            ↓
to_dict() → {"explanation": "...", "causal_statements": [...]}
```

**Frontend 不需要解析 `explanation` 字符串**——直接消费 `causal_statements` 数组进行结构化渲染。
