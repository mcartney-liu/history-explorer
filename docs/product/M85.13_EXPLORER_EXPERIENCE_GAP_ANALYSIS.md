## Part 1 — Experience Journey Gap Mapping

以 M85.12 的 First Explorer Journey 六阶段为基准，逐阶段对照当前产品现实。

| Stage | Current Reality | Missing Experience | Violated Principle | Severity |
|---|---|---|---|---|
| **Curiosity** | 用户打开产品后看到"开始探索"按钮，点击后进入由 `m77-package-01` 等技术代号 + "深度/覆盖"等内部指标组成的卡片列表。用户不知道自己在选什么，也不知道选了之后会发生什么。 | 缺少一个能把"我随便有个好奇"接住的入口。当前入口把认知负担完全甩给用户，且用内部语言让用户在第一秒就产生"这是给开发者用的"错觉。 | P01（不知为何在此）、P03（未翻译为人话） | **Critical** |
| **Orientation** | 不存在这个阶段。用户选 Package 后直接进入实体列表，没有任何"你即将经历什么"的定位。 | 缺失整个 Orientation 层——选定方向后第一句应该是"你要理解的是 X，接下来会一步步看到 Y"。 | P01（不知为何在此）、P12（像翻库而非对话） | **Critical** |
| **Discovery** | 用户能看到实体列表（人名/事件名/文明名），但实体卡片仅展示名称和类型标签，没有"为什么它在这条线上"。点击进入后得到 EntityPage，信息量大但无上下文锚定。 | 具体对象存在但缺少"为什么选它""它在这条线上扮演什么角色"的解释。用户撞见了东西，但不知道撞见的是关键环还是边缘信息。 | P08（关系无语义）、P02（信息增量无认知推进） | **High** |
| **Connection** | 实体间有链接（Related Entities / Relationship View），但仅呈现名字或关系类型标签（如 `causes`），不解释"为什么 A 和 B 相关对理解这条线意味着什么"。CausalObject 之间也有横向跳转，同样无语义导航。 | 连接机制存在但语义层空白。用户能跳转但不知道为什么跳、跳了之后更懂了什么。两个无终止横向循环（实体↔实体、CausalObject↔CausalObject）属于典型的"信息增量无认知推进"。 | P08（关系无语义）、P05（无认知目的地） | **Critical** |
| **Understanding** | 不存在这个阶段。用户看了实体、跳了关系、可能问了 AI，但产品从未给出"你现在看懂了 X"的闭合信号。理解种子藏在 AI 面板脚注，不主动展示。M85 的 Semantic Relationship 能力在前端几乎不可见。 | 核心缺失：无"原来如此"的闭环。用户积累了大量信息但没有结构化的理解确认。理解种子（M85 的核心交付）在体验中近乎隐形。 | P06（无闭环信号）、P04（核心价值隐性化） | **Critical** |
| **New Question** | 不存在这个阶段。产品无"你刚看懂了 X，这自然引出一个新问题 Y"的机制。探索终点要么是转圈停不下来，要么是空 tab（Extensions "即将推出"）的伪终点。 | 缺失整个"理解孵化新疑问"的螺旋。用户要么迷失在无限跳转中，要么被迫在挫败感中离开。 | P07（疑问驱动缺失）、P06（无完成信号） | **Critical** |

**结论**：六个阶段中，**四个是 Critical 缺失**（Curiosity 入口死胡同、Orientation 不存在、Connection 无语义、Understanding/New Question 不存在），两个是 High（Discovery 缺锚点、Connection 缺方向）。当前产品体验本质上是"翻数据库"，不是"探索文明"。

## Part 2 — Navigation Contract Gap

以 M85.12 的 Navigation Contract（每次跳转必须携带：From 来源 / Why 原因 / Value 价值）为基准，逐节点检查当前导航链。

| 导航节点 | From（来源） | Why（原因） | Value（价值） | 状态 |
|---|---|---|---|---|
| Landing → Explore | ✅ 有（点击"开始探索"） | ❌ 无（不知道为何是"选 Package"而非直接探索） | ❌ 无（不知道"探索"意味着什么） | **来源弱，原因/价值缺失** |
| Explore → Package | ❌ 无上下文传递 | ❌ 无（系统返回所有 Package，无"哪个适合你"） | ❌ 无（不知道选完会看到什么） | **三元全缺** |
| Package → Entity List | ❌ 无（进入后忘了是哪个 Package） | ❌ 无（为什么这些实体在一起？） | ❌ 无（看这些实体能理解什么？） | **三元全缺** |
| Entity → Entity（横向跳转） | ❌ 无（不知从哪个实体跳来） | ❌ 无（仅显示名字，不说明为何相关） | ❌ 无 | **三元全缺** |
| Entity → CausalObject | ❌ 无 | ❌ 无（为什么这个原因和这个实体有关？） | ❌ 无 | **三元全缺** |
| CausalObject → CausalObject | ❌ 无 | ❌ 无 | ❌ 无 | **三元全缺** |
| Any → Companion | ❌ 无（AI 不知道自己被在什么上下文中调用） | ❌ 无 | ❌ 无 | **三元全缺** |
| Any → Workspace | ❌ 无（工作台不知道自己属于哪条探索线） | ❌ 无 | ❌ 无 | **三元全缺** |

**Navigation Contract Score：1 / 10**

唯一得分的"1"来自 Landing → Explore 的"开始探索"按钮提供了最弱级别的来源感（用户知道自己主动点击了），其余所有节点三元全缺。

**Top 10 Context Loss Points（按认知断裂严重度排序）：**

1. **Landing → Package 选择页**：从"我想探索历史"突然跳进技术代号卡片矩阵。认知断崖。
2. **Package → Entity List**：失去"我选了什么、要理解什么"的所有上下文。
3. **Entity → Entity 横向跳转**：不知道从哪来、为什么跳、跳完更懂什么。无终止循环起点。
4. **Entity → CausalObject**：解释层与事实层的连接无语义说明。
5. **CausalObject → CausalObject**：同密度循环，无认知推进。
6. **Any → Companion**：AI 不知道用户在探索什么，对话从零开始。
7. **Any → Workspace**：工作台不知道用户在哪条线上，展示的是全局堆积而非上下文轨迹。
8. **Entity Page 内 tab 切换**：tab 命名混杂架构词与用户词，切换后无"这一步帮你理解什么"。
9. **Companion 回答 → 用户下一步**：AI 回答后无"基于这个回答，你可以接着看什么"的桥梁。
10. **探索结束 → 无出口**：用户累了但不知道"我完成了什么"，被迫在伪终点或循环中放弃。

## Part 3 — Cognitive Progress Audit

分析用户每一次行动后，认知是否推进。

| 用户行动 | 当前认知收益 | 认知分类 | 理想认知收益 |
|---|---|---|---|
| 点击"开始探索" | 知道"我要选一个 Package" | C — 消耗注意力但无认知收益 | 知道"我要理解一个我好奇的文明问题" |
| 浏览 Package 卡片 | 看到技术代号和内部指标 | C — 无认知收益（甚至增加困惑） | 看到"这些是你可以走的路，每条会帮你理解什么" |
| 选择一个 Package | 无认知变化 | C | 选定方向，确认"我要理解 X" |
| 看实体列表 | 看到一些名字 | B — 增加信息 | 看到关键对象，并知道"为什么这些是理解 X 的关键" |
| 点击一个实体 | 看到更多信息（描述/属性） | B — 增加信息 | 理解这个对象在文明链条中的位置与角色 |
| 点击 Related Entity | 看到另一个名字 | C — 无认知收益（转圈） | 理解"为什么这两个对象相关，以及这说明了什么" |
| 点击 CausalObject | 看到解释详情 | B — 增加信息 | 理解"这个原因如何改变了历史走向" |
| 打开 AI Companion | 能提问 | B — 增加信息（取决于提问质量） | 在探索上下文中有针对性地获得解释 |
| 看 Understanding Seeds | 看到几个提问 | A — 增加理解（但藏得太深，几乎不被发现） | 主动获得"换个角度看历史"的认知支架 |
| 打开 Workspace | 看到历史记录 | B — 增加信息 | 看到"我走过了什么路、理解了什么" |
| 探索结束（放弃） | 无认知闭环 | C — 无认知收益 | 确认"我看懂了 X，并带着新问题 Y 离开" |

**统计**：
- **A 类（增加理解）**：1 项（Understanding Seeds，但 Hidden）
- **B 类（增加信息）**：5 项
- **C 类（消耗注意力但无认知收益）**：5 项

当前产品中，用户约 **45% 的行动属于 C 类**——消耗了注意力但没有产生认知推进。最致命的是：唯一的 A 类能力（理解种子）处于 Hidden 状态，对绝大多数用户不可达。

## Part 4 — Hidden Value Exposure Audit

| 核心能力 | 当前可见度 | 判断 |
|---|---|---|
| **AI Historian（Companion）** | **Hidden** | 默认收起为屏幕边缘小图标。如果用户不知道 AI 存在，等于核心对话能力不存在。 |
| **Understanding Seeds（理解种子）** | **Hidden** | 藏在 AI 面板底部脚注。M85 的核心交付对普通用户几乎为零。P04 严重违反。 |
| **Workspace（探索工作台）** | **Hidden** | 默认收起。回看/续探能力不可达，用户无法"暂停与回归"。 |
| **Journey（探索旅程）** | **Weakly Visible** | 存在但无"这是你走过的理解之路"的叙事包装。 |
| **Causal Explanation（因果解释）** | **Weakly Visible** | CausalObject 页面存在但进入路径依赖用户主动发现。 |

**回答**：如果用户不知道这些存在，是否等于产品核心能力不存在？**是的。** 五项核心能力中，三项 Hidden、两项 Weakly Visible。对首次使用的普通用户而言，History Explorer 的"三层能力"退化为"一层半"——用户只能看到 Fact Layer 的实体浏览和少量 Explanation Layer 的碎片，Understanding Layer 完全不可达。

## Part 5 — Architecture Language Leakage Audit

### 必须消失

| 内部词 | 当前出现位置 | 危害 |
|---|---|---|
| `Global ID` | Entity Page 元数据区 | 纯系统寻址标识，对用户毫无意义 |
| `Coverage`（覆盖） | Package 卡片指标 | 内部度量指标 |
| `Depth`（深度） | Package 卡片指标 | 同上，且暗示"深=好"的误导 |
| `m77-package-01` 等代号 | Package 卡片标题 | 里程碑代号 |

### 需要翻译

| 内部词 | 应翻译为 |
|---|---|
| `Entity` | 该对象的具体名称，类型标签改为"人物/事件/制度" |
| `CausalObject` | "关键原因"或直接以原因内容作标题 |
| `Package` | "探索路线"或"理解主题" |
| `Seed` / `Seed Topic` | "理解起点"或"一个能展开的问题" |
| `Knowledge Graph` | "文明中事物的相连网络" |
| `Semantic Relationship` | "为什么它们值得一起理解" |
| `Relation Type` | "因果/影响/同源"（保留但加解释） |
| `Exploration Goal` | "这条路想帮你理解什么" |
| `Extensions` | 删除或替换为"更多视角"（不能是空 tab） |
| `Explore` / `Understand` tab | 统一翻译为用户语言 |

### 可以保留

| 概念 | 理由 |
|---|---|
| `Timeline` | 用户自然理解 |
| `Relationship` | 翻译后（"为什么相关"）可接受 |
| `Causal Statement` | 翻译后（"可溯源的解释"）可接受 |
| `Workspace` | 翻译后（"探索工作台/你走过的路"）可接受 |
| `Historian` | 翻译后（"历史对话伙伴"）可接受 |

**结论**：当前用户可见概念中，4 个必须消失、10 个需要翻译、5 个可保留。超过 **70% 的用户界面语言需要迁移**。

## Part 6 — M86 Scope Prioritization

### A 类 — 必须进入 M86（不改则产品仍不是 Explorer Experience）

| # | Gap | 引用的 Principle | 为什么是 A |
|---|---|---|---|
| **A1** | 入口用技术代号 + 内部指标替代主题 | P01、P03 | 用户在第一秒就迷失。不改这一步，后续所有体验都是空中楼阁。 |
| **A2** | Orientation 层完全缺失 | P01、P12 | 用户选定方向后无任何定位，直接坠入数据。无此层，Discovery 就是噪音。 |
| **A3** | 所有跳转无 Navigation Contract | P01、P05、P08、P09 | 每一次跳转都是认知断裂。这是"翻数据库"与"探索文明"的本质分界线。 |
| **A4** | 理解闭环信号完全缺失 | P06 | 无"看懂了"的休止，探索就是无限游荡。用户无法形成成就感，必然放弃。 |

| **A6** | 关系无语义（仅名字/标签） | P08 | 连接是体验的核心，无语义的连接只是超链接。 |

### B 类 — 可以进入 M86，提高体验

| # | Gap | 引用的 Principle |
|---|---|---|
| **B1** | 内部概念全量翻译为用户语言 | P03 |
| **B2** | 面包屑 / 方向指示 / 可退回机制 | P09 |
| **B3** | 暂停与回归（退出到起点、回看轨迹） | P10 |
| **B4** | 理解种子从脚注提升为核心区块 | P04、P06 |
| **B5** | 伪终点（空 Extensions tab）移除或替换 | P06 |
| **B6** | AI Companion 获知用户探索上下文 | P04、P02 |
| **B7** | Workspace 从全局堆积转为上下文轨迹 | P10、P01 |

### C 类 — 继续观察

| # | Gap | 理由 |
|---|---|---|
| **C1** | Timeline/Map/Video 等载体如何守宪法 | 待 M86 核心体验就位后再评估载体适配 |

**A 类 7 项是 M86 的最低门槛**——不改这些，产品仍然不是 Explorer Experience。

## Part 7 — Final Decision

### Q1：如果今天开放给普通用户，最大的失败点是什么？

**用户会经历 15 分钟的信息堆积，然后带着"看了很多但什么都没懂"的困惑离开，并且不会再回来。**

具体失败链：打开产品 → 看到技术代号 → 硬选一个 → 看实体列表 → 点开实体 → 横向循环跳转 → 找不到出口 → 不知道 AI 在哪 → 关闭离开。这不是功能缺失问题，这是**体验不存在**的问题——能力在引擎里，但没被翻译成体验。

### Q2：如果只能改 5 件事，哪 5 件改变最大？

1. **入口翻译**：把 Package 选择页从技术代号矩阵变成"你想理解什么？"的主题引导。→ 修复 P01、P03。
2. **Orientation 层**：选定方向后，给一句定位。→ 修复 P01、P12。
3. **Navigation Contract**：每次跳转携带来源/原因/价值。→ 修复 P01、P05、P08、P09。
4. **理解闭环**：给出"你看懂了 X"的确认，并显形自然引出的新问题。→ 修复 P06、P07。
5. **核心价值主动可见**：AI 对话伙伴、理解种子、工作台不再隐藏。→ 修复 P04。

### Q3：M86 的核心目标一句话应该是什么？

**让一个普通用户第一次进入 History Explorer 时，能在 15 分钟内完成一轮完整的文明理解——从好奇到"原来如此"，并自然产生"我还想知道更多"。**

## 最终结论：我们距离真正的人类文明探索体验，还有多远？

**当前差距：约 85%。**

计算依据：
- 6 个体验阶段中，4 个 Critical 缺失、2 个 High 缺失。
- Navigation Contract 评分 1/10。
- 用户行动中 45% 消耗注意力但无认知推进。
- 5 项核心能力中 3 项 Hidden、2 项 Weakly Visible。
- 用户可见概念中 70% 需要迁移或消除。
- M86 A 类必须修复的 Gap 有 7 项。

这不是"产品不够好"的差距，这是**"体验存在"与"体验不存在"之间的差距**。M1-M85 建了一个强大的文明理解引擎，但用户打开车门后，发现方向盘是技术代号、仪表盘是内部指标、导航系统不存在、目的地从未被告知。

**M85.13 完成。M86 的方向已经明确：从"引擎存在"到"体验存在"。**
