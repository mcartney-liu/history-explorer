# M89.2.3 — Interaction Contract
### Strict Read-Only / Interaction Design Freeze

> 模式声明：严格只读。冻结 History Explorer 的交互契约——谁主动、谁解释、什么时候选择。不讨论 UI、页面、代码。

---

## 一、核心原则（冻结）

> **Every exploration step requires an intentional user choice.**
>
> **每一次探索，都必须由用户主动迈出下一步。**

Runtime 可以告诉：为什么建议、为什么相关、为什么值得。但**永远不要自动进入下一步。**

---

## 二、主动权的分配

| 角色 | 职责 | 禁止 |
|------|------|------|
| **系统** | 解释（为什么看这个）、引导（下一步看什么）、总结（你理解了什么） | 自动跳转、替用户选择、替用户决定"够了" |
| **用户** | 选择入口、决定采纳/拒绝建议、决定继续/暂停 | — |

---

## 三、六屏交互契约

### 屏 1 — Curiosity Entry

| 维度 | 内容 |
|------|------|
| 系统主动 | 给出一个问题（"法国大革命为什么发生？"） |
| 用户主动 | 选择这个问题 |
| 禁止 | 用户自己搜索；系统给出多个无解释的选项 |
| 对应 Moment | Moment 1："原来不是让我搜资料" |

### 屏 2 — Orientation

| 维度 | 内容 |
|------|------|
| 系统主动 | 展示理解框架（6 个维度 + 第一步预告） |
| 用户主动 | 点击"开始第一步" |
| 禁止 | 自动进入内容；用户自由乱点维度 |
| 对应 Moment | Moment 1 → Moment 2 过渡 |

### 屏 3 — Exploration（主循环）

| 维度 | 内容 |
|------|------|
| 系统主动 | 展示当前内容 + 下一步建议 + 为什么建议（reason） |
| 用户主动 | 点击"继续探索"采纳建议，或"换一个方向"拒绝 |
| 禁止 | 自动跳转到下一步；用户被迫接受建议 |
| 对应 Moment | Moment 2："原来我知道下一步为什么" |

### 屏 4 — Navigation Card（每次跳转前）

| 维度 | 内容 |
|------|------|
| 系统主动 | 展示 From（你刚看了 X）→ Why（因为 Y 关系）→ Value（帮你理解 Z） |
| 用户主动 | 确认跳转 |
| 禁止 | 跳过这个步骤直接加载下一页 |
| 对应 Moment | Moment 2 + Moment 3 |

### 屏 5 — Understanding Closure

| 维度 | 内容 |
|------|------|
| 系统主动 | 展示总结（"你理解了 X"）+ 新问题入口 |
| 用户主动 | 选择是否继续探索新问题 |
| 禁止 | 自动开始下一轮探索；总结由 AI 自由生成 |
| 对应 Moment | Moment 4："原来我还想继续" |

### 屏 6 — Continue

| 维度 | 内容 |
|------|------|
| 系统主动 | 展示可继续的方向 |
| 用户主动 | 选择方向或离开 |
| 禁止 | 自动推荐"最热门"；展示无解释的列表 |
| 对应 Moment | Moment 4 延伸 |

---

## 四、交互反模式（禁止）

| 反模式 | 为什么禁止 |
|--------|-----------|
| 自动播放下一个内容 | 用户失去选择权 → 变成短视频 |
| 无解释的"猜你喜欢"列表 | 退化为推荐系统 |
| 跳过 Navigation Card | 用户不知道"为什么看这个" |
| 用户被迫接受唯一路径 | 探索 = 自由，非强制 |
| 搜索框作为主入口 | 退化为搜索引擎 |

---

## 五、与现有产品的交互差异

| 产品 | 系统角色 | 用户角色 |
|------|---------|---------|
| 搜索引擎 | 返回结果 | 自己判断 |
| Wikipedia | 提供静态内容 | 自己点击链接 |
| ChatGPT | 回答所有问题 | 被动接收 |
| 短视频 | 自动推送 | 被动消费 |
| **History Explorer** | **解释 + 引导** | **主动选择每一步** |
