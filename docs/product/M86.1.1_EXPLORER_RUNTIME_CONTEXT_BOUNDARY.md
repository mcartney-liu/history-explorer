# M86.1.1 — Explorer Runtime Context Implementation Boundary
### Strict Read-Only / Architecture Boundary（非实现）

> 模式声明：严格只读。定义 Explorer Runtime Context 在现有前端架构中的宿主、生命周期托管、单一数据源保证机制。不写代码、不设计组件、不决定技术实现。这是 M86 真正第一行代码之前最后一道架构护栏。

---

## 第一部分：EP-007（冻结）

> **Explorer Runtime Context is relational, not factual.**
>
> **Explorer Runtime Context 描述用户与知识之间的理解关系，而不是知识本身。**

Context 存的是 `User ↔ Knowledge` 的关系，不是 Knowledge 的副本。

**错误示例**：`current_focus: { entity: "Roman Empire", population: 50000000, period: "27BC" }`（这是 Knowledge Layer 的数据）

**正确示例**：`current_focus: "用户正在理解罗马为什么能够维持长期扩张"`

所有 8 个字段均为理解关系，非知识副本。

---

## 第二部分：cognitive_stage 定义修正（冻结）

> **Cognitive Stage represents current cognitive need, not exploration progress.**
>
> **cognitive_stage 表示用户当前的认知需求类型，而不是探索进度。**

用户不是按线性关卡推进——探索不是课程。stage 的上移和下移都是合法行为。

五阶段值（不变）：`FACT` / `EXPLANATION` / `CONNECTION` / `UNDERSTANDING` / `NEW_QUESTION`。

**关键约束**：cognitive_stage 的变化不由系统自动推进——由用户在探索过程中的自然行为驱动。

---

## 第三部分：Context 宿主与单一数据源

> **Explorer Runtime Context 由 ExplorePage 层作为单一宿主持有。所有 Experience Layer 通过同一个 Context 实例读写——不创建副本，不独立推断，不各自维护。**

```
ExplorePage（Context 宿主）
  ├── Curiosity Entry Layer（不读 Context，触发 Context 创建）
  ├── Orientation Layer（只读 user_question + understanding_goal）
  ├── Entity Page（读写 current_focus / previous_focus / relation_reason / cognitive_stage）
  ├── AI Companion（只读全 Context）
  ├── Understanding Seeds（只读 current_focus + cognitive_stage）
  ├── Workspace（只读 Context 历史链）
  └── Question Transition（只读 unresolved_gap）
```

宿主选择理由：ExplorePage 是所有 Experience Layer 的共同祖先、生命周期覆盖整条 Exploration、已持有类似全局状态。

---

## 第四部分：Context 生命周期托管

### 创建
- 触发者：Curiosity Entry Layer（用户选定方向）
- 创建者：ExplorePage（宿主）
- 初始值来源：`ExplorationPackage.seed_topic` → user_question；`ExplorationPackage.exploration_goals` → understanding_goal

### 更新
| 更新事件 | 触发者 | 更新的字段 |
|---|---|---|
| 用户跳转到新对象 | Navigation Context Layer | current_focus, previous_focus, relation_reason, cognitive_stage |
| 用户回到事实确认 | Navigation Context Layer | cognitive_stage → FACT |
| 用户完成理解闭环 | Understanding Layer | cognitive_stage → UNDERSTANDING, unresolved_gap |
| 用户选择继续新问题 | Question Transition Layer | 新 Context 创建，旧 Context 完成 |

### 完成
用户主动退出或 NEW_QUESTION 后不继续。Context 保留供 Workspace 读取，但不活跃。

### 销毁
不在 M86 范围。当前为内存态，页面关闭即释放。持久化留给 M87+。

> **Context 的创建和更新全部通过 ExplorePage 宿主暴露的方法进行——Experience Layer 不直接修改 Context，而是通过宿主提交变更。**

---

## 第五部分：Context 传递机制

- 不引入新的全局状态管理库
- 不通过 URL 传递 Context
- 不通过 localStorage 持久化
- 利用 React Context API 或 Props drilling（取决于现有架构已有模式）
- 子组件通过 useContext 读取，通过宿主回调提交写入

> **任何 Experience Layer 不持有 Context 的本地副本——每次读取都是当前 Context 的最新快照。**

---

## 第六部分：与现有状态的关系

现有 ExplorePage state（topic / result / loading / selectedEntity / packageId 等）继续管理数据和 UI。Context 是语义升级层——不替换现有 state，而是新增的理解过程追踪层。

与 ExplorerPath 的关系：ExplorerPath 记录"用户去了哪些节点"（行为记录），Context 记录"用户为什么去、理解了没有"（语义）。

---

## 第七部分：防止碎片化护栏

1. **单一宿主**：Context 只存在于 ExplorePage 层
2. **只读消费**：除 Navigation Context Layer 和 Understanding Layer 外，其余只读不写
3. **写操作统一入口**：所有写操作通过宿主暴露的有限方法集
4. **Context 不跨 Exploration**：每次新 Exploration 创建新 Context 实例
