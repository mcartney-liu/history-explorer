## Phase 1 — Frontend Reality Mapping

> 完整逐项映射见 `M90.3_CURRENT_TO_TARGET_MIGRATION_MAP.md`。此处只给结论与判断依据。

| DevCatalog | `#/dev/catalog` | `DevCatalog` | **无 Shell** | `causalObjects` | （开发用） | — |

**Phase 1 关键发现（超出 M90.1 审计的部分）：**

1. **Map 能力不存在。** M90 架构列出的 MapView 在当前代码中**没有对应实现**——`GraphViewPanel` 是关系图不是地图。M90.3 必须把 MapView 标为 **Reserved（预留占位，Mode 内置灰）**，不能假装迁移。
2. **CausalObject 有两条渲染路径**（App.tsx:1091 hash 分支 与 App.tsx:1353 NavNode 分支），渲染同一组件但一个在 Shell 内一个在 Shell 外。这是"同一能力两种容器"的最直接证据。
3. **Landing 与 Discover 同屏并列渲染**（App.tsx:1374-1410），不是二选一。用户看到的是两套入口叠在一起。
4. **M89 的 lazy 组件在 render 函数体内创建**（App.tsx:1059），每次 render 重建 lazy 包装。这是必须在 Stage A 顺带修掉的正确性缺陷，不是风格问题。
5. **Timeline 有四个并存实现**，Panel 归位时必须合并为一个 TimelineView，否则 Stage D 数字不会下降。

### 1.2 按 Experience Flow 重新分类（不按文件结构）

判断依据：**这个组件推进用户理解流程的哪一步？**

```
Question（我想理解什么）
  LandingPage(quickstart) · DiscoverPage · ExplorationPackagePage(header)
  → 目标：QuestionHeader + Discover Canvas

Exploration（我在看什么）
  EntityPage · MainEntityCard · SummaryPanel · StorySection · EntityPickerPanel
  TimelinePanel · TimelineStrip · MultiEntityTimeline · TemporalComparisonPanel
  ThemesPanel · GraphViewPanel · MultiEntityContextPanel · RelatedEntityList
  → 目标：Exploration Mode Canvas

Evidence（我获得了什么事实）
  ProvenancePanel · GroundingBadge · EventImpactPanel
  → 目标：EvidenceBlock（跨 Mode 复用）

Explanation（为什么发生）
  CausalObjectDetailPage · CausalStatementCard · AIExplanationPanel
  InterpretationPanel · WhyImportantPanel · ConnectionsExplainedPanel
  → 目标：Explanation Mode Canvas

Connection（它们之间有什么关系）
  RelationshipInsightPanel(35KB) · RelationshipView · RelationshipContext
  ConnectionsPanel · CrossTopicConnectionsPanel · CrossTopicView · TopicComparisonPanel
  → 目标：Relationship Mode Canvas

Understanding（我形成了什么理解）
  UnderstandingWorkspace(M89) · JourneyPanel · WorkspacePanel
  ExplorationPath · ExplorationJourney · ExplorationInsightPanel · ExplorationPathsPanel
  → 目标：Understanding Mode Canvas + Context Rail

New Question（我还想知道什么）
  ContinueExploringPanel · RecommendationPanel · ResearchPanel · ResearchDiscoveryPanel
  → 目标：NavigationAction + Companion Dock

无法归入任何一步（= 装饰品）
  FeedbackWidget · 3 个 Guide 组件中的 2 个 · SummaryPanel(301B)
  → 处置：删除或合并
```

### 1.3 处置标记原则

标记依据是**用户体验价值**，不是代码质量：

| 标记 | 判定标准 |
|------|---------|
| **保留** | 能回答 M90 §8.1 四问，且已是 Primitive 形态 |
| **迁移** | 能回答四问，但当前挂在错误容器上 |
| **合并** | 与其他组件回答了**同一个**用户问题（Timeline×4、Guide×3、Landing+Discover） |
| **废弃** | 答不出四问，或为单主题写死，或是死代码 |

## Phase 2 — 建立唯一 Explorer Shell

### 2.1 目标结构

```
ExplorerShell（唯一容器）
├── GlobalBar               系统身份 · 主题 · 检索
├── QuestionHeader          question + understandingGoal        [常驻]
├── ModeBar                 availablePerspectives               [常驻]
├── ContextRail             explorationPath / evidence / stage  [默认展开]
├── UnderstandingCanvas     当前 Mode 内容（唯一变化区）max 720px
├── NavigationContractBar   From / Why / Value                  [常驻不可关]
└── CompanionDock           AI 解释层                            [默认可见]
```

### 2.2 相对现状的强制修正

| 现状 | 违反 | 修正 |
|------|------|------|
| `ExplorationShell` 只有 3 个 slot（workspace/companion/timeline） | 缺 Question/Mode/Navigation 三个语义区 | 扩展为 7 区域 |
| `workspaceCollapsed = useState(true)` | EC-007 失败 | 默认 `false` |
| `companionCollapsed = useState(true)` | EC-005 失败 | 默认 `false` |
| Timeline 固定占据 footer | Timeline 是 Exploration Mode 的内容，不是 Shell 结构 | 从 Shell 移出，降为 Mode 内容 |
| 无 Navigation 语义区 | EC-003 / FP-03 失败 | 新增常驻区域 |

> **判断说明**：把 TimelineStrip 从 Shell footer 移出，是本 Phase 唯一一处**削减 Shell 能力**的改动。理由：Shell 区域必须服务 ExperienceSession 的字段，Timeline 服务的是 Fact Layer 数据，属于 Canvas 内容。若保留在 Shell，则 Relationship Mode / Understanding Mode 下会出现一条无意义的时间轴。

### 2.3 Shell 内禁止

```

## Phase 3 — 路由重构

### 3.1 废弃与替代

| 废弃 | 当前位置 | 替代 |
|------|---------|------|
| `#/m89` | App.tsx:1058, 1392 | `#/explore/:topic/understanding` |
| `#/causal/:id` | App.tsx:1079, 1086, 1100 | `#/explore/:topic/explanation/:focusId` |
| `#/package/:slug` | usePackageContext.ts | `#/explore/:topicSlug` |
| `#/entity/:gid` | App.tsx:1097（**只写不读，断链**） | `#/explore/:topic/exploration/:focusId` |
| `#/dev/catalog` | App.tsx:1074 | `#/explore/_dev/catalog`（dev-only，仍在 Shell 内） |

### 3.2 目标路由语法

```
#/                                    Shell + Discover（无 Session）
#/explore/:topicSlug                  Shell + Session + 默认 Mode
#/explore/:topicSlug/:mode            Shell + Session + 指定 Mode
#/explore/:topicSlug/:mode/:focusId   Shell + Session + Mode + 焦点
```

**URL 表达"用户正在理解什么"，不表达"打开哪个页面"。**

### 3.3 Router 契约

```
Router 输入：  location.hash
Router 输出：  { session: ExperienceSession, mode: ModeId, focusId: string | null }
Router 不输出："渲染哪个组件"
```

**硬约束**：`window.location.hash` 在整个 `frontend/src` 中只允许出现在 Router 模块内。任何组件读 hash = 架构违规。

### 3.4 兼容策略

旧 hash 做**一次性重定向**，不做长期双轨：

```
#/m89            → #/explore/french-revolution/understanding
#/causal/:id     → #/explore/{lookup(id).topic}/explanation/:id
#/package/:slug  → #/explore/:slug
#/entity/:gid    → 直接删除写入点（本就无消费者）
```

> **判断说明**：不保留长期兼容层。双轨路由等于保留绕过通道，而 M90 §1.3 根因 2 已判定"只要存在绕过通道就一定会被使用"。重定向表在 Stage C 结束后删除。

## Phase 4 — Mode 化迁移

### 4.1 Mode Registry 契约

Mode 是**数据驱动的注册项**，不是 switch 分支：

```
ModeDefinition {
  id            'exploration' | 'explanation' | 'relationship' | 'understanding' | 'civilization'
  label         用户可见名称
  question      该 Mode 回答的用户问题（显示在 Canvas 顶部）
  backendLayer  Fact | Explanation | Understanding | Runtime | Future
  isAvailable   (session) => boolean      ← 由数据可用性推导，禁止硬编码
  unavailableReason  string               ← 置灰时向用户说明原因
  Canvas        React 组件
}
```

**MR-03 强制**：`isAvailable` 只能读 Session 数据，不得读主题名。

### 4.2 五个 Mode 的初始归属

| Mode | 回答 | 后端层 | 迁入内容 | 可用条件 |
|------|------|--------|---------|---------|
| **Exploration** | 这是什么？ | Fact | EntityPage / MainEntityCard / StorySection / Timeline×4→1 / EntityPicker / Themes | 始终可用（默认） |
| **Explanation** | 为什么发生？ | Explanation | CausalObjectDetailPage / CausalStatementCard / Interpretation / AIExplanation / EventImpact | 存在 CausalObject 数据 |
| **Relationship** | 为什么值得一起理解？ | Understanding | RelationshipInsightPanel / RelationshipView / CrossTopic / TopicComparison | 存在 Semantic Relationship 数据 |
| **Understanding** | 我形成了什么理解？ | Runtime | M89 UnderstandingWorkspace（泛化）/ Journey / Workspace / ExplorationPath | `evidence.length ≥ 1` |
| **Civilization** | 有什么文明模式？ | M86+ | **仅注册，Canvas 返回置灰说明** | 完成 ≥2 主题 Loop（M90.3 内恒为 false） |

### 4.3 M89 泛化（本 Phase 最高风险项）

当前 `UnderstandingWorkspace` 依赖 `next/exploration/frenchRevolution/`。

泛化要求：

```
组件签名从：  <UnderstandingWorkspace />          （内部 import 法国大革命数据）
改为：        <UnderstandingCanvas session={} />  （数据由 Session 注入）
```

`frenchRevolution/` 目录降级为**一份数据 fixture**，不再是组件依赖。

**验收**：把 fixture 换成任意其他主题数据，Understanding Mode 必须正常渲染。做不到 = Stage C 不通过。

### 4.4 MapView 的诚实处理

代码审计确认：**地理 Map 能力当前不存在**。

处置：在 Exploration Mode 内注册 `MapView` 为 Reserved 占位，`isAvailable` 恒 false，置灰文案说明"该主题暂无地理数据"。

> **判断说明**：M90 架构把 MapView 列入 Primitives 清单，但架构文档描述的是目标态。M90.3 不能把不存在的能力写成"迁移"，否则 Stage D 验收会出现虚假通过。这是我对上游文档的一处修正，需在确认时一并裁决。

- 目标是文明探索产品，不是 SaaS Dashboard。

## Phase 7 — Navigation Experience

### 7.1 废弃 Breadcrumb

`navigation.ts` 的 `buildBreadcrumb` 产出纯节点名序列，无语义，废弃。

### 7.2 Understanding Navigation Contract

每次跳转必须显示三元组：

| 字段 | 含义 | 数据来源 | 禁止 |
|------|------|---------|------|
| **From** | 你刚刚理解了什么 | `previousAnchor.displayName` + 该 Anchor 产生的理解 | AI 生成 |
| **Why** | 为什么看到这个 | `activeRelation.descriptionRef` → Causal/Understanding Layer 查询 | AI 生成（EP-009） |
| **Value** | 它会增加什么理解 | Curator 撰写的 `understandingGoal` 片段 | AI 生成 |

### 7.3 硬约束

```
没有 Why → 禁止渲染为可点击链接
```

这条直接决定产品与 Wikipedia 的区别（Understanding Graph vs Information Graph）。

**执行影响**：`ContinueExploringPanel` / `RecommendationPanel` / `CrossTopicView` 当前产出的大量跳转**没有 Why 数据**。这些跳转在 Stage E 之后要么补上 Relation 数据，要么降级为不可点击的展示项。这会导致可见链接数量**明显减少**——这是预期结果，不是回退。

### 7.4 Breadcrumb 语义化

```
现在：  罗马 > 凯撒 > 高卢战争
