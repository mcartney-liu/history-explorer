> **阶段**：M83.1 Explorer Validation Instrumentation — Design Review

## Executive Summary

M83.1 的目标是在现有前端事件系统中增加 CausalStatement 交互的埋点，为 M83.4（Explorer Validation Execution）提供行为数据。

**关键发现**：项目已有完整的前端事件系统（17 种事件类型、localStorage 存储、分析管线），但**零 CausalStatement 事件**。M83.1 仅需扩展 `UserBehaviorEvent.ts`，新增 5-7 个事件类型。不涉及后端、不引入新依赖、不修改架构。

## 1. Current Capability Audit

### 1.1 已有事件系统

| 维度 | 现状 |
| --- | --- |
| **存储** | 纯 `localStorage`（key: `history-explorer.events.v1`），上限 1000 条 |
| **事件 Schema** | `{action: BehaviorAction, entityGlobalId?, entityType?, tab?, packageSlug?, sourceId?, timestamp: ISO8601}` |
| **已定义事件** | 17 种（12 种实际 emit，5 种有类型无调用者） |
| **emit 机制** | 纯函数式 `recordEvent(event)` → 写入 localStorage（无事件总线/无 pub-sub） |
| **消费机制** | Pull 模式：分析管线通过 `getEvents()` 读取 |
| **会话模型** | 30 分钟间隔启发式（无 session ID，无 session_start/end 事件） |
| **后端** | 零后端事件端点（无 `POST /events`） |
| **CausalStatement 事件** | **零**（无任何 `causal*` 事件类型） |
| **分析管线** | 已有（漏斗分析/行为模式/探索深度/知识覆盖率/产品智能指标） |

### 1.2 现有分析管线能回答什么？

| 现有能力 | 能否用于 M83 Validation？ |
| --- | --- |
| `explorationMetrics.ts` — 探索深度/覆盖率/扩展/引导交互 | 🟡 部分 — 能计算 "含 CS 的路径深度"，但无法区分 "CS 被看了" vs "CS 被忽略了" |
| `ExplorationFunnelAnalysis.ts` — 漏斗分析 | ❌ 不适用 — 无 CS 相关漏斗步骤 |
| `ExplorationBehaviors.ts` — 行为模式检测 | ❌ 不适用 — 无 "因果探索" 模式定义 |
| `ProductIntelligence.ts` — 产品智能 | ❌ 不适用 — 无 CS 相关转化率/流失点 |

### 1.3 缺失的能力

| 缺失 | M83.4 需要？ |
| --- | --- |
| CS 是否被展示 | ✅ 是 — 验证 CS 是否有机会被看到 |
| CS 是否被点击/展开 | ✅ 是 — 验证 Explorer 是否主动探索因果信息 |
| CS 哪个部分被关注（mechanism/consequence/evidence） | ✅ 是 — 验证三层信息中哪个最有价值 |
| CS 出现后是否继续探索 | ✅ 是 — 验证因果解释是否提升探索深度 |
| CS 的 confidence 是否被注意到 | 🟡 部分 — Session Review 定性验证为主，事件为辅 |

## 2. Event Model Proposal

### 2.1 新增 BehaviorAction

```typescript
// 新增 7 种事件类型（追加到现有 BehaviorAction 联合类型）

type BehaviorAction =
  | "open_discover"       // 已有
  | "click_entity"        // 已有
  | "open_entity"         // 已有
  | "switch_tab"          // 已有
  | "click_relationship"  // 已有
  | "click_journey"       // 已有
  | "start_chat"          // 已有
  | "open_package"        // 已有
  | "click_guide_next"    // 已有
  | "view_source"         // 已有
  | "complete_package"    // 已有
  | "start_research"      // 已有
  | "save_research"       // 已有
  | "restore_research"    // 已有
  | "start_comparison"    // 已有
  | "click_recommendation"// 已有
  | "delete_research"     // 已有
  | "reset"               // 已有
  // ─── M83.1 新增 ───
  | "cs_card_view"              // CS Card 被渲染/展示
  | "cs_card_click"             // CS Card 被点击（展开/聚焦）
  | "cs_mechanism_read"         // Mechanism 区域被展开或停留
  | "cs_consequence_read"       // Consequence 区域被展开或停留
  | "cs_evidence_click"         // Evidence 引用被点击
  | "cs_guide_next"             // 看到 CS 理由后点击 Guide 下一步
  | "cs_confidence_notice"      // Confidence 标识被 hover/点击
```

### 2.2 扩展 UserBehaviorEvent Schema

```typescript
// 现有字段不变，新增 2 个可选字段
interface UserBehaviorEvent {
  action: BehaviorAction;          // 不变
  entityGlobalId?: string;         // 不变
  entityType?: string;             // 不变
  tab?: string;                    // 不变
  packageSlug?: string;            // 不变
  sourceId?: string;               // 不变
  timestamp: string;               // 不变
  // ─── M83.1 新增 ───
  causalId?: string;               // CausalStatement ID（如 "cs-001"）
  causalConfidence?: string;       // CS 置信度（"high"|"medium"|"low"|null）
}
```

### 2.3 事件设计原则

| 原则 | 说明 |
| --- | --- |
| **最小化** | 仅新增 M83.4 验证必须的事件。不做 "可能有用" 的事件 |
| **不改变现有 Schema** | 只追加字段（`causalId?` / `causalConfidence?`），不修改已有字段 |
| **不改变存储机制** | 继续使用 localStorage，上限 1000 条，不上传后端 |
| **不与现有事件耦合** | 新事件是独立类型，不影响现有分析管线 |

## 3. Metric Definition

### 3.1 M83.4 验证指标 → 事件映射

| M83.4 验证指标 | 事件 | 计算方式 |
| --- | --- | --- |
| **CS Card Click Rate** | `cs_card_view` + `cs_card_click` | `cs_card_click / cs_card_view` |
| **Continue Exploration Rate** | `cs_card_view` + `cs_guide_next` | `cs_guide_next after cs_card_view / cs_card_view` |
| **Exploration Depth**（含 CS） | `open_entity`（已有）+ `cs_card_view` | 含 CS 事件的 session 中 `open_entity` 序列长度 |
| **CS 关注焦点分布** | `cs_mechanism_read` / `cs_consequence_read` / `cs_evidence_click` | 各事件频率占比 |
| **Confidence 注意率** | `cs_confidence_notice` / `cs_card_view` | 注意到 confidence 标识的比例 |
| **CS vs 模板 reason 对比** | `cs_guide_next` vs `click_guide_next`（已有） | 有 CS 理由时的 follow-through rate vs 无 CS 时 |

### 3.2 不采集的指标

| 不采集 | 理由 |
| --- | --- |
| CS Card 停留时间 | 需要 timer，增加复杂度，Session Review 定性验证即可 |
| CS 阅读完成率（scroll to end） | 需要 IntersectionObserver，过度设计 |
| CS 内容复现率（用户是否记住内容） | 无法通过前端事件采集，属于 Session Review 范畴 |

## 4. Data Flow

### 4.1 事件产生

```
CausalStatementCard
  ├── on mount        → recordEvent({action: "cs_card_view", causalId, causalConfidence})
  ├── on click        → recordEvent({action: "cs_card_click", causalId})
  ├── mechanism expand → recordEvent({action: "cs_mechanism_read", causalId})
  ├── consequence expand → recordEvent({action: "cs_consequence_read", causalId})
  ├── evidence click  → recordEvent({action: "cs_evidence_click", causalId})
  └── confidence hover → recordEvent({action: "cs_confidence_notice", causalId, causalConfidence})

GuidePanel
  └── next click (after CS reason) → recordEvent({action: "cs_guide_next", causalId})
```

### 4.2 事件消费

```
localStorage (history-explorer.events.v1)
  ↓
getEvents() / getEventsByAction("cs_*")
  ↓
M83.4 Validation Script (Session Review 时手动运行)
  ↓
M83 Validation Report
```

### 4.3 不需要新增分析管线

M83.4 的验证是 **Session Review 驱动**（定性为主，定量为辅）。事件数据在 Session Review 中作为辅助证据使用，不需要为此新增自动化分析管线（如 `explorationMetrics.ts` 的扩展）。Session Review 时手动查询即可。

## 5. Privacy Consideration

| 维度 | 现状 | M83.1 后 |
| --- | --- | --- |
| **数据存储位置** | localStorage（仅前端） | 不变 |
| **数据上传后端** | 否 | 不变 |
| **PII（个人可识别信息）** | 无（不采集用户身份） | 不变 |
| **数据保留** | 上限 1000 条，超出自动丢弃 | 不变 |
| **数据可清除** | `clearEvents()` | 不变 |
| **新增可识别字段** | — | `causalId`（CS ID，非用户数据）+ `causalConfidence`（数据元信息） |

**结论：M83.1 不引入任何隐私风险。新增字段均为产品数据元信息，不涉及用户身份。**
