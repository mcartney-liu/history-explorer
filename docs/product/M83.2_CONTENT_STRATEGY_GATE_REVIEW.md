## Executive Summary

M83.2 的目标不是 "增加 CausalStatement 数量"，而是 **确保 M83.4 Explorer Validation 的实验变量质量可控**。

当前 5 条 CS 的质量分析揭示了一个模式：高质量 CS 的共同特征是 **Exploration Value** — 即 "这条因果解释能否引导 Explorer 继续探索"。如果一条 CS 只是 "讲了一个好故事" 但不会触发后续探索，它对 M83.4 的验证无价值。

因此，M83.2 的内容标准必须回答一个问题：**什么样的 CS 能帮助验证 "因果解释是否改变探索行为"？**

## 1. 当前 CausalStatement 内容质量审计

### 1.1 逐条分析

| ID | 因果链 | 质量 | Exploration Value | 问题 |
| --- | --- | --- | --- | --- |
| **cs-001** | 科举 → 文官 | 🟢 高 | 🟢 高 — 科举和文官都是独立 Entity，Explorer 可以沿任意方向继续探索 | 无 |
| **cs-002** | 三省六部 → 内阁 | 🟢 高 | 🟢 高 — 两个制度性 Entity，mechanism 解释了制度演化逻辑 | 无 |
| **cs-003** | 唐诗 → 宋词 | 🟢 高 | 🟡 中 — 文学继承关系，但 Explorer 从 "词" 出发的继续探索方向不够明确 | mechanism 引用了 "影响的焦虑"（文学理论概念），Explorer 可能不熟悉 |
| **cs-004** | 宋朝 → 理学 | 🟡 中 | 🟡 中 — confidence="low" 本身就是实验价值，但 mechanism 过度学术化（"佛道影响仍有争议"） | 学术争议的表述方式可能让 Explorer 困惑而非好奇 |
| **cs-005** | 明朝 → 郑和 | 🟢 高 | 🟢 高 — 郑和是 Event 而非 Idea，consequence 包含了历史转折性叙事（"从海洋撤退"） | 无 |

### 1.2 模式识别

| 维度 | 高质量特征（cs-001/002/005） | 可改进特征（cs-003/004） |
| --- | --- | --- |
| **Cause** | 制度性 Entity（科举/三省六部/明朝） | 文化性 Entity（唐诗/宋朝） |
| **Effect** | 独立的、可继续探索的 Entity（文官/内阁/郑和） | Effect 的探索方向不够明确 |
| **Mechanism** | 具体的历史因果机制（"考试取代世袭"） | 过度学术化（"影响的焦虑"、"佛道影响有争议"） |
| **Consequence** | 包含历史转折性叙事（"从海洋撤退"） | 偏向学术评价 |
| **Exploration Value** | 高 — Effect 是独立的 KG 节点，有丰富的出边 | 中 — Effect 的出边不够丰富 |

### 1.3 关键洞察

**M83.4 验证的不是 "CS 写得好不好"，而是 "CS 出现后 Explorer 是否继续探索"。**

因此 CS 的 Exploration Value 由以下因素决定：
1. **Effect Entity 的出边丰富度** — Effect 是一个有很多连接的 KG 节点
2. **Mechanism 的可理解性** — Explorer 不需要专业知识就能理解 "为什么"
3. **Consequence 的探索引导力** — 读完 consequence 后，Explorer 有 "接下来我想了解 X" 的冲动

## 2. 高质量 CS 标准

### 2.1 必须满足的标准

每条新增 CS 必须同时满足以下 4 项：

| # | 标准 | 定义 | 验证方式 |
| --- | --- | --- | --- |
| **S1** | **KG 连通性** | Cause 和 Effect 都必须是在 KG 中实际存在的 Entity，且两者之间存在 `caused` / `influenced` 等关系边 | 检查 `cause_id` 和 `effect_id` 在 KG 中是否存在，以及两者之间是否有路径 |
| **S2** | **Exploration Value** | Effect Entity 至少有 3+ 条出边（关系连接），确保 Explorer 有足够的 "下一步" 可探索 | 检查 Effect 的 KG 出边数量 |
| **S3** | **Mechanism 可理解性** | 不需要专业知识即可理解 "为什么发生"。避免学术术语和过度学术化的表述 | 人工审核 — 非历史专业的人读一遍能复述 |
| **S4** | **Confidence 多样性** | 5-10 条 CS 中至少包含 1 条 `confidence="low"` 和 1 条 `confidence="medium"`，确保 M83.4 能验证 "用户是否注意到 confidence 差异" | 统计 confidence 分布 |

### 2.2 不应包含的 CS

| 类型 | 为什么排除 | 示例 |
| --- | --- | --- |
| **纯学术争议** | 不会引导 Explorer 继续探索，而是让 Explorer 困惑 | "理学是否由佛道推动"（已在 cs-004 中，保留但作为 low confidence 样本） |
| **Effect 是叶子节点** | 没有出边，Explorer 无法继续 | 一个没有后续关系的终点 Entity |
| **Cause 和 Effect 不在同一个包** | 跨包关联在当前 KG 中可能不完整 | 罗马的某个 Entity 导致中国的某个 Entity（除非有明确的跨包路径） |
| **Effect 是 Cause 的简单属性** | 不是因果，是定义 | "唐朝的首都是长安"（这不是因果） |
| **纯描述性文本** | 不是因果解释，是历史叙述 | "唐朝经历了安史之乱"（没有解释为什么） |

## 3. 数量策略

### 3.1 数量目标

```
5-10 条，其中新增 3-5 条
```

| 分类 | 数量 | 说明 |
| --- | --- | --- |
| **保留现有** | 5 条 | cs-001 到 cs-005，质量可接受 |
| **新增（中国包）** | 2-3 条 | 补充中国包中 Exploration Value 更高的因果链 |
| **新增（罗马包）** | 1-2 条 | 覆盖罗马包的关键因果，验证跨包场景 |
| **合计** | 8-10 条 | |

### 3.2 为什么不是 15+ 条

1. M83.4 的验证是 **定性为主**（Session Review），5-10 条样本足够
2. 超过 10 条后，边际验证价值递减 — 第 11 条 CS 不会比第 10 条提供更多验证信息
3. 数量越多，质量越难保证 — "为了凑数而加" 的风险上升

## 4. Content Quality Checklist

每条新增 CS 必须通过以下 checklist 才能入库：

| # | 检查项 | 通过条件 |
| --- | --- | --- |
| C1 | **KG 验证** | `cause_id` 和 `effect_id` 在 KG 中存在，且两者之间有路径 |
| C2 | **Exploration Value** | Effect 有 ≥3 条出边 |
| C3 | **Mechanism 长度** | 50-200 字（太短 = 无解释力，太长 = 不易阅读） |
| C4 | **Mechanism 可理解性** | 非专业读者能用自己的话复述 |
| C5 | **Consequence 探索引导力** | Consequence 包含至少一个可继续探索的方向 |
| C6 | **Evidence** | 至少有 1 个 evidence_ref（引用现有 Evidence Layer 记录） |
| C7 | **Confidence 标注** | 明确标注 high/medium/low，理由可追溯 |
| C8 | **Schema 合规** | 7 字段完整（id/cause_id/effect_id/mechanism/consequence/confidence/evidence_refs） |

## 5. Content Format（冻结）

```json
{
  "id": "cs-{NNN}",                          // 格式：cs- 前缀 + 3 位数字
  "cause_id": "{package}:{entity_type}-{id}", // KG GID 格式
  "effect_id": "{package}:{entity_type}-{id}",// 同上
  "mechanism": "具体的历史因果机制描述",       // 50-200 字，可理解性优先
  "consequence": "历史影响与探索引导",         // 包含至少一个可继续探索的方向
  "confidence": "high|medium|low",            // curator assessment，可追溯
  "evidence_refs": ["ec-{pkg}-{NNN}"]        // 至少 1 个引用
}
```

**禁止**：
- 新增 Schema 字段
- 修改已有 CS 的 id（会破坏 M83.1 的 `causalId` 关联）
- 修改已有 CS 的 `cause_id` / `effect_id`（会破坏 KG 连通性）

## 6. Freeze Boundary

### 6.1 Allowed

| 操作 | 范围 |
| --- | --- |
| 在 `data/causal_statements.json` 中追加 3-5 条新 CS | 仅追加，不修改已有条目 |
| 同步更新 `ExplorationPackagePage.tsx` 中的硬编码 CS（如果 DEBT-001B 未完成） | 保持与 JSON 一致 |
| 新增 CS 的 evidence_refs 引用现有 Evidence Layer 记录 | 不新增 Evidence 记录 |

### 6.2 Forbidden

| 操作 | 理由 |
| --- | --- |
| 修改已有 CS 的任何字段 | 破坏 M83.1 的 causalId 关联 |
| 新增 Schema 字段 | C-7 约束 |
| 新增 Evidence Layer 记录 | M83 不涉及 Evidence Layer |
| 修改 CS 的 id 格式 | 破坏因果关联 |
| 为罗马包新增 KG Entity | M83 不涉及 KG 数据层 |
