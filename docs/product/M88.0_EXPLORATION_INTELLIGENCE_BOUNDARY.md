# M88.0 — Exploration Intelligence Boundary Contract
### Strict Read-Only / Boundary Freeze

> 模式声明：严格只读。冻结 Exploration Intelligence 作为第五个 Domain Module 的 Runtime 边界。不写代码。

---

## 一、定位

Exploration Intelligence 是 Cognitive Runtime 上的**第五个 Domain Module**。

```
Cognitive Runtime Kernel
    ├── Understanding Module     (M86)
    ├── Memory Module            (M86)
    ├── Companion Module         (M87)
    ├── Exploration Module       (M88) ← 当前
    └── Future Domains
```

不是 Runtime Kernel 的修改。不是独立推荐系统。

---

## 二、核心假设（Hypothesis Freeze）

> **如果系统理解用户当前探索状态，并根据认知缺口主动引导下一步探索，那么用户将获得比传统搜索/百科浏览更连续、更深入的历史理解。**

验证目标：Exploration Depth ↑ / Exploration Continuity ↑

---

## 三、Exploration ≠ Recommendation

这是 M88.0 最重要的边界。

| 维度 | Recommendation（禁止） | Exploration Intelligence（目标） |
|------|------------------------|--------------------------------|
| 核心对象 | Item recommendation | Knowledge progression |
| 驱动信号 | 点击率/时长/流行度 | 认知缺口/理解状态 |
| 输出形式 | "猜你喜欢：罗马帝国" | "你已理解军事扩张，但缺少经济基础——如果继续，会发现道路也是贸易网络" |
| 判定方式 | 协同过滤/排序算法 | Policy 规则（RuleTrace 可审计） |
| 用户感知 | 被动接收 | 主动认知推动 |

---

## 四、ExplorationState（核心输入）

ExplorationState 是当前探索 Session 的状态快照。它不是 Memory（长期认知成长），而是从 Memory + Understanding + Companion 聚合的当前状态。

```typescript
ExplorationState {
  explorationId: string
  currentTopic: string
  understandingStage: UnderstandingStage
  coverageRatio: number
  knownDimensions: string[]
  missingDimensions: string[]
  missingConnections: MissingLink[]
  activeQuestions: string[]           // 用户已提出的问题
  explorationHistory: string[]        // 已探索的 entityId 序列
  memoryProjection: MemoryProjection | null
  understandingProjection: UnderstandingProjection | null
}
```

关系：

```
Memory (长期认知成长)
    ↓
ExplorationState (当前 Session 快照)
    ↓
ExplorationPolicy (生成探索建议)
```

---

## 五、ExplorationAction（核心输出）

输出必须走 `Decision<ExplorationAction>`。

```typescript
ExplorationActionType =
  | 'deep_continue'     // 深化当前维度（同一主题，更深层次）
  | 'open_dimension'    // 打开缺失维度（扩展理解广度）
  | 'follow_cause'      // 追踪因果关系（因果链推进）
  | 'compare_context'   // 跨语境对比（横向理解）
  | 'reflect'           // 理解收束（帮助用户形成总结）

ExplorationAction {
  type: ExplorationActionType
  targetRef: string                   // 目标 entityId / relationId
  reason: string                      // 为什么建议这个方向（来自 RuleTrace）
  narrativeHook: string               // 叙事钩子（吸引用户继续）
  expectedGrowth: {
    dimension: string                 // 预期覆盖的维度
    relationType: string              // 预期建立的关系类型
  }
  confidence: number
}
```

## 六、禁止 AI 决定探索方向

继续沿用 M87 原则。

```
错误：
  LLM: "我觉得你应该看秦朝"

正确：
  ExplorationPolicy:
    发现：当前理解缺少制度演化链
    ↓
  Decision<ExplorationAction>:
    type: "follow_cause"
    targetRef: "qin-han-transition"
    reason: "missing causal link: 罗马共和→帝国 的对比案例"
    ↓
  LLM (Renderer):
    解释为什么秦汉制度转换值得探索
```

LLM 只负责解释，不负责决定方向。

## 七、ExplorationPolicy 规则（第一版原则）

### 7.1 输入

```
ExplorationPolicyContext {
  state: ExplorationState
  understandingProjection: UnderstandingProjection
  memoryProjection: MemoryProjection
}
```

### 7.2 规则（Policy 规则，非 AI 规则）

| 条件 | 输出 |
|------|------|
| coverageRatio < 1.0 && missingDimensions.length > 0 | open_dimension（最优先） |
| missingConnections.length > 0 | follow_cause |
| understandingStage = UNDERSTANDING | reflect |
| coverageRatio < 1.0 && missingDimensions.length = 0 && missingConnections.length = 0 | deep_continue |
| 默认 | deep_continue |

### 7.3 RuleTrace 要求

每一条 ExplorationAction 必须包含 RuleTrace：
```
{
  ruleId: "exploration-open-dimension",
  inputs: { missingDimensions: ["economy"], coverageRatio: 0.45 },
  decision: true
}
```

## 八、约束（不可妥协）

### 8.1 Runtime 兼容性

- ✅ 输出 `Decision<ExplorationAction>`
- ✅ RuleTrace 可审计
- ✅ Replay 可回放
- ✅ 不修改 Runtime Kernel
- ✅ 不访问 MemoryStore（通过 Projection 消费）
- ✅ 不调用 LLM（Policy 纯规则）

### 8.2 探索方向约束

- ❌ 不基于点击率/时长/流行度
- ❌ 不基于协同过滤
- ❌ 不基于"其他用户也看了"
- ❌ 不由 LLM 决定方向
- ❌ 不推荐用户已探索过的 entity

### 8.3 认知推进约束

- ✅ 基于 coverageRatio / missingDimensions / missingConnections
- ✅ 基于 UnderstandingStage 判定推进深度
- ✅ 基于 MemoryProjection 避免重复
- ✅ ExplorationAction.reason 必须来自 RuleTrace

## 九、与已有 Domain 的关系

### 9.1 Exploration ↔ Understanding

```
UnderstandingProjection → ExplorationState → ExplorationPolicy
```

Exploration 消费 Understanding 的 coverage/missingLinks 来决定方向。

### 9.2 Exploration ↔ Memory

```
MemoryProjection → ExplorationState → ExplorationPolicy
                     ↓
              ExplorationAction → 用户行动 → Memory Growth
```

Exploration 消费 Memory 的 stageTimeline/activeBranches 来避免重复推进。用户采纳 ExplorationAction 后，Memory 记录 Growth。

### 9.3 Exploration ↔ Companion

```
ExplorationAction → CompanionPolicy → CompanionResponse → Explanation → 用户
```

Exploration 决定方向，Companion 决定如何呈现。两者不互相替代。

## 十二、最大风险与缓解

| 风险 | 缓解 |
|------|------|
| Exploration 退化成推荐系统 | 严格约束 Policy 规则来源（coverage/missing/relations，非点击指标） |
| Exploration 与 Companion 职责重叠 | Companion 负责呈现策略，Exploration 负责方向决策 |
| ExplorationState 与 Memory 混淆 | ExplorationState 是 Session 快照（当前），Memory 是长期成长（历史） |
| 用户不采纳建议 → 系统无反馈 | M88.5 验证，不采纳也是信号 |
