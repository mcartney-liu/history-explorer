## 1. Event Storage Boundary

### 判定

```
✅ 复用现有 UserBehaviorEvent pipeline — localStorage only
❌ 不新增 backend endpoint / analytics service / 第三方 SDK
```

### 边界

| 允许 | 禁止 |
| --- | --- |
| `recordEvent()` → `localStorage`（现有管道） | 新建 `POST /events` 后端端点 |
| `getEvents()` / `getEventsByAction()`（现有读取） | 新建 Analytics Service |
| M83.4 Session Review 时手动查询 | 上传用户行为数据到后端 |
| | 引入第三方 analytics SDK（如 Mixpanel / Amplitude / Google Analytics） |
| | 新建 `AnalyticsEngine` / `EventBus` 等新架构组件 |

### 理由

M83 是产品验证实验，不是产品数据平台建设。现有 localStorage 管道 + 手动查询足以支撑 M83.4 的 Session Review（定性为主，定量为辅）。新建 backend endpoint 或 analytics service 是 M84+ 的工程基础设施工作，M83 阶段过度设计。

## 2. causalId Boundary

### 判定

```
✅ 来源仅 CausalStatement.id — 不生成、不修改、不扩展
```

### 边界

| 允许 | 禁止 |
| --- | --- |
| `causalId = causalStatement.id`（如 `"cs-001"`） | `causalId = uuid()` 运行时生成 |
| 从 CausalStatementData 对象中提取 `id` 字段 | `causalId = timestamp()` |
| `causalId` 为空时不 emit（CausalStatementCard 仅在有 `id` 时 emit） | `causalId = hash(entity_a + entity_b)` |
| | 修改 CausalStatement.id 格式或语义 |
| | 在没有 CausalStatement 数据时生成假的 causalId |

### 理由

`causalId` 的唯一作用是**关联 Behavior Data 和 Semantic Content**。如果运行时生成，关联就会断裂——无法从事件追溯到具体的 CausalStatement 内容（mechanism / consequence / confidence）。

这保证了 M83.4 的离线关联可行：

```
event.causalId = "cs-001"
    ↓
causal_statements.json → cs-001 → { mechanism, consequence, confidence }
```

## 3. Component Boundary

### 判定

```
✅ CausalStatementCard 仅 emit 事件 — 不根据事件改变行为
```

### 边界

| 允许 | 禁止 |
| --- | --- |
| 在 mount / click / entity click / evidence click 时调用 `recordEvent()` | 根据 `cs_card_view` 次数改变 CS Card 展示（如 A/B 测试不同样式） |
| 在已有事件处理函数中追加 `recordEvent()` 调用 | 根据用户行为推荐不同的因果解释 |
| | 动态调整 `confidence` 标识（如 "已有 12 人查看"） |
| | 根据 `cs_card_expand` 频率改变 UI 逻辑 |
| | 在 CausalStatementCard 内部引入任何状态管理（`useState` / `useReducer`）用于事件计数 |

### 理由

Instrumentation 是**被动采集**，不是**主动控制**。如果 CausalStatementCard 根据事件改变行为，Instrumentation 就从 "观察者" 变成了 "参与者"——它改变了自己正在测量的事物。这在测量学中称为 Observer Effect，会污染 M83.4 的验证结果。

**具体实现约束**：

```tsx
// ✅ 允许：在已有交互回调中追加 recordEvent
const handleClick = () => {
  // ... 现有逻辑不变
  recordEvent({ action: "cs_card_expand", causalId: cs.id });
};

// ❌ 禁止：根据事件状态改变渲染
const [expandCount, setExpandCount] = useState(0);
// ... 根据 expandCount 改变 UI
```
