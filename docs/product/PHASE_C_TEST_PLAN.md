> 目的：验证「下一站探索」是否从**写死路线**变为**基于证据/上下文的候选决策**（ADR-0024）
> 时长：约 3–5 分钟

## 0. 前置

1. 打开公网隧道页面：`https://cache-crawford-trusted-kenny.trycloudflare.com`
2. **强制刷新**（Windows：`Ctrl + Shift + R`），确保加载新构建（新包 `index-BAtZfyDy.js` 含 C 层代码）
3. 认识目标区域：实体页底部有一块「**下一站探索**」（英文 Next Steps，带 inference 小徽标）——里面的推荐条目就是本次改造对象

---

## 1. 主路径（推荐）：从探索包进入，看「下一站探索」

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1.1 | 首页点「**了解**」标签 → 往下滚到「官方探索包」→ 点任意一个包（如「丝绸之路探索包 V1」） | 进入包详情页 |
| 1.2 | 在包详情页点**任意一个实体**（如某王朝/人物/地点） | 进入实体页；顶部有「来自探索包」衔接卡（Phase B 效果）；**底部出现「下一站探索」** |
| 1.3 | 看「下一站探索」里**第一条**推荐的**理由文字**（reason） | **Phase C 生效**：第一条理由应是 C 的文案（见对照表），**不再是**「剧本下一站 · 导致」这类 |

### 判定：看第一条的理由文字（对照表）

| 你看到的 reason 文案 | 来源 | 说明 |
|---|---|---|
| 「命中你标记的探索缺口」 | **C 层 L1** | 候选命中用户标记的缺口，最高优先 ✅ |
| 「与当前探索上下文最匹配」 | **C 层 L2** | 上下文特征（主题/维度/路径）胜出 ✅ |
| 「与当前实体存在最可靠的关系」 | **C 层 L3** | 关系证据（RS 查表）胜出 ✅ |
| 「提供全新的探索方向」 | **C 层 L4** | 新颖度胜出 ✅ |
| 「多个方向旗鼓相当，选择稳定衔接的下一步」 | **C 层 L5** | 平局确定性 tie-break ✅（注意：此文案不含来源描述，是 D22 红线） |
| 「当前仅有一个可探索方向」 | **C 层** | 单候选场景 ✅ |
| 「剧本下一站 · 导致/影响/…」 | **旧逻辑兜底** | C 候选为空时才出现（D11 回退链）——若**经常**看到，说明 C 没生效，报给我 |
| 「已覆盖…缺少「X」维度」 / 「你标记了还想搞清楚…」 | **旧 policyAction** | 兜底项（见 §3 特殊情况） |

> 关键判断：**第一条 reason 属于上表前 6 行 = C 在干活**；属于后 2 行 = C 未接管或回退。

---

## 2. 核心验证：连续点「下一步」，看排序是否按依据走

| 步骤 | 操作 | 预期 |
|---|---|---|
| 2.1 | 在实体页点「下一站探索」里的第一条 → 跳到新实体 | 新实体页底部「下一站探索」**重新计算**，第一条理由仍然是 C 文案（证据/上下文依据） |
| 2.2 | 连续跳 2–3 次 | 每次推荐**都有明确理由**（不是固定按包内顺序走） |
| 2.3 | （进阶）观察：若包内「剧本下一站」与当前实体**没有直接关系/不匹配上下文**，它应被**压到后面**（可能不在第一条），而不是无脑排第一 | package_next 无特权（PC5 红线） |

### 反向验证（可选，最能看出"无特权"）

- 找一个「下一站探索」里第一、二条**不是**包内下一站的场景 → 说明 C 按证据/上下文重新排序了，而不是照抄剧本路线 ✅

---

## 3. 特殊情况（遇到别慌，是预期行为）

| 场景 | 预期 |
|---|---|
| 你之前在理解工作区**标记过缺口**（"还想搞清楚X"） | 「下一站探索」第一条是「你标记了还想搞清楚…」——这是 **Rule 0 显式意图优先**（C3 红线：用户说了去哪，C 不介入）✅ |
| 候选全部已探索/无数据 | 「下一站探索」退回旧逻辑（剧本下一站/维度补缺）——D11 回退链 ✅ |
| 从首页直接点实体（非包路径） | 「下一站探索」仍会算 C 候选（图邻居/跨主题桥/维度目标），但候选可能少——属正常 |
