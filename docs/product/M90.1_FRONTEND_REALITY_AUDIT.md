# M90.1 — Frontend Reality Audit
### Read-Only / No Code Changes

> 模式：只读审计。分析当前前端所有入口、UI 模式、体验碎片化问题。

## 一、用户入口总览（7 个独立入口）

```
首页 (LandingPage + DiscoverPage 双渲染)
    ├── QuickStart chips（4个）        → #/explore → Explorer Shell
    ├── M89 Understanding Entry         → #/m89     → Understanding Workspace（独立页面）
    ├── 精选主题卡片                    → #/explore → Explorer Shell
    ├── 探索包卡片                      → #/package/xxx → ExplorationPackagePage（Shell内）
    ├── 实体卡片                        → #/explore → Explorer Shell
    ├── 最近探索列表                    → #/explore → Explorer Shell
    └── 主题网格                        → #/explore → Explorer Shell

独立路由:
    #/causal/xxx                        → CausalObjectDetailPage（独立页面，无 Shell）
    #/m89                               → Understanding Workspace（独立页面，有简易 Header）
```

**问题**：同一个产品，7 个入口 → 3 种完全不同的容器（Explorer Shell / 独立页面 / 简易 Header）。

## 二、User Journey Map（每条入口的完整路径）

### 路径 1：QuickStart（凯撒/秦始皇）
```
首页 QuickStart 点击
    ↓
#/explore (topic 模式)
    ↓
Explorer Shell:
  - 左 WorkspacePanel（默认收起）
  - 主画布（15+ 面板堆叠: SummaryPanel / StorySection / TimelinePanel / GraphView / AIExplanation / EntityPicker / ContinueExploring...）
  - 右 Companion（默认收起）
  - 底 TimelineStrip
    ↓
下一步：点击任何面板内链接 → 新实体/关系 → 同一 Shell 内更新
```

### 路径 2：探索包（法国/德国）
```
首页探索包卡片点击
    ↓
#/package/xxx
    ↓
ExplorationPackagePage（Explorer Shell 内）
  - 不同的页面结构: Package 概览 + 关系图 + 实体列表
    ↓
下一步：点击包内实体 → #/explore → Explorer Shell
```

### 路径 3：法国大革命（M89）
```
首页 Understanding Entry 点击
    ↓
#/m89
    ↓
Understanding Workspace（独立页面，简易 Header）
  - 完全不同的 UI: 垂直流 / 暗色主题 / 金
色主色 / Serif 字体
  - 无 Shell 的 WorkspacePanel / Companion / TimelineStrip
    ↓
下一步：只有 3 个 Evidence → Closure → 回到首页
```

### 路径 4：因果对象
```
任何页面因果对象链接点击
    ↓
#/causal/xxx
    ↓
CausalObjectDetailPage（独立页面，无 Shell）
    ↓
下一步：只能返回，无 Shell 导航
```

## 三、UI Pattern Inventory

### 3.1 组件统计

| 类型 | 数量 | 主要分布 |
|------|------|----------|
| Panel（面板） | **35+** | `components/` 根目录 + `ai/` + `entity/` |
| Card（卡片） | 8 | Landing / Entity / Journey |
| Shell | 3 | AppShell / ExplorationShell / CompanionShell |
| Page（独立页面） | 3 | LandingPage / EntityPage / CausalObjectDetailPage |
| Guide | 3 | EntityExplorationGuide / ExplorationFlowGuide / FirstExplorationGuide |
| Navigation | 3 | Breadcrumb / HistoryBar / ExplorationPath |
| Header | 2 | EntityHeader / EntityExperienceHeader |
| Control | 5 | ViewSwitcher / LanguageSwitcher / SearchBox / EntitySearchBox / MultiEntitySelector |

### 3.2 重复模式

- **Panel 模式重复 35+ 次**：每个面板独立实现自己的标题/内容/折叠，没有统一的 Panel 基组件
- **Card 模式有 4 种不同实现**：ResearchDimensionCard / EventNarrativeCard / JourneyCard / ExplorationCard，各有自己的样式
- **Guide 模式有 3 种不同实现**：三个 Guide 组件结构类似但独立实现

### 3.3 冲突

- **3 个 Shell** 各自有不同的 slot 模型（AppShell vs ExplorationShell vs CompanionShell）
- **LandingPage + DiscoverPage 双渲染**：同一个首页由两个独立组件拼接
- **UI 原语**（Badge/Button/Card）在 `components/ui/` 中有定义，但大量组件**不使用它们**，直接用原生 HTML

### 3.4 应该废弃

- 3 个 Guide 组件可以合并为一个
- 35+ Panel 应该共用统一 Panel 基组件
- `AppShell` / `ExplorationShell` / `CompanionShell` 应该合并为一个 Shell

## 四、Experience Fragmentation Report（体验碎片化分析）

### 为什么用户会感觉"进入了不同产品"？

**根因 1：3 种容器**
- Explorer Shell（含左 WorkspacePanel + 右 Companion + 底 TimelineStrip）
- 独立页面（CausalObjectDetailPage — 无任何 Shell）
- 简易 Header 页面（Understanding Workspace — 只有 Header 链接）

用户点三个入口，看到三个完全不同的"容器"。

**根因 2：Landing + Discover 双渲染**
首页由两个独立组件拼成，QuickStart 和主题网格属于不同的渲染逻辑，视觉上像一个页面，逻辑上是两个。

**根因 3：无统一 Mode 切换**
Browse / Timeline / Map / Understanding 没有明确的 Mode 概念。用户不知道"现在是什么模式"。

**根因 4：Panel 堆叠无层次**
主画布 15+ Panel 同时渲染，无折叠/展开/优先级。用户不知道先看什么。

**根因 5：Navigation 无语义**
Breadcrumb 只显示节点名称序列（"罗马 > 凯撒 > 高卢战争"），无 From/Why/Value。用户不知道"为什么从 A 到了 B"。

## 五、总结

| 维度 | 当前状态 |
|------|----------|
| 入口数 | 7 个 |
| 容器类型 | 3 种（互不统一） |
| Panel 数量 | 35+（无基组件） |
| Shell 数量 | 3 个（各自不同） |
| 首页 | 2 组件双渲染 |
| Navigation | 无语义 |
| Mode | 无概念 |

**核心结论**：用户感觉"进入不同产品"，因为前端确实有 3 种完全不同的容器、7 个独立的入口、没有统一的 Shell 和 Mode 模型。这不是 UI 美化问题，是架构层面缺少 Frontend Experience Contract。
