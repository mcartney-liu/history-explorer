# M90.2 — Frontend Experience Contract
### Product Architecture / Single Source of Truth

> 模式：产品架构。重新定义 History Explorer 前端体验体系。不改代码。

---

## 一、Experience Philosophy

### 1.1 用户进入后经历什么

不是"浏览页面"，而是"形成理解"：

```
Discover（发现一个问题）
    ↓
Question（形成具体疑问）
    ↓
Explore（获得证据）
    ↓
Connect（发现关联）
    ↓
Understand（形成理解）
    ↓
New Question（产生更深好奇）
```

### 1.2 最小体验单位

不是 Entity、不是 Page、不是 Card、不是 Panel。

是 **Understanding Transition**（理解跃迁）：

```
Before Belief → Evidence → After Belief
```

所有 UI 组件服务于这个循环。任何不服务于这个循环的 UI 都应废弃。

### 1.3 核心交互原则

- **Click-to-Explore**：每次点击都是探索，不是翻页
- **Time first, Space second**：时间叙事优先于空间展示
- **AI 是解释层，不替用户思考**
- **用户永远知道：现在在哪、为什么看这个、下一步为什么**

## 二、Explorer Shell Contract

### 2.1 唯一容器

**所有功能运行在同一个 Explorer Shell 中。** 不存在独立页面。

```
┌─────────────────────────────────────────────────────────┐
│ Global Navigation                                       │
│ 我在哪里？我正在探索什么？                                │
├─────────────────────────────────────────────────────────┤
│ Question Context                                        │
│ 我为什么开始这个探索？                                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│              Understanding Canvas                       │
│                                                         │
│         用户形成理解的核心区域                             │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ Context Layer                                           │
│ Timeline · Map · Entity · Source · Relationship         │
├─────────────────────────────────────────────────────────┤
│ Exploration Navigation                                  │
│ From: 为什么从这里来？ Why: 为什么现在看到？              │
│ Value: 它增加什么理解？                                   │
└─────────────────────────────────────────────────────────┘
```

### 2.2 Shell 固定区域

| 区域 | 职责 | 始终存在 |
|------|------|---------|
| Global Navigation | 位置 + 主题上下文 | ✅ |
| Question Context | 当前探索问题 | ✅ |
| Understanding Canvas | 主内容区 | ✅ |
| Context Layer | 辅助信息 | 按需 |
| Exploration Navigation | From/Why/Value | ✅ |

## 三、Mode Architecture

### 3.1 四种 Mode

| Mode | 目的 | 触发 |
|------|------|------|
| Exploration Mode | 自由浏览历史对象 | 默认 |
| Understanding Mode | 形成因果理解 | 有 Understanding Projection 的主题 |
| Timeline Mode | 理解时间变化 | 有时间线数据的主题 |
| Map Mode | 理解空间关系 | 有地理数据的主题 |

### 3.2 Mode 规则

- **Mode 不是页面。** Mode 是同一个 Explorer 的不同观察角度。
- 所有 Mode 共享：Shell / Navigation / State / Design Language
- Mode 切换不产生"跳到了另一个产品"的感觉

---

## 四、Navigation Contract

### 4.1 每次跳转必须携带

```
From:  你刚理解了 X
Why:   因为 X 与 Y 存在 Z 关系
Value: 理解 Y 帮你理解更大的 W
```

### 4.2 Breadcrumb 语义化

```
现在：罗马 > 凯撒 > 高卢战争（无语义）
未来：罗马共和国的扩张 → 凯撒的军事改革 → 高卢战争如何改变了罗马（有语义）
```

---

## 五、Understanding Experience Model

### 5.1 M89 Understanding Mode 融合

- **禁止** `#/m89` 独立路由
- Understanding Mode 运行于 Explorer Shell 的 Understanding Canvas 中
- Evidence / Understanding Transition / Understanding Path 是 Shell 的核心能力，不是特殊页面

### 5.2 体验流

```
Question Context（为什么探索这个问题）
    ↓
Current Evidence（当前证据）
    ↓
Understanding Transition（理解发生了什么变化）
    ↓
Understanding Path（走到哪里了）
    ↓
Next Action（下一步为什么）
```

## 六、Design System Rules

### 6.1 Layout

- 最大内容宽度：720px（Understanding Canvas）/ 全宽（Context Layer）
- 间距：4px 基础单位，8px 操作网格
- 信息密度：每个视口 ≤ 3 个主要信息块

### 6.2 Typography

| 用途 | 字体 | 示例 |
|------|------|------|
| 问题 | Serif H2 | "法国大革命为什么发生？" |
| 解释 | Serif Body LG | 因果说明 |
| 证据 | Sans Body | 事实描述 |
| 来源 | Sans Caption | 引用标注 |
| 辅助 | Sans Caption | 元数据 |

### 6.3 Color（基于 Design System V1）

| 用途 | Token |
|------|-------|
| 事实层 | `--verified` #4FA784 |
| 解释层 | `--gold-500` #CBA135 |
| 理解层 | `--text-high` #F2EBDD |
| 背景 | `--bg-base` #16130E |

### 6.4 Component Primitives（替换 35+ 自定义 Panel）

```
ExplorerPrimitive:
  Shell         — 唯一容器
  Canvas        — 主内容区
  EvidenceBlock — 证据展示（替代 Panel）
  ContextCard   — 上下文卡片（替代 Card）
  NavigationCard — 跳转说明（新增）
  InsightBlock  — 理解总结
  TimelineItem  — 时间条目
  EntityReference — 实体引用
  RelationshipLink — 关系链接
  ActionBar     — 行动按钮
```

## 七、Component Governance

### 7.1 页面纪律（四问）

每个新页面/组件必须回答：
1. 属于哪个 Mode？
2. 运行在哪个 Shell？
3. 服务哪个用户理解目标？
4. 如何增强 Question → Evidence → Understanding？

回答不了 = 不该存在。

### 7.2 禁止

- 独立页面（无 Shell 包裹）
- 独立 Header / 独立导航
- 独立视觉体系（不使用 Design System token）
- 自定义 Panel（必须使用 ExplorerPrimitive）

## 九、Future Frontend Development Rules

1. 所有新功能运行于 Explorer Shell
2. 所有新 UI 使用 ExplorerPrimitive 组件
3. 所有新页面遵守四问纪律
4. 所有新样式使用 Design System token
5. 每次跳转携带 From/Why/Value
6. Mode 不是页面——是同一 Shell 的不同视角

---

## 十、验收

完成后，任何新增功能必须回答：

1. 属于哪个 Mode？
2. 运行在哪个 Shell？
3. 服务哪个用户理解目标？
4. 如何增强 Question → Evidence → Understanding？
5. 是否遵守统一 Design System？

**目标**：不是让 History Explorer 看起来统一。而是让用户感觉——"我始终在使用同一个文明探索系统。"
