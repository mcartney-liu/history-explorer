# M89.2.2 — Explorer Storyboard
### Strict Read-Only / Cognitive Storyboard Freeze

> 模式声明：严格只读。冻结法国大革命 15 分钟探索的认知故事板。不讨论 UI、页面、代码。

---

## 一、第一句话

> **"选择一个你真正想理解的问题，我们一起把它拆开。"**

这句话定义了整个产品的气质：不是"查资料"，不是"问 AI"，是"一起理解一个问题"。

---

## 二、认知故事板（6 个时刻）

### T0 — 入口

| 维度 | 内容 |
|------|------|
| 用户看到 | "法国大革命为什么发生？"（一个问题，非主题名） |
| 系统为什么这样安排 | 激发好奇，建立"我是在理解一个问题"的预期，而非"我要搜资料" |
| Runtime 支撑 | `HistoricalKnowledgeProjection.topicName` + `description` |
| 属于哪个 Moment | Moment 1："原来不是让我搜资料" |
| 改变什么认知 | 从"这个产品是什么" → "我要理解这个问题" |
| 删掉会损失什么 | Moment 1 不存在——用户第一秒就迷失 |

---

### T1 — 六维地图

| 维度 | 内容 |
|------|------|
| 用户看到 | 这个问题涉及 6 个角度：财政、政治、社会、思想、军事、外交 |
| 系统为什么这样安排 | 建立理解框架——让用户知道前方有什么，而不是直接丢进第一条内容 |
| Runtime 支撑 | `ExplorationState` { coveredDimensions=[], missingDimensions=[6个], coverageRatio=0 } |
| 属于哪个 Moment | Moment 1 → Moment 2 的过渡 |
| 改变什么认知 | 从"一个问题" → "这个问题可以从多个角度理解" |
| 删掉会损失什么 | Orientation 缺失——用户直接进入内容，不知道自己在理解什么 |

---

### T2 — 第一步

| 维度 | 内容 |
|------|------|
| 用户看到 | "我们先从财政危机开始。因为：法国大革命的根本触发点是国家财政崩溃。" |
| 系统为什么这样安排 | 这是 ExplorationPolicy 的第一个 Decision——open_dimension，选择第一个 missingDimension |
| Runtime 支撑 | `ExplorationAction` { type: 'open_dimension', targetRef: 'entity:fiscal-crisis', reason: '已覆盖0维度，缺少财政维度', narrativeHook: '...' } |
| 属于哪个 Moment | Moment 2："原来我知道下一步为什么" |
| 改变什么认知 | 从"系统让我看这个" → "因为缺这个，所以先看这个" |
| 删掉会损失什么 | Navigation Contract 第一次触发不存在——用户不知道"为什么先看财政" |

---

### T3 — 因果跳转

| 维度 | 内容 |
|------|------|
| 用户看到 | "你刚理解了财政危机。因为财政问题导致国王召开三级会议，所以下一步看三级会议——帮你理解为什么财政问题最终演变成政治危机。" |
| 系统为什么这样安排 | ExplorationPolicy 的 follow_cause——missingConnections 触发，追踪因果链 |
| Runtime 支撑 | `ExplorationAction` { type: 'follow_cause', reason: '...', narrativeHook: '...' } + `RuleTrace` |
| 属于哪个 Moment | Moment 2 → Moment 3 |
| 改变什么认知 | 从"知道了两个事件" → "看懂了它们之间的因果关系" |
| 删掉会损失什么 | Navigation Contract 失效——跳转退化为随机点击 |

---

### T4 — 关联浮现

| 维度 | 内容 |
|------|------|
| 用户看到 | 财政危机 → 三级会议 → 政治冲突 → 革命爆发。你探索了 4 个维度，发现了 3 条因果链。 |
| 系统为什么这样安排 | `coveredDimensions` 达到阈值，`connectionDelta > 0`——是时候让用户看到关联 |
| Runtime 支撑 | `ExplorationState` { coveredDimensions=[财政, 政治, 社会, 思想], coverageRatio=0.67 } + `ExplorationMetrics.connectionDelta` |
| 属于哪个 Moment | Moment 3："原来这些事情有关联" |
| 改变什么认知 | 从"知道了几个孤立事件" → "看懂了它们为什么连在一起" |
| 删掉会损失什么 | Moment 3 不存在——用户只能逐个描述事件 |

---

### T5 — 闭环与新问题

| 维度 | 内容 |
|------|------|
| 用户看到 | "原来法国大革命不是突然发生，而是财政危机、制度矛盾、思想变化共同推动的结果。下一个问题：为什么革命最后产生了拿破仑？" |
| 系统为什么这样安排 | `coverageRatio` 达到阈值，触发 reflect。同时基于理解结构自然引出新问题 |
| Runtime 支撑 | `ExplorationPolicy` 的 reflect + `ExplorationMetrics.understandingGrowthScore` + `ExplorationState.coverageRatio=1.0` |
| 属于哪个 Moment | Moment 4："原来我还想继续" |
| 改变什么认知 | 从"我看完了" → "我还想知道更多" |
| 删掉会损失什么 | Understanding Loop 断裂——探索没有终点，也没有续接 |

---

## 三、故事板验证：四个 Moment 全覆盖

| Moment | 对应时刻 | 验证 |
|--------|---------|------|
| "原来不是让我搜资料" | T0 | 入口是一个问题，不是搜索框 |
| "原来我知道下一步为什么" | T2, T3 | 每次跳转有 reason + narrativeHook |
| "原来这些事情有关联" | T4 | 因果链浮现 + connectionDelta |
| "原来我还想继续" | T5 | 闭环 + 新问题入口 |

---

## 四、页面纪律（四问）

以后每一个新页面必须回答：

1. **属于哪个 Moment？**
2. **消费哪些 Runtime 数据？**
3. **改变用户什么认知？**
4. **删掉它会损失哪个 Moment？**

回答不了 = 不该存在。

---

## 五、数据流总览

```
T0: HistoricalKnowledgeProjection → 入口
T1: ExplorationState (coverage=0) → 六维地图
T2: ExplorationAction (open_dimension) → 第一步
T3: ExplorationAction (follow_cause) + RuleTrace → 因果跳转
T4: ExplorationState (coverage=0.67) + Metrics.connectionDelta → 关联浮现
T5: ExplorationPolicy.reflect + Metrics.understandingGrowthScore → 闭环
```

所有数据来自已有 Runtime。不新增任何后端能力。
