# M89.2.6 — Evidence Contract v2
### Product Unit Freeze / Understanding Change Unit

> 模式：冻结 History Explorer 的最小产品单位。Evidence 不是信息单元，是认知变化单元。

---

## 一、Evidence v2 定义

> **Evidence 是一份推动用户从一个认知状态进入另一个认知状态的证据单元。**

```
Before Understanding
        ↓
    Evidence
        ↓
After Understanding
```

---

## 二、Evidence 结构

```typescript
Evidence {
  id: string

  // ── 它服务的大问题 ──
  explorationQuestion: string       // "法国大革命为什么发生？"

  // ── 当前用户的认知缺口 ──
  understandingGap: string          // 用户缺少什么理解
  beforeUnderstanding: string       // 用户当前可能的理解（不完整/错误）

  // ── 为什么现在给这个 Evidence ──
  navigationReason: string          // 来自 ExplorationAction.reason
  navigationHook: string            // 来自 ExplorationAction.narrativeHook

  // ── 展示给用户的材料 ──
  materials: {
    text: string                    // 核心文字描述
    facts: string[]                 // 关键事实
    references: string[]            // 引用来源
  }

  // ── 用户理解变化 ──
  understandingDelta: {
    before: string                  // 用户之前的理解
    after: string                   // 用户之后的理解
    dimensionAdded: string          // 新覆盖的维度
  }

  // ── 下一步连接 ──
  nextConnections: {
    reason: string                  // 为什么下一步是那个
    targetEvidenceId: string        // 下一个 Evidence 的 ID
  }[]
}
```

---

## 三、Evidence vs Entity vs Card

| 概念 | 是什么 | 为什么不合适 |
|------|--------|-------------|
| Entity | 历史对象（路易十六） | 用户不在看对象，在理解问题 |
| Card | UI 组件 | 形式，非意义 |
| 普通 Evidence | 问题+材料 | 增强版知识卡片，无认知变化 |
| **Evidence v2** | **Before → 材料 → After** | **认知变化单元** |

## 四、Evidence 与 Runtime 的关系

### Evidence ↔ ExplorationAction

```
ExplorationAction {
  type: 'open_dimension' | 'follow_cause' | ...
  targetRef: string          → Evidence.id
  reason: string             → Evidence.navigationReason
  narrativeHook: string      → Evidence.navigationHook
  expectedGrowth.dimension   → Evidence.understandingDelta.dimensionAdded
}
```

**不需要改 Policy。** Policy 仍然输出 `Decision<ExplorationAction>`。Evidence 是 Experience 层的抽象，Entity 是 Knowledge 层的概念。Projection 负责映射。

### Evidence ↔ ExplorationState

```
Before Evidence:
  coveredDimensions = [财政]
  missingDimensions = [政治, 社会, ...]

After Evidence:
  coveredDimensions = [财政, 政治]
  missingDimensions = [社会, 思想, ...]
```

每个 Evidence 对应一次 `coveredDimensions` 的变化。这是 understandingDelta 的 Runtime 验证。

### Evidence ↔ ExplorationMetrics

```
Evidence.understandingDelta.before  → 对应 Metrics.before
Evidence.understandingDelta.after   → 对应 Metrics.after
Evidence 序列的累积                 → depthDelta + dimensionDelta + connectionDelta
```

## 五、法国大革命 Evidence 链（示例）

```
Evidence ① — "财政危机"
  before: "革命 = 人民不满国王"
  after:  "革命首先是旧制度无法解决财政危机"
  dimensionAdded: 财政
  ↓
Evidence ② — "三级会议"
  before: "国王召开会议解决问题"
  after:  "三级会议暴露了制度矛盾——特权阶级 vs 第三等级"
  dimensionAdded: 政治
  ↓
Evidence ③ — "第三等级"
  before: "人民反对国王"
  after:  "97%的人口承担全部税负却没有政治权力"
  dimensionAdded: 社会
  ↓
Evidence ④ — "人权宣言"
  before: "革命是暴力推翻"
  after:  "革命有思想基础——启蒙运动的自由平等理念"
  dimensionAdded: 思想
  ↓
Evidence ⑤ — "革命战争"
  before: "法国国内革命"
  after:  "革命引发欧洲列强干预，战争反过来加速了革命激进化"
  dimensionAdded: 军事
  ↓
Evidence ⑥ — "拿破仑崛起"
  before: "革命结束了"
  after:  "革命产生的新制度为拿破仑的崛起提供了条件"
  dimensionAdded: 外交
```

每个 Evidence 改变用户的一个理解，而非仅仅展示一个事实。

## 六、这对 Workspace 意味着什么

Workspace 不是展示 Evidence 的页面。Workspace 是 **让 Evidence 发生认知转化的空间**。

```
错误（展示 Evidence）：
  标题 + 正文 + 图片 + 下一张卡片

正确（认知转化空间）：
  为什么现在看这个？
      ↓
  你原本可能认为：X
      ↓
  新的证据：Y
      ↓
  现在你可以理解：Z
      ↓
  下一步：W
```
