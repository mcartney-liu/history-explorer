# M89.3.0 — 前端 UX 审计与统一方案
### Frontend Audit / Before Any Further Development

> 模式：审计报告。先摸清现状，再给出统一标准。不改代码。

---

## 一、现状问题总览

### 问题 1：四种完全不同的页面体验

| 入口 | 点击后进入 | 体验风格 |
|------|-----------|----------|
| QuickStart（凯撒/秦始皇/罗马） | `#/explore` → Explorer Shell（左栏+主画布+右栏+底时间轴） | 传统数据展示 |
| 探索包（法国/德国等） | `#/package/xxx` → ExplorationPackagePage | 另一种布局 |
| 因果对象链接 | `#/causal/xxx` → CausalObjectDetailPage | 独立页面，无 Shell |
| 法国大革命（M89） | `#/m89` → Understanding Workspace | 完全独立的新 UI |

**用户困惑**：同一个人点四个入口，看到四个完全不同的界面。

### 问题 2：首页入口混乱

- LandingPage 和 DiscoverPage **同时渲染**
- QuickStart chips 和 Understanding Entry Card 视觉不统一
- 没有统一的"进入探索"的认知模型

### 问题 3：Shell 内面板过多

Explorer Shell 主画布渲染 **15+ 个面板**（SummaryPanel / StorySection / TimelinePanel / GraphView / AIExplanation / EntityPicker / ContinueExploring...），没有层次感。

### 问题 4：NavNode 无语义

`NavNode` 只存 `{ type, id/topic, title/name }`，没有 reason/narrativeHook/relationType。Breadcrumb 只显示节点名称序列。

## 三、统一方案

### 核心原则

> **首页统一入口 → Explorer Shell 统一容器 → 两种 Mode（Browse / Understanding）**

### 3.1 首页统一

```
Home（一个页面，非两个同时渲染）
    ├── Hero + 描述
    ├── QuickStart 快捷问题（3-4 个）          → Browse Mode
    ├── Understanding Entry（1 个，法国大革命）  → Understanding Mode
    └── 最近探索 / 主题网格
```

**删除**：两个 Landing/Discover 同时渲染的问题。

### 3.2 Shell 统一容器

所有探索体验包裹在同一个 Explorer Shell 中：
- 顶部 Header（Logo + 导航）
- 左栏 Workspace（当前探索上下文）
- 主画布（根据 Mode 切换内容）
- 右栏 Companion（可选，默认可见）
- 底部 Timeline（可选）

**不新增独立页面。不绕过 Shell。**

### 3.3 两种 Mode

| Mode | 用途 | 内容 |
|------|------|------|
| Browse Mode | 自由浏览历史内容 | 现有的 topic/entity 探索视图 |
| Understanding Mode | 引导式理解 | M89 Understanding Workspace |

切换：ExplorationRoute 根据当前主题是否有 Understanding Projection 判断进入哪种 Mode。

### 3.4 短期（M89.3 前）最小改动

不改全部。只做三个修正：

1. **首页**：删除 LandingPage/DiscoverPage 双渲染，合并为一个 Home
2. **M89 Workspace**：改为包裹在 Explorer Shell 内（Header + 主画布 = Workspace，不新建独立页面）
3. **NavNode**：增加可选 `reason` / `narrativeHook` 字段

### 3.5 长期（M90+）

- 所有入口统一走 `ExplorationRoute`
- Shell 统一管理 Mode 切换
- 面板分层（一级面板常驻，二级面板按需展开）
