# M86.1.8 — Understanding State Contract
### Strict Read-Only / Semantic Freeze

> 模式声明：严格只读。定义 Understanding State 的语义模型。不写代码、不涉及 AI 判定。基于 M86.1.0~1.7 全链路输入。

---

## 第一部分：定义

> **Understanding State = 系统对"用户当前形成了什么认知结构"的运行时表示。不是 AI 的猜测，而是基于用户已建立的 Anchor 链和 Relation 链的结构化推导。**

不是：AI 总结、行为评分、停留时长函数、点击次数函数、Knowledge Layer 数据副本。

---

## 第二部分：模型

```
UnderstandingState {
  topic: string
  knownFacts: KnownFact[]
  discoveredRelations: DiscoveredRelation[]
  stage: UnderstandingStage
  missingLinks: MissingLink[]
  unresolvedQuestions: string[]
}
```

子类型：
- `KnownFact` = { anchorRef, entityType, firstSeenAt, revisitCount }
- `DiscoveredRelation` = { relationRef, fromFactRef, toFactRef, relationType }
- `MissingLink` = { fromFactRef, toFactRef, missingRelationType, reason }
- `UnderstandingStage` = FACT | CONNECTION | UNDERSTANDING | NEW_QUESTION

---

## 第三部分：Stage 判定规则

- FACT → CONNECTION：discoveredRelations.length >= 1（必须有 Causal Layer 数据）
- CONNECTION → UNDERSTANDING：存在完整因果链（A→B→C）+ 覆盖 understandingGoal 维度
- UNDERSTANDING → NEW_QUESTION：missingLinks.length > 0
- 任何阶段可回退（理解不是线性关卡）

**不可自动推进**：不由跳转次数/时长/点击数触发。

---

## 第四部分：计算约束

- determineStage 不使用 AI——基于锚点链和关系链的结构判定
- computeMissingLinks 不使用 AI——基于 Curator 预写的理解结构模板
- deriveQuestions 不使用 AI——基于 missingLinks 的类型推导
- 所有计算不依赖停留时长、点击次数、页面浏览数

---

## 第五部分：Curator 理解结构模板

```
UnderstandingTemplate {
  topic, goal, requiredDimensions[], expectedRelations[{from, to, type}]
}
```

来源：ExplorationPackage 的 exploration_goals + Curator 预写。不由 AI 生成。

---

## 第六部分：写入权限

Understanding Layer（唯一写入者）→ cognitiveStage + unresolvedGap。Navigation/AI/定时器不可写入。
