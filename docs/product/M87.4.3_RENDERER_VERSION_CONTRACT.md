# M87.4.3 — Renderer Version Contract
### Strict Read-Only / Boundary Freeze

> 模式声明：严格只读。冻结 Renderer 版本管理体系。不写代码。

---

## 一、定位

M87.4.3 不是"Prompt 版本管理"，而是 **Renderer Version Contract**。

原因：
- Prompt 只是 LLM Renderer 的实现细节
- 未来 Renderer 可能包括：LLM / Template / Rule / Voice / AR/VR
- 版本管理应该属于 Renderer Artifact System，而非 Prompt

---

## 二、核心声明

> **Renderer Version 不影响 Replay。Decision 相同 → 认知状态相同，即使不同 Renderer 产生不同 Artifact。**

---

## 三、RendererIdentity

### 3.1 类型定义

```typescript
type RendererType = 'llm' | 'template' | 'rule'

interface RendererIdentity {
  /** 唯一标识 */
  rendererId: string
  /** Renderer 类型 */
  rendererType: RendererType
  /** 版本号 */
  rendererVersion: string
}
```

### 3.2 类型含义

| rendererType | 含义 | 示例 |
|-------------|------|------|
| llm | 调用 LLM 模型生成 | GPT Renderer / Qwen Renderer |
| template | 基于模板渲染 | 固定格式输出（如 NoopRenderer 进化版） |
| rule | 基于规则渲染 | 条件分支 + 模板组合 |

### 3.3 版本号格式

```
{type}-v{major}.{minor}

示例：
  llm-v1.0
  template-v2.1
  rule-v1.0
```

版本号含义：
- major：非兼容变更（输出结构变化）
- minor：兼容变更（风格调整、措辞优化）

## 四、ModelMetadata（仅 LLM Renderer）

```typescript
interface ModelMetadata {
  /** 模型提供方 */
  provider: string
  /** 模型标识 */
  model: string
  /** 模型版本 */
  modelVersion: string
  /** Prompt 版本 */
  promptVersion: string
  /** 温度（可选） */
  temperature?: number
  /** 最大 Token（可选） */
  maxTokens?: number
}
```

注意：
- `ModelMetadata` 只属于 `rendererType = 'llm'` 的 Renderer
- Template / Rule Renderer 不需要此元数据
- `ExplanationArtifact` 中已有 `modelProvider` / `modelVersion` / `promptVersion`，与 `ModelMetadata` 对应

## 五、RendererRegistry

### 5.1 接口

```typescript
interface RendererRegistry {
  register(identity: RendererIdentity, renderer: ExplanationRenderer): void
  get(identity: RendererIdentity): ExplanationRenderer | null
  list(): RendererIdentity[]
  resolve(rendererId: string): ExplanationRenderer | null
}
```

### 5.2 行为

- 同一 `rendererId` + `rendererVersion` 只能注册一次
- 不同版本的同一 Renderer 可共存（如 `llm-v1.0` 和 `llm-v1.1`）
- `resolve(rendererId)` 返回最新版本（按 semver 排序）

## 六、Artifact 可重建关系

### 6.1 重建链

```
Artifact
  ↓ (sourceDecisionId)
Decision
  ↓ (re-compute)
ExplanationContext
  ↓ (rendererId + rendererVersion)
Renderer
  ↓
Artifact' (应与原 Artifact content 一致，如果 Renderer 是确定性的)
```

### 6.2 确定性 Renderer

- `template` 和 `rule` 类型的 Renderer 应该是确定性的
- 同一 Decision + 同一 Renderer 版本 → 同一 Artifact content
- `llm` 类型可能非确定性（temperature > 0），但 sourceDecisionId 不变

### 6.3 非确定性 Renderer 的 Replay

```
Decision-001
  + llm-v1.0 + temperature=0.7
  → Artifact A (content: "The Roman Empire expanded...")

Decision-001
  + llm-v1.0 + temperature=0.7
  → Artifact B (content: "Rome grew through military...")

两个 Artifact 都合法，因为：
  - sourceDecisionId 相同
  - 认知状态相同
  - 表达不同是 LLM 的合理行为
```

---

## 七、Renderer Version ≠ Replay 结果

这是 M87.4.3 最核心的约束：

```
允许：
  Decision-001 + Renderer-v1 → "The Roman Empire expanded..."
  Decision-001 + Renderer-v2 → "Rome grew through military..."

禁止：
  因为 Renderer 版本不同而质疑 Decision 的正确性
```

原因：
- Replay 对象 = Decision（不变）
- Renderer 版本影响的是表达，不是认知
- 两个 Artifact 都合法——sourceDecisionId 相同

## 九、Renderer 升级策略

### 9.1 升级路径

```
M87.4.2: NoopRenderer (rendererType: 'template', version: 'noop-v1')
    ↓
M87.4.3: TemplateRenderer (rendererType: 'template', version: 'template-v1.0')
    ↓
M87.4.3+: LLMRenderer (rendererType: 'llm', version: 'llm-v1.0')
    ↓
未来: VoiceRenderer / ARRenderer / ...
```

### 9.2 升级安全

- 旧 Artifact 保留旧 rendererVersion
- 新 Artifact 使用新 rendererVersion
- 同一 Decision 可被不同版本 Renderer 渲染
- 对比不同版本的输出（A/B 测试）
