## §1 M85 Objective Definition

### 1.1 M85 不是实现 Multi-hop

M85 的定位必须严格澄清：

```
❌ M85 ≠ Multi-hop Engine
❌ M85 ≠ AI Reasoning Pipeline
❌ M85 ≠ 自动探索路径生成
❌ M85 ≠ "为了展示 AI 能力而做 Multi-hop"
```

M85 的真正问题是：

> 当 Explorer 理解一个解释（CausalObject）之后，是否需要跨越多个 Semantic Object 建立更高阶的探索关系？

### 1.2 M82→M84 的方向回顾

```
M82: 事实 → 解释（"系统会解释"）
M83: 解释 → 价值（"解释有价值"）
M84: 解释 → 平台能力（"解释成为平台能力"）

当前状态：
  CausalObject
    ├ mechanism
    ├ consequence
    ├ related_entities
    └ exploration_paths
  ↑ 单对象内部探索（已验证）
```

### 1.3 M85 的假设空间

```
M85 探索的问题：
  CausalObject A
        ↓
      ?（什么关系？）
        ↓
  CausalObject B
```

M85 要验证的不是 "技术能不能做 Multi-hop"，而是：

> Explorer 是否需要在理解一个因果解释后，自然地进入另一个相关的因果解释？

这与 M83 的验证逻辑一致：**先验证行为需要，再决定技术实现。**

### 1.4 M85 不是 "AI Knowledge Graph Engine"

```
History Explorer 的演进方向：

✅ 已建立（M82-M84）：
   事实 → 解释 → 语义对象
   KG（What exists）→ SO（How to understand）→ Explorer（How to explore）

⚠️ M85 的危险方向（必须避免）：
   解释 → 解释之间的关系 → 知识推理
   这可能从 History Explorer 滑向 AI Knowledge Graph Engine
```

**M85 第一原则**：

> 不构建会思考的系统，先验证用户是否需要系统帮助他思考。

## §2 Multi-hop Boundary Definition

### 2.1 什么叫 Multi-hop？

在 History Explorer 语境中，Multi-hop 的精确定义：

```
Multi-hop = Explorer 从一个 CausalObject 的解释出发，
            通过 curator 预定义的关联关系，
            进入另一个 CausalObject 的解释，
            形成理解链。
```

**关键约束**：关联关系是 curator 策展的，不是系统推理的。

### 2.2 Allowed 模型

```
✅ Allowed（M85）：

CausalObject A                CausalObject B
┌──────────────────┐         ┌──────────────────┐
│ 科举制度          │         │ 文官体系          │
│ ↓ 导致            │ ──────→ │ ↓ 导致            │
│ 社会流动性增加     │  related │ 士大夫阶层形成     │
└──────────────────┘         └──────────────────┘

关联方式：curator 在 CausalObject A 中声明
"related_causal_objects: [co-005]"
```

**这本质上是一个静态链接关系，不是图遍历。**

### 2.3 Forbidden 模型

```
❌ Forbidden（M85）：

1. KG Edge Expansion
   CausalObject 之间的关联 ≠ 新的 Graph Edge 类型
   关联关系不写入 KG（Entity/Relationship/Edge 不变）

2. 自动图搜索
   不从 cause_id/effect_id 自动推导 CausalObject 图
   不基于 KG 拓扑自动发现因果链
   不运行 BFS/DFS 来构建 "因果网络"

3. AI 生成因果链
   AI 不生成 CausalObject 之间的关联
   AI 不推断 "A 导致 B，B 导致 C，所以 A 间接导致 C"
   AI 不推荐 "你可能还想了解..."

4. 推荐算法
   不基于用户行为推荐下一个 CausalObject
   不基于相似度/协同过滤推荐
   不基于热度排序
```

### 2.4 与 M83 Decision D5 的关系

```
M83 Decision D5：
  "Multi-hop 暂不进入 M84。当前 CS 都是 1-hop（A→B），
   无链式 CS 数据，无多跳行为证据。"

M85 的 D5 继承：
  - M83 的约束仍然成立：无链式 CS 数据，无多跳行为证据
  - M84 的 CausalObject 没有改变这个事实：co-001/005/008 仍然是单跳
  - M85 进入的前提：必须产生新的证据（见 §6）
```

### 2.5 Multi-hop 边界一句话

```
Multi-hop in M85 = curator 策展的 CausalObject 静态关联
                 ≠ 系统推理的因果图遍历
                 ≠ AI 生成的因果链
                 ≠ KG 层的图扩展
```

## §3 Semantic Layer Architecture

### 3.1 三层架构回顾

```
KG（Fact Layer）           → 回答 "What exists?"
Semantic Object Layer      → 回答 "How to understand it?"
Explorer Interaction Layer → 回答 "How to explore it?"
```

这三层是 M74（Trust Boundary）+ M79（Semantic Freeze）+ M84（Semantic Object）共同建立的架构，M85 不得突破。

### 3.2 Multi-hop 属于哪一层？

**判定：Semantic Object 层。**

| 选项 | 判定 | 理由 |
| --- | --- | --- |
| A. KG 层 | ❌ 不是 | Multi-hop 是解释之间的关系，不是事实之间的关系。KG 只存储 "A 和 B 之间存在关系 R"，不存储 "为什么 A 导致 B 的解释与为什么 B 导致 C 的解释是相关的" |
| B. Semantic Object 层 | ✅ 是 | CausalObject 之间的关联是解释层概念：curator 认为 "理解科举制度如何导致社会流动" 有助于理解 "文官体系如何形成士大夫阶层"。这不是 KG 事实，是策展判断 |
| C. Explorer Interaction 层 | ❌ 不是（至少不完全是） | Explorer 的职责是呈现和导航，不是定义关联关系。关联关系必须在 SO 层定义，Explorer 层只负责呈现 |

### 3.3 架构位置

```
KG（事实层）
  ├── Entity: 科举制度（china_v1:institution-keju）
  ├── Entity: 社会流动（china_v1:phenomenon-social-mobility）
  └── Relationship: caused（科举制度 → 社会流动）
       │
       │ GID reference（单向）
       ▼
Semantic Object Layer（解释层）
  ├── CausalObject co-001: 科举制度 → 社会流动
  │     ├── mechanism: "..."
  │     ├── consequence: "..."
  │     └── related_causal_objects: [co-005]  ← M85 新增
  │
  └── CausalObject co-005: 文官体系 → 士大夫阶层
        ├── mechanism: "..."
        └── consequence: "..."

Explorer Interaction Layer（交互层）
  ├── CausalObjectDetailPage: 展示 co-001
  │     └── "相关解释" section: 链接到 co-005  ← M85 新增 UI
  └── 点击 → 进入 co-005 Detail Page
```

### 3.4 必须保持的边界

```
KG = What exists       ← M85 不触
SO = How to understand ← M85 在 SO 层新增 related_causal_objects
Explorer = How to explore ← M85 新增 "相关解释" 导航 UI
```

**KG 层完全不动。SO 层新增一个字段。Explorer 层新增一个 UI 区块。** 这是最小架构变更。

## §4 CausalObject Relationship Model

### 4.1 核心问题：是否需要 `related_causal_objects`？

```
CausalObject（M84，10 字段）
  ├── id, cause_id, effect_id
  ├── mechanism, consequence
  ├── confidence, evidence_refs
  ├── object_type = "causal"
  ├── related_entities      ← M84：关联的 KG Entity
  └── exploration_paths     ← M84：推荐的 KG 探索路径

CausalObject（M85 如果新增，11 字段）
  └── related_causal_objects ← M85：关联的其他 CausalObject
```

### 4.2 为什么需要？

| 理由 | 说明 |
| --- | --- |
| **M83 验证了"解释 → 探索"的价值** | 4/4 Explorer 在看到 CausalStatement 后深入探索（E2）。M85 是这条路径的自然延伸：从 "单对象内部探索" 升级为 "跨对象探索" |
| **CausalObject 之间确实存在语义关联** | co-001（科举→社会流动）和 co-005（文官→士大夫）是同一历史叙事的不同侧面。curator 有能力识别这种关联 |
| **这是最小的 Multi-hop 实现** | 一个字段 + 一个 UI 区块。不做图遍历，不做 AI 推理，不做推荐算法 |
| **先验证再扩展** | 如果 `related_causal_objects` 的点击率 > 20%，说明 Explorer 确实需要跨对象探索。再决定 M86 是否需要更复杂的 traversal |

### 4.3 为什么可能不需要？

| 理由 | 说明 |
| --- | --- |
| **CausalObject 数量太少** | 当前只有 3 个 CausalObject（co-001/005/008）。`related_causal_objects` 在数据量 < 10 时几乎是无意义的 |
| **没有证据证明 Explorer 需要跨对象探索** | M83 的验证全部在单对象层面。没有一条证据表明 Explorer 需要 "从解释 A 跳转到解释 B" |
| **可能只是 curator 的自我满足** | curator 觉得 co-001 和 co-005 相关，但 Explorer 可能不关心这种关联 |

### 4.4 判定

```
需要 related_causal_objects。

但 M85 的进入条件不是 "字段定义好了"，而是 "验证条件满足了"（见 §6）。
```

### 4.5 如何避免提前建立 Ontology

```
禁止：
  ❌ related_causal_objects 成为 CausalObject 之间的 "语义图"
  ❌ 定义 CausalObjectRelationship 抽象类型
  ❌ 基于 related_causal_objects 构建 CausalGraph 索引
  ❌ 自动推导 transitive closure（A→B, B→C ⇒ A→C）

允许：
  ✅ 一个简单的一对多引用列表：related_causal_objects: [str]
  ✅ curator 手动维护
  ✅ Explorer 层以 "相关解释" 区块呈现（类似 "相关文章"）
```

**一句话：`related_causal_objects` 是一个静态链接列表，不是 Semantic Graph 的边。**

## §5 AI Boundary

### 5.1 默认立场

```
M85 默认：NO AI。

不引入 AI 生成解释。
不引入 AI 推荐路径。
不引入 LLM 推理。
```

### 5.2 为什么 M85 最容易滑向 AI？

```
危险路径（必须阻止）：

  CausalObject A
       ↓
  "AI 推断 A 和 B 的关系"
       ↓
  CausalObject B
       ↓
  "AI 生成一条因果链解释"
       ↓
  "AI 推荐 Explorer 下一步看什么"
```

这条路径会同时违反：
- M82 Freeze C-6（AI 不作为事实来源）
- M83 Decision D6（AI 自动生成 CS REJECT）
- M74 Trust Boundary（解释层与推理层混淆）
- M84 KG Boundary（SO 写入 KG 等效）

### 5.3 M85 的 AI 约束

| 操作 | 允许？ | 理由 |
| --- | --- | --- |
| AI 生成 CausalObject 内容（mechanism/consequence） | ❌ | M83 D6（REJECT） |
| AI 推断 CausalObject 之间的关联 | ❌ | 关联是 curator 的策展判断，不是推理结果 |
| AI 推荐 "下一个 CausalObject" | ❌ | 推荐引擎 → M86+ |
| LLM 用于 UI 文案润色 | 🟡 需 PO 决策 | 不影响数据模型和架构边界，但应明确声明 |
| AI 用于 CausalObject 数据质检（consistency check） | 🟡 需 PO 决策 | 不改变数据内容，只做质量辅助 |

### 5.4 Evidence Gate（如果未来需要 AI）

如果 M86+ 需要引入 AI，必须先通过以下 Evidence Gate：

```
E1: Explorer 主动请求 AI 解释的比例 > X%
E2: curator 策展效率成为瓶颈（人工策展跟不上 Explorer 需求）
E3: 策展内容与 AI 生成内容在 A/B 测试中 Explorer 偏好 AI 内容
E4: AI 生成内容的准确率 > Y%（经 curator 审核）
```

**当前：4 项 Evidence Gate 全部未满足。M85 不引入 AI。**

## §6 Validation Requirement

### 6.1 继承 M83 的验证方法论

M83 建立了 History Explorer 的验证方法论：

```
H0: 无 CausalStatement → Explorer 探索深度不变
H1: 有 CausalStatement → Explorer 探索深度显著提升
H2: Explorer 理解但不一定改变行为

验证结果：H1 成立（4/4 深度提升），H2 成立（理解 ≠ 行为改变）
```

M85 必须遵循相同的验证逻辑：**先证明需要，再决定实现。**

### 6.2 M85 验证问题

```
H0（Null Hypothesis）:
  单 CausalObject 已满足 Explorer 的探索需求。
  Explorer 不需要从一个 CausalObject 跳转到另一个 CausalObject。

H1（Alternative Hypothesis）:
  跨 CausalObject 能显著提高 Explorer 的探索深度和理解广度。
  Explorer 在 "相关解释" 的引导下进入更长的探索链。
```

### 6.3 M85 进入前必须收集的证据

| # | 证据 | 当前状态 | 来源 |
| --- | --- | --- | --- |
| E1 | CausalObject 数量 ≥ 10 个 | ⬜ 未满足（当前 3 个） | M84 数据扩展 |
| E2 | CausalObject Open Rate > 30% | ⬜ 未验证（M84 验证未执行） | M84 Explorer Validation |
| E3 | 至少 2 个 CausalObject 存在 curator 认可的语义关联 | ⬜ 未满足（3 个 CO 可能不构成关联对） | curator 审查 |
| E4 | Explorer 在单 CausalObject 内表达了 "还想了解更多相关解释" 的意图 | ⬜ 未验证 | M84 Explorer Validation（定性） |

### 6.4 验证设计（M85 Pre-condition）

```
M85 Entry Condition = E1 ∧ E2 ∧ E3 ∧ E4

E1: CausalObject ≥ 10（数据基础）
E2: Open Rate > 30%（Explorer 接受 CausalObject）
E3: ≥ 2 关联对（存在跨对象探索的前提）
E4: Explorer 表达跨对象需求（行为信号）

当前状态：0/4 满足。
```

### 6.5 如果条件不满足

```
如果 M85 Entry Condition 不满足：

→ M85 不进入 Implementation。
→ 优先完成 M84 数据扩展 + Explorer Validation。
→ 重新评估 M85 是否应该是 "CausalObject 数据扩展" 而非 "Reasoning/Multi-hop"。
```

## §8 Architecture Decision

### 8.1 判定

```
HOLD
```

### 8.2 为什么不是 READY？

M85 的方向是正确的——"从单对象内部探索升级为跨对象探索" 是 M82→M84 路径的自然延伸。但进入条件不满足：

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| M84 数据基础 | ⬜ CausalObject 仅 3 个 | 3 个 CO 不足以支撑 `related_causal_objects` 的最小验证 |
| M84 Explorer Validation | ⬜ 未执行 | M84 Retrospective 明确记录 "M84 用户验证未执行" |
| 跨对象探索的行为证据 | ⬜ 无 | M83 的 4 场 Session 全部在单对象层面 |
| curator 识别的语义关联 | ⬜ 未审查 | 3 个 CO 之间是否存在有意义的关联尚未评估 |

### 8.3 为什么不是 REJECT？

```
M85 的方向不是错的。

M83 验证了 "解释有价值"。
M84 验证了 "解释可以成为平台能力"。
M85 验证 "多个解释之间的关系是否有价值" 是逻辑上合理的下一步。

但当前的数据基础和验证基础不足以支撑 M85 进入 Implementation。
```

### 8.4 M85 进入路径

```
Step 1: 完成 M84 未完成的工作
  ├── CausalObject 数据扩展到 10+ 个（M84 Scope Freeze 目标：3-5 个 + CS 20+ 条）
  ├── 执行 M84 Explorer Validation（M84 Retrospective §5 记录为未执行）
  └── curator 审查：现有 CausalObject 之间是否存在有意义的语义关联

Step 2: 收集 M85 Entry Evidence（§6.3）
  ├── E1: CausalObject ≥ 10 ✅
  ├── E2: Open Rate > 30% ✅
  ├── E3: ≥ 2 关联对 ✅
  └── E4: Explorer 表达跨对象需求 ✅

Step 3: 重新进入 M85 Architecture Gate
  └── 如果 4/4 Evidence 满足 → READY
  └── 如果 2-3/4 Evidence 满足 → HOLD（继续收集）
  └── 如果 0-1/4 Evidence 满足 → 重新审视 M85 方向
```

### 8.5 关键风险重申

```
M85 是第一次可能挑战 History Explorer 核心边界的 Milestone。

M82-M84 的方向一直是：
  事实 → 解释 → 语义对象

M85 开始触碰：
  解释 → 解释之间的关系 → 知识推理

这里很容易从 History Explorer 滑向 AI Knowledge Graph Engine。

M85 的第一原则应该保持：
  不构建会思考的系统，先验证用户是否需要系统帮助他思考。
```

### 8.6 一句话判定

```
M85 的方向正确，但进入条件不满足。
优先完成 M84 的数据扩展和用户验证，再重新评估 M85 的 Entry Gate。
```
