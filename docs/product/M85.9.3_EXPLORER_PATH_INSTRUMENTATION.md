# M85.9.3 Explorer Path Instrumentation Design

> **阶段**：M85.9.3 — 记录探索路径，不展示，不推荐
> **类型**：Instrumentation Design（轻量，非 Architecture Gate）
> **日期**：2026-08-06
> **基线**：M85.9.2 入口升级 + M85.8.4.2 Experience Contract
> **目标**：为 M86 Pattern 验证积累真实探索路径数据

---

## 0. 核心原则

```
Explorer Path 记录 ≠ 用户行为追踪

记录的是：
  "人类理解文明时，通常经过哪些认知路径"

不是：
  "用户喜欢什么，我们应该推荐什么"

数据用途：
  ✅ M86 Pattern 验证 — 不同用户的路径是否汇聚成模式
  ❌ 推荐引擎 — 不基于路径数据预测用户下一步
```

---

## 1. 记录什么

### ExplorerSessionPath

```typescript
interface ExplorerSessionPath {
  sessionId: string          // 唯一会话标识
  seedId: string             // 入口 Seed ID（institutional_evolution / civilization_contrast / technological_chain）
  visitedObjects: string[]   // 按时间顺序访问的 CausalObject ID 列表（如 ["co-004", "co-001", "co-010"]）
  depth: number              // 最大探索深度（visitedObjects 长度）
  generatedQuestion?: string // 用户是否产生了新问题（O3）
  timestamp: number          // 会话开始时间
}
```

### 记录时机

```
每次 onCausalObjectClick 时追加 visitedObjects。
会话结束时（用户返回 Discover / 关闭页面）写入 localStorage。
```

### 不记录

```
❌ 用户身份 / 画像
❌ 停留时长
❌ 点击次数
❌ 页面滚动位置
❌ 用户评分 / 反馈
❌ 浏览器指纹
❌ IP / 地理位置
```

---

## 2. 存储方式

```
localStorage only。
key: "explorer_paths"
value: JSON.stringify(ExplorerSessionPath[])

容量：最多保留 50 条最近会话（FIFO）。
```

### 为什么不发送到后端？

```
1. 当前是观察阶段，不需要实时分析
2. 避免过度工程化 — 不建 analytics pipeline
3. 保持 M85 的"不收集用户数据"原则
4. localStorage 足以支撑 M86 Pattern 验证的样本量
```

## 4. 如何防止滑向推荐系统

### 红线

```
C1: ExplorerPath 数据不进入任何推荐/排序/ranking 逻辑
C2: 不基于 visitedObjects 计算用户偏好
C3: 不基于路径数据预加载/预渲染下一个 CausalObject
C4: ExplorerPath 数据仅用于 M86 Pattern 验证
```

### 代码约束

```typescript
// ❌ 禁止
function suggestNext(visited: string[]): string[] { ... }
function rankByPopularity(paths: ExplorerSessionPath[]): string[] { ... }
function predictUserInterest(paths: ExplorerSessionPath[]): string[] { ... }

// ✅ 允许
function analyzePatterns(paths: ExplorerSessionPath[]): PathPattern[] { ... }
// 仅用于 M86 研究，不进入 runtime
```
