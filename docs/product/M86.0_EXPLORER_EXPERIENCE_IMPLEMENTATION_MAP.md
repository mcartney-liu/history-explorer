# M86.0 — Explorer Experience Implementation Map
### Strict Read-Only / Implementation Planning（非开发）

> 模式声明：严格只读实现规划。不写代码、不创建组件、不拆开发任务。基于 M85.11.1 ~ M85.16 全链路输入。目标：将 EC 映射到现有架构，识别冲突与复用点，冻结 M86 实施边界。M86 不是 Implementation Phase，而是 Explorer Experience Realization。

---

## 第一条原则（冻结）

> **M86 不重建 History Explorer 的能力，而重建用户穿越能力的方式。**

现有引擎（Entity / CausalObject / AI / Workspace / Timeline / KG）保持不变。M86 的任务是在引擎之上建立 Experience Flow Layer。

## 补充冻结原则（Founder 2026-08-06）

> **Experience Layer 不拥有历史知识，只拥有用户理解过程。**

三层职责边界：

| 层 | 回答 | 职责 |
|---|---|---|
| Knowledge | 发生了什么 | 事实与数据 |
| Causal | 为什么相关 | 关系与解释 |
| Experience | 为什么现在理解它 | 时机、顺序、闭环 |

Experience Layer 不应调用 AI 临时生成解释——解释应来自 Causal Layer 的已有数据。Experience Layer 只决定"什么时候告诉用户"和"如何形成理解"。

## Part 1：EC → Experience Layer Mapping

| EC | 需要的 Experience Layer | 核心职责 |
|---|---|---|
| EC-001 Curiosity Entry | **Curiosity Entry Layer** | 用户从好奇进入，而非从技术代号进入 |
| EC-002 Orientation | **Orientation Layer** | 选定方向后获得定位承诺 |
| EC-003 Navigation Contract | **Navigation Context Layer** | 每次跳转携带 From / Why / Value |
| EC-004 Understanding Completion | **Understanding Layer** | 理解闭环信号 + 因果复述确认 |
| EC-005 AI Companion Discovery | **Companion Visibility Layer** | AI 主动可见 + 获知探索上下文 |
| EC-006 Understanding Seeds Discovery | **Seeds Visibility Layer** | 理解种子主动可见 + 上下文关联 |
| EC-007 Workspace Discovery | **Workspace Context Layer** | 工作台从全局堆积转为上下文轨迹 |
| EC-008 New Question Generation | **Question Transition Layer** | 理解孵化新问题 + 递回用户自主选择 |

## Part 2：Experience Layer → Current Architecture Mapping

### Layer 1：Curiosity Entry Layer
- **当前载体**：`App.tsx` Landing → `ExplorePage` Discover 视图
- **当前问题**：卡片标题为 `m77-package-01` 等技术代号 + `Coverage`/`Depth` 内部指标
- **已有可复用数据**：`ExplorationPackage` 已有 `title`(LocalizedText)、`summary`、`exploration_goals`、`seed_topic`——当前未展示
- **M86 需要做的**：展示层替换——用 `title.zh` / `summary.zh` / `exploration_goals` 替换技术代号和内部指标。**数据层零改动**
- **冲突等级**：**Reuse**

### Layer 2：Orientation Layer
- **当前载体**：无
- **当前问题**：选择 Package 后直接进入实体列表，无定位
- **已有可复用数据**：Package 的 `exploration_goals`（Curator 预写）和 `seed_topic`
- **M86 需要做的**：在 Package → Entity List 之间插入 Orientation 展示
- **冲突等级**：**Adapt**

### Layer 3：Navigation Context Layer
- **当前载体**：`window.location.hash` 路由 + `ExplorationPath` 记录
- **当前问题**：路由仅表达"打开哪个实体"，不表达"为什么"
- **已有可复用数据**：`ExplorerPath` 路径记录；Entity 间关系数据（`RelatedEntity` 带 `relation_type`）
- **M86 需要做的**：建立 `ExploreContext`（From / Why / Value），在跳转时携带并展示
- **冲突等级**：**Adapt**

### Layer 4：Understanding Layer
- **当前载体**：无
- **当前问题**：无任何理解闭环信号
- **已有可复用数据**：`ExplorationPath` 路径记录；Package 的 `exploration_goals`
- **M86 需要做的**：用户走完一条逻辑链（至少 2 个 Connected 节点）后展示理解闭环
- **冲突等级**：**Adapt**

### Layer 5：Companion Visibility Layer
- **当前载体**：`CompanionShell` 组件，右侧小图标打开抽屉
- **当前问题**：默认收起；AI 不知道用户探索上下文
- **已有可复用数据**：`CompanionShell` 已有 `workspaceContext` 参数
- **M86 需要做的**：默认可见 + 传入 `ExploreContext`
- **冲突等级**：**Reuse**

### Layer 6：Seeds Visibility Layer
- **当前载体**：`CompanionShell` 内嵌脚注
- **当前问题**：需打开 AI 抽屉 → 滚动到底部才能发现
- **已有可复用数据**：Understanding Seeds 数据已存在（Curator 预写）
- **M86 需要做的**：从 AI 面板脚注提升为独立可见区块
- **冲突等级**：**Adapt**

### Layer 7：Workspace Context Layer
- **当前载体**：`WorkspacePanel` 组件，左侧小图标打开抽屉
- **当前问题**：默认收起；展示全局堆积而非上下文轨迹
- **已有可复用数据**：`ExplorationPath` 路径记录
- **M86 需要做的**：默认可见 + 展示从"全局堆积"转为"当前探索线认知轨迹"
- **冲突等级**：**Adapt**

### Layer 8：Question Transition Layer
- **当前载体**：无
- **当前问题**：理解后无续接机制
- **已有可复用数据**：Curator 种子数据（可作新问题来源）
- **M86 需要做的**：理解闭环后基于走通的理解链 + Curator 种子，显形自然引出的新问题。**红线**：不推荐、不算法决定
- **冲突等级**：**Adapt**

|---|---|---|
| Orientation | Package goals/seed_topic | Orientation 展示节点 |
| Navigation Context | ExplorerPath + Entity 关系 | ExploreContext 状态 + 语义展示 |

### Replace
**无。** M86 不替换任何现有能力。

## Part 4：M86 实施边界冻结

### 进入 M86 的内容
1. 8 个 Experience Layer 全部实现（Reuse 3 个 + Adapt 5 个）
2. ExploreContext 状态管理（From / Why / Value 三元 + 当前理解线）
3. Understanding Loop 端到端连通
4. 默认可见性调整（Companion / Seeds / Workspace）

### 禁止进入 M86 的内容
- 新 AI Agent 或推荐算法
- 新数据源或后端 API
- Timeline / Map / Video / Mobile 等新载体
- 路由体系重构
- 组件库替换或大规模 UI 框架变更
- 任何非 EC 相关的"顺便优化"

### 可延后到 M87+ 的内容
- Timeline 作为理解流辅助视图
- Map 作为空间维度理解载体
- Mobile 适配
- 搜索框引导优化
- 多语言支持

## 附：M86 进入开发前补充冻结（Founder 2026-08-06）

### Freeze 1 — Experience Flow Overlay（实施策略冻结）

M86 采用 `Experience Flow First + Overlay Existing Architecture`。不是重构，不是 Big Rewrite。

### Freeze 2 — Explorer Runtime Context（核心基础设施冻结）

Navigation Context Layer 中的 `ExploreContext` 升级为 **Explorer Runtime Context**——不只是 Batch 1 的一个状态变量，而是整个 M86 的运行时上下文。所有后续 Layer（Orientation / Companion / Seeds / Workspace / Understanding / Question Transition）全部依赖它。

Explorer Runtime Context 最小结构：

```
ExplorerContext {
  journey_id            // 当前探索会话
  current_question      // 用户正在理解的问题
  understanding_goal    // 这条线的理解目标
  current_node          // 当前所在节点
  previous_node         // 上一个节点
  relation_reason       // 为什么从上一个到当前
  cognitive_stage       // 当前认知阶段（Curiosity/Orientation/Discovery/Connection/Understanding/NewQuestion）
  unresolved_questions  // 尚未闭合的理解缺口
}
```

注意：这不是后端 API，不是数据库，是体验运行时上下文。

### Freeze 3 — New Question = Understanding Gap（问题定义冻结）

New Question ≠ Recommendation。Question Transition Layer 的流程修正为：

```
Understanding Completed
        ↓
Identify Missing Dimension（识别当前理解结构中的缺口）
        ↓
Generate Next Question（基于缺口生成问题，非算法推荐）
```

问题来自"当前理解结构 - 尚未解释的缺口"，而不是算法偏好或内容推荐。

## Experience Architecture Principles（M86 开发防退化原则）

### EP-001
Experience Layer 不创造知识，只组织理解。

### EP-002
任何跳转必须携带 From / Why / Value。

### EP-003
任何推荐必须来自理解缺口，而不是算法偏好。

### EP-004
任何完成状态必须证明用户理解，而不是用户浏览。

### EP-005
所有核心能力必须围绕 Understanding Loop，而不是页面结构。

## 关键概念修正

### Workspace = Understanding Memory

Workspace 保存的不是"我看过什么"（历史记录），而是"我理解过什么"（理解记忆）。

区别：

历史记录：`A 页面 → B 页面 → C 页面`

理解记忆：`我已经理解：A 导致 B，B 影响 C。当前还可以继续理解：D`

### Navigation Context Layer = M86 真正核心

入口和定位只解决"我为什么开始"。Navigation Context 解决"我为什么继续"——这是 History Explorer 与 Wikipedia 的根本差异。所有后续载体（Entity / CausalObject / Timeline / Map / AI）全部依赖它。因此 M86.1 的第一步不是改 Curiosity Entry，而是建立 Explorer Runtime Context 的实现边界——**让系统第一次知道"用户正在理解什么"。**

### M86.1 实施顺序修正

表面上是入口改造（EC-001 Curiosity Entry + EC-002 Orientation），但第一根骨头是 **Explorer Runtime Context 的建立**。没有它，Orientation 是孤岛，Navigation Contract 是假象，Understanding Loop 无法成立。
