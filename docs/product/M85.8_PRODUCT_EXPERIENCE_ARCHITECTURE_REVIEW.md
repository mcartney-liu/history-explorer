## 2. 当前 CausalObjectDetailPage 的问题

### 2.1 未被任何路由消费

```
App.tsx 中：
  - topic 页：不渲染 CausalObjectDetailPage
  - entity 页：不渲染 CausalObjectDetailPage
  - package 页：不渲染 CausalObjectDetailPage
  - discover 页：不渲染 CausalObjectDetailPage

CausalObjectDetailPage 有 onCausalObjectClick prop 但无调用方传入。
```

### 2.2 页面信息架构问题

```
当前结构：
  Header（back + LayerBadge）
  Mechanism（为什么发生）
  Consequence（产生了什么影响）
  Confidence（学术界共识）
  理解关联（M85）
  Related Entities（GID 列表，原始字符串）
  Exploration Paths（KG 路径）

问题：
  1. 页面是一块平铺的 section 列表，没有叙事节奏
  2. related_entities 显示的是 GID 而非人类可读名称
  3. exploration_paths 和 related_causal_objects 的视觉层级相同，但含义不同
  4. 没有"继续探索"的明确行动召唤
```

### 2.3 用户当前看到的是什么

## 3. M85.8 目标体验设计

### 3.1 设计原则

```
P1: CausalObject 不是百科条目，是理解入口
    → 页面回答的不是"这是什么"，而是"为什么这值得探索"

P2: 叙事节奏 > 信息密度
    → mechanism → consequence → understanding → explore（四步叙事弧）

P3: Understanding Layer 在视觉上有独立身份
    → "理解关联"区块不是 section 列表中的一项，而是页面的第二幕

P4: 探索流转是自然的，不是推荐引擎
    → "继续探索"不是"你可能还想了解"，而是"基于你的理解，下一步可以..."
```

#### 关键视觉决策

| 区域 | 视觉处理 | 理由 |
| --- | --- | --- |
| 第一幕（理解） | 白色/金色文字，宽松间距，大段阅读 | 这是"阅读+思考"区域，不是"浏览"区域 |
| 第二幕（关联） | 独立视觉区块，每个关系一张卡片，relation_type 彩色标签 | 这是 M85 的核心价值区，需要有独立身份 |
| 第三幕（探索） | 轻量卡片+箭头，行动召唤 | 这是"下一步"区域，不是推荐列表 |
| 分隔线 | 金色细线（--gold-line） | 三幕之间的叙事分隔 |
