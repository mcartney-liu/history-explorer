## B. Loader Design

### 架构

```
data/causal_statements.json
  ↓ CausalLoader._read_json()    → JSON 解析 + 格式校验
  ↓ CausalLoader._parse_all()    → 构造 CausalStatement 实例（仅提取 7 字段）
  ↓ CausalLoader._build_index()  → 构建 by_cause / by_effect 索引
  ↓ CausalIndex                   → 不可变查询结构
```

### 关键设计决策

| 决策 | 说明 |
| --- | --- |
| **未知字段忽略** | `_parse_all` 只提取 7 个冻结字段，JSON 中的额外 key 静默忽略。M84+ 新增字段（status/replaces/proposed_by）不会破坏加载 |
| **无 **kwargs 解包** | 使用显式 `CausalStatement(cause_id=obj["cause_id"], ...)` 构造，未来字段不会因解包而触发 TypeError |
| **by_cause / by_effect 双索引** | O(1) 查询，为 P1.3 Adapter 的 `get_for_entity()` 提供直接支持 |
| **无业务逻辑** | Loader 不校验因果合理性、不检查 GID 存在性（那是 Adapter 的职责）、不调用 AI |
