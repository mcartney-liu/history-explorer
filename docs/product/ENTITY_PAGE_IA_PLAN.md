# 实体页认知层级重构方案（Entity Page IA Plan v2）

> 版本：v2（2026-08-16，吸收 PO 架构评审后修订；v1 结论"方向正确"升级为**有条件通过**）
> 触发：PO 实机反馈「用户点进去，信息很杂乱」——不同认知职责的信息被同权平铺。
> 定位：**不是"实体页减负方案"，而是"实体页认知层级重构方案"**——给 Phase D 提前建立正确的"认知界面骨架"。
> 核心原则（PO 定稿）：**不是减少信息，而是让系统替用户决定「现在该看什么、接下来该做什么、什么需要主动调用」。**
> 红线：不动 backend / 不引新依赖 / 不改探索决策逻辑（Phase B/C 引擎原样）；只动呈现层（EntityPage / EntityPageShell / ConnectionCard / 相关子组件 / 样式 / 文案词典）。

---

## 0. 认知漏斗（本次重构的不可破坏产品结构）

用户进入实体页，认知路径必须连续可走通：

```
我在哪里？        ← 站间衔接卡
      ↓
它是什么？        ← 实体标题 + 一句话摘要
      ↓
为什么重要？      ← 历史叙事 / 为什么重要 / 这意味着什么（连续理解段落）
      ↓
它和什么有关？    ← 关系洞察 → 关系探索（图/时间/地图）
      ↓
下一步最值得探索什么？ ← 下一站探索（Phase C 决策）
      ↓
如果我想深入：    ← AI / Evidence / More（按需调用）
```

**Phase B → C → D 对应关系（不可破坏）**：
`B：建立关系 → C：基于关系做下一步决策 → D：形成认知闭环`——实体页就是这三者的界面落点。

---

## 1. 现状盘点（v1 实测，保留）

实体页 info tab 默认可见 11 块：入口桥 / ConnectionCard / 探索此实体 / EntityHero / 探索引导 / 故事+历史意义 / 它意味着什么 / 关系洞察 / 关系探索（三视图）/ AI 对话 / 证据溯源 + footer 下一站探索 / 继续探索。

三个关键事实：① tabs 存在但 info tab 装 9 块=满汉全席；② M60-001 把 AI 对话并入 info tab；③ 入口桥 + ConnectionCard 叙述重复（PO 截图实锤）。

## 2. 三层模型 v2（PO 修订版）

| 层 | 职能 | 包含 | 呈现 |
|---|---|---|---|
| **L1 认知主体** | 我在哪 / 它是什么 / 为什么重要 / 这意味着什么 | 站间衔接卡、EntityHero、**主体叙事区**（历史叙事+历史意义+理解叙事） | 第一屏，**≤3 个主要视觉焦点** |
| **L1→L2 桥** | 系统提示"现在最值得理解什么" | **轻量探索提示**（替代原 ExplorationGuide 大块） | 一句行动提示，非常轻 |
| **L2 认知扩展** | 它和什么有关 / 下一步探索什么 | 关系洞察 → 关系探索（三视图）→ **下一站探索（C 决策）** | 按认知顺序呈现（理解扩展 → 行动决策） |
| **L3 按需能力** | 主动调用才出现 | AI 历史学家（独立 tab）、证据与溯源（直接可见折叠）、更多（继续探索） | **可达，但不抢主线** |

**关键修订（相对 v1）：**
- **ExplorationGuide 不是工具**——它是"系统告诉用户现在应该往哪里理解"的**认知导航**，应成为 **L1 → L2 的桥**，不是简单折叠/吞并。
- **InterpretationPanel 补定位**——它属于 L1 主体层（"它意味着什么"是实体理解的一部分），与 Story/WhyImportant 连成**连续的理解段落**，不是三个独立大卡片堆叠。
- **L2 内部排序**：关系洞察 → 关系探索 → 下一站探索（认知过程：理解了它 → 它跟什么有关 → 下一步看什么）。

## 3. 收敛动作 A1–A6（PO 修订版）

### A1 站间衔接合一 —— 信息去重，不是功能删除 ✅ 通过
- 现状：入口桥 + ConnectionCard 回答同一问题（"你为什么从上一站来到这里"），内容重复。
- 动作：合并为一张**站间衔接卡**，它是 Phase B 的**认知上下文接口**：

```
ConnectionCard
├── 第 X / N 站
├── 从哪里来
├── 为什么来到这里（有证据走关系叙述 / 无证据走诚实陈述）
└── 极简 Journey Trail（secondary nav：① → ② → ③）
```

### A2 AI 收进独立 tab —— 按需唤起，不常驻平铺 ✅ 通过
- 现状：HistorianChat 在 info tab 平铺（M60-001 合并）。"容易被看见 ≠ 应该在主体阅读流中常驻"。
- 动作：AI 对话移出主体流，收进独立 tab。**命名建议用「AI / 问史」而非「扩展」**（用户应理解"这里可以问历史学家"）。
- **tab 体系选型（D7）**，结合 tabs 实际职责：
  - 方案甲（推荐）：**概览 / 研究 / AI** —— research tab 已装研究类面板，AI 独立；
  - 方案乙：**概览 / 关系 / AI** —— 关系优先（关系是 History Explorer 的核心差异）。
- 注：tab 标签本就运营可编辑（`entity_tabs.nav_labels` slot），命名调整成本低。

### A3 证据与溯源折叠 —— 低干扰、高可达 ✅ 通过（90%）
- 动作：证据保持直接可见的 `[证据与溯源 ▾]` 折叠行，**不塞进"更多"**（信任层是未来可信度基础设施，要"低干扰、高可达"，不能"低优先级、低可发现"）。
- 原则：**Evidence = 低干扰、高可达；不是低优先级、低可发现。**

### A4 ExplorationGuide → 轻量认知提示（PO 重点修订）🟡→✅
- 原方案"折叠/并入"危险：ExplorationGuide 回答"你现在最值得看什么"，与 ConnectionExplorer 的"它和谁有关"是不同问题。
- **新动作**：有强推荐时显示**一行轻量行动提示**：

```
接下来可以了解：安史之乱
想理解这个实体，可以先看看：……
```

位置：EntityHero / 主体叙事区之后、关系探索之前（L1→L2 桥）。无强推荐时自然不渲染。
- 保留"主动引导"，但把大块变成轻提示——既减负又不丢 History Explorer 的"主动引导"DNA。

### A5 下一站探索 vs 继续探索 —— 职责分明 ✅ 非常正确
- **下一站探索（L2 主位）**= 系统基于当前探索上下文的**下一步认知决策**（Phase C）。
- **继续探索（L3 更多）**= 还有哪些相关内容可看（内容推荐）。
- 用户不再面对"A/B/C/D 全是推荐"的困惑——系统明确"哪个是最值得看的"。

### A6 JourneyTrail 收敛 —— 信息收敛，不是组件收容 ✅ 通过（防超级卡片）
- 方向对，但**关键约束**：ConnectionCard 只承担「第 X/N 站 + 从哪里来 + 为什么到这里」；
- JourneyTrail 做成**极简 secondary nav**（`① → ② → ③`），嵌入但不展开全部信息——**绝不让 ConnectionCard 变成超级卡片**。

## 4. 重组后实体页结构（PO 定稿版）

```
ENTITY PAGE
│
├── L1 认知主体
│   ├── Connection Card（第 X/N 站 · 从哪里来 · 为什么到这里 · 极简行程）
│   ├── Entity Hero（名称 · 一句话摘要）
│   └── 主体叙事区（历史叙事 → 为什么重要 → 这意味着什么，连续成段）
│
├── L1 → L2 桥
│   └── 轻量探索提示（"接下来可以了解：……"）
│
├── L2 认知扩展
│   ├── Relationship Insight
│   ├── Connection Explorer（Graph · Timeline · Map）
│   └── Next Exploration（Phase C 决策）
│
└── L3 按需能力
    ├── AI Historian（独立 tab）
    ├── Evidence & Provenance（直接可见折叠）
    └── More（Continue Exploring）
```

## 5. 验收标准 v2（PO 修订：视觉焦点为主，块数为辅）

**主指标（用户概念）：**
1. **认知顺序**：用户能否顺着「我在哪 → 它是什么 → 为什么重要 → 它和什么有关 → 下一步去哪」走通；
2. **视觉权重**：第一屏只有 **≤3 个主要视觉焦点**（站间上下文 / 实体 / 核心意义）；
3. **按需能力**：AI / Evidence / More **可达但不抢主线**（打开即用）；
4. **重复消除**：入口桥与 ConnectionCard 彻底无重复。

**辅助指标（工程概念，不作为核心）：**
- 可见块 11 → ≤6；第一屏组件 ≤4。

**防过度折叠（PO 提醒）：** 目标不是"把所有东西藏起来"（那会从信息过载变成操作过载），而是**系统替用户判断什么现在值得看、什么现在不值得看**。

## 7. 施工边界与风险

- 施工只动：`EntityPage.tsx` / `EntityPageShell.tsx` / `ConnectionCard.tsx` / `EntityExperienceHeader.tsx`（含 EntityHero/ExplorationGuide 调用）/ `InterpretationPanel` 相关包装 / 样式 / 文案词典（`entity.*`）。
- 不碰：backend / `next/exploration/*`（Phase C 引擎）/ `data/continuityEngine*` / 决策逻辑。
- 施工顺序建议：A1（去重，影响面最清晰）→ A6（行程收敛）→ A4（探索提示）→ A3（证据折叠）→ A2 + D7（tab 体系）→ A5 + InterpretationPanel 叙事区（最后，涉及组件编排）。
- 验证：无头浏览器实测第一屏视觉焦点数 + 认知顺序走通 + 全部能力可达（tab/折叠打开）+ 重复消除；tsc / 相关组件测试 / freeze-check / 隧道重建。
