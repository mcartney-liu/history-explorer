# 实体页信息架构方案（Entity Page IA Plan）

> 版本：v1（2026-08-16 初稿，待 PO 拍板）
> 触发：PO 实机反馈「用户点进去，信息很杂乱」——实体页 13+ 信息块同权平铺。
> 定位：Phase D 认知闭环的前置界面层工作；也是 Article 0「帮助用户形成认知结构」的界面落地。
> 原则：**不删功能，只重组呈现**。所有既有能力（关系/时间/地图/AI/证据/探索）都保留，只调整层级、顺序与收敛方式。
> 红线：不动 backend / 不引新依赖 / 不改探索决策逻辑（Phase B/C 引擎原样）。

---

## 1. 现状盘点（2026-08-16 无头浏览器实测 + 代码核实）

实体页（info tab 默认）从上到下**真实可见 11 个信息块**：

| # | 信息块 | 组件 | 位置 | 回答什么 |
|---|---|---|---|---|
| 1 | 入口桥（顶部蓝框） | EntityPage originBridge | tab 外 | 我从哪来 |
| 2 | ConnectionCard（来自探索包/第 X/N 站/查看行程/过渡叙述/上一站下一站） | ConnectionCard | tab 外 | 我在哪条线上 / 上一站什么关系 |
| 3 | 探索此实体 / 探索 唐朝 | SummaryPanel / EntityExplorationGuide | tab 外 | 该怎么看它 |
| 4 | 实体标题 + 摘要 | EntityHero | info tab | 这个实体是什么 |
| 5 | 探索引导（推荐节点/时间线锚点） | ExplorationGuide | info tab | 该看什么 |
| 6 | 故事叙述 + 历史意义 | StorySection + WhyImportantPanel | info tab | 它为什么重要 |
| 7 | 它意味着什么（理解叙事） | InterpretationPanel | info tab | 怎么理解它 |
| 8 | 关系洞察（AI 门控） | RelationshipInsight | info tab | 深层关系 |
| 9 | 关系探索（Graph/Timeline/Map 三视图） | ConnectionExplorer | info tab | 它跟谁相连 |
| 10 | AI 历史学家对话 | HistorianChat | info tab | 问它问题 |
| 11 | 证据与溯源 | ProvenancePanel | info tab | 凭什么信 |

App 层 footer 另有：**下一站探索**（C 决策，Phase C 新增）、**继续探索**（内容推荐）、**探索路径**（ExplorationPath）。

**三个关键事实：**
1. **tabs 是存在的**（info/research/extensions），但 **info tab 默认就装了 9 块**——tab 没起到减负作用，用户一进来就是"满汉全席"。
2. **M60-001 把 AI 对话从 explore tab 并进了 info tab**——AI 也平铺在主体内容里。
3. **入口桥 + ConnectionCard 过渡叙述内容重复**（同一句话两处显示，PO 截图确认）。

## 2. 用户阅读主线（Article 0 推导）

用户从探索包进入实体，认知上依次需要回答：

```
① 我站在哪     → 位置感（哪条线、第几站）
② 它是什么     → 实体主体（标题/摘要/类型）
③ 为什么重要   → 价值判断（历史意义）
④ 什么关系     → 关系理解（跟谁相连、如何相连）
⑤ 接下来去哪   → 探索延续（下一站）
```

**杂乱的根因**：11 块平铺没有按这条主线分层——AI 对话、证据溯源、探索引导这些"工具/支撑"内容和"主体理解"内容同权堆叠，用户视线无法沿主线走。

---

## 3. 三层模型（方案核心）

| 层 | 职能 | 包含（重组后） | 呈现 |
|---|---|---|---|
| **L1 主体层** | 回答 ①②③（我在哪/是什么/为什么重要） | 站间衔接卡（合并入口桥+ConnectionCard 过渡）、实体标题+摘要、历史意义 | **第一屏，强制精简 ≤ 4 块** |
| **L2 探索层** | 回答 ④⑤（什么关系/接下来去哪） | 关系探索（三视图）、下一站探索（C 决策） | 主体层下方，按序呈现 |
| **L3 工具层** | 支撑性职能（AI/证据/引导） | AI 历史学家、证据与溯源、探索引导、继续探索 | **收进 tab / 折叠**，默认不抢占注意力 |

## 4. 收敛动作 A1–A6

### A1 站间衔接合一（消除重复）
- **现状**：入口桥（顶部蓝框）+ ConnectionCard 过渡叙述各显一遍相同内容。
- **动作**：入口桥并入 ConnectionCard——顶部只留一张「站间衔接卡」，一段话回答「从哪来 + 什么关系」（有证据走关系叙述、无证据走诚实陈述）。
- **影响**：删 1 个平铺块；EntityPage originBridge 组件移除或降级为 ConnectionCard 内部逻辑。
- **风险**：低（纯 UI 重组，Phase B 引擎与数据不动）。

### A2 AI 历史学家收进独立 tab
- **现状**：HistorianChat 在 info tab 平铺（M60-001 合并进来的）。
- **动作**：AI 对话移出 info tab，收进「AI」tab（或 extensions tab）——实体主体页不再是"内容 + 聊天"混排。
- **影响**：info tab 减 1 大块；AI 能力仍在（点 tab 即用）。
- **风险**：中（逆转 M60-001 的合并决策，需 PO 确认 AI 在实体页的定位——建议"按需唤起"而非"常驻平铺"）。

### A3 证据与溯源折叠
- **现状**：ProvenancePanel 平铺在页面底部。
- **动作**：默认折叠为一行标题「证据与溯源」，点击展开（Article 0 真值层仍在，但不再强制滚动可见）。
- **影响**：视觉减负，可信度能力不丢。
- **风险**：低。

### A4 探索引导折叠或并入主体
- **现状**：ExplorationGuide（推荐节点/时间线锚点）与 EntityHero 摘要并存。
- **动作**：探索引导折叠（或仅在有强引导建议时显示）；推荐节点能力并入 L2 关系探索的入口。
- **影响**：减 1 平铺块。
- **风险**：低~中（引导是"探索抓手"，折叠后要保证 L2 关系探索仍易达）。

### A5 继续探索与下一站探索职责划分
- **现状**：下一站探索（C 决策）+ 继续探索（内容推荐）两个块都回答"去哪"。
- **动作**：**下一站探索（C 决策，Phase C 核心）保留在 L2 主位**；继续探索收进「更多」折叠/tab（内容推荐降为二级）。
- **影响**：探索入口主次分明——C 决策是"系统推断的下一个认知目标"，继续探索是"相关内容池"。
- **风险**：低（只是呈现层级调整）。

### A6 探索路径（JourneyTrail）并入站间衔接区
- **现状**：ExplorationPath 行程条独立在 EntityPage 与 footer 之间。
- **动作**：行程条并入 ConnectionCard（站间衔接卡内嵌"第 X/N 站 + 行程缩略"），不再单独占一行。
- **影响**：减 1 个视觉行。
- **风险**：低。

## 5. 重组后实体页（用户视角示意）

```
┌─────────────────────────────────────────────┐
│ 全局导航 · 搜索                               │
├─────────────────────────────────────────────┤
│ 站间衔接卡（合并）                            │  ← L1 ①
│  来自探索包 · 第 3/13 站 · 上一站/下一站        │
│  「公元前27年 关联于 罗马帝国建立 [证据强]」      │
├─────────────────────────────────────────────┤
│ 罗马帝国建立 · 摘要（EntityHero）              │  ← L1 ②
│ 历史意义：它为什么重要                          │  ← L1 ③
├─────────────────────────────────────────────┤
│ 关系探索（图/时间/地图 三视图）                  │  ← L2 ④
│ 下一站探索（C 决策）：奥古斯都 + 理由            │  ← L2 ⑤
├─────────────────────────────────────────────┤
│ [AI 历史学家]  [证据与溯源 ▾]  [更多 ▾]        │  ← L3 工具层（tab/折叠）
└─────────────────────────────────────────────┘
```

**第一屏目标**：用户进入后 5 秒内看到「我在哪 → 它是什么 → 为什么重要」，30 秒内自然走到「关系 → 下一站」。

## 7. 与 Phase B/C/D 的关系

- **Phase B**：站间衔接（ConnectionCard/入口桥）是 L1 ① 的核心——本次只合并呈现，引擎不动。
- **Phase C**：「下一站探索」是 L2 ⑤ 的核心——本次把它放到探索层主位，突出 C 决策价值。
- **Phase D**：认知闭环（理解→缺口→候选→行动）落地时，实体页就是主战场——本次信息架构梳理是 D 的界面层前置，避免"引擎建好了、界面装不下"。
- **施工边界**：本方案拍板后，施工只动 `EntityPage.tsx` / `EntityPageShell.tsx` / `ConnectionCard.tsx` / 相关样式 + 文案词典，不碰 backend / 引擎 / 决策逻辑。

## 8. 验证方式

- 施工后无头浏览器实测：实体页**可见块数从 11 降到 ≤6**（第一屏 ≤4）。
- 功能完整性：关系/时间/地图/AI/证据/下一站/继续探索**全部可达**（tab/折叠可打开）。
- 回归：tsc + 相关组件测试 + freeze-check + 隧道重建。
