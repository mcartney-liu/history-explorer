## 2. RelatedCausalObjectRef — 完整定义

### 2.1 Data Model

```python
@dataclass(frozen=True)
class RelatedCausalObjectRef:
    """M85 — A curator-authored semantic link between two CausalObjects.

    This is NOT a graph edge. It does NOT write to the Knowledge Graph.
    It does NOT participate in any traversal algorithm.
    It is a curator's judgment that understanding Object A helps
    understand Object B — a "why worth reading together" annotation.

    Identity:
      - NOT a KG edge wrapper
      - NOT an AI-generated recommendation
      - NOT a navigation hint (that's M86+)
      - IS a human-curated understanding entry point
    """
    target_id: str         # CausalObject ID (e.g. "co-001")
    relation_type: str     # See §2.3 for allowed values
    explanation: str       # Curator-authored text explaining the relationship

    def to_dict(self) -> dict:
        return {
            "target_id": self.target_id,
            "relation_type": self.relation_type,
            "explanation": self.explanation,
        }
```

### 2.2 字段约束

| 字段 | 约束 |
| --- | --- |
| `target_id` | 必须是存在的 CausalObject ID（co-xxx 格式） |
| `relation_type` | 必须是 §2.3 中定义的 4 种之一（M85 期间不扩展） |
| `explanation` | Curator 手动撰写，非 AI 生成。表达 "为什么值得一起理解"，非 "数据库里存在一条边" |

### 2.3 relation_type — 冻结的 4 种类型

| relation_type | 语义 | 示例 | 判定规则 |
| --- | --- | --- | --- |
| `institutional_evolution` | 制度之间的演化关系 | co-004（秦制）→ co-001（科举） | 两个 CausalObject 解释的制度存在历史连续性 |
| `technological_chain` | 技术之间的互补/前提关系 | co-008（印刷术）→ co-011（造纸术） | 一个技术的理解需要另一个技术作为前提 |
| `civilization_contrast` | 跨文明的制度/思想对比 | co-009（罗马法）→ co-004（秦制） | 两个 CausalObject 分别解释不同文明的类似现象 |
| `ideological_influence` | 思想之间的影响关系 | co-013（佛教）→ co-014（理学） | 一个思想体系的形成受另一个思想体系的影响 |

**M85 期间：仅此 4 种。不新增。M86+ 根据 Explorer 行为数据扩展。**

### 2.4 禁止的 relation_type

| 禁止值 | 理由 |
| --- | --- |
| `kg_derived` | KG 边包装 |
| `ai_generated` | AI 生成 |
| `recommended` | 推荐引擎 |
| `similar_to` | 过于模糊 |
| `causal_chain` | 暗示因果推导链 → 逼近 Reasoning |
| `same_topic` | 过于泛化 → 无法区分 Semantic vs Navigation |

## 3. Relationship ≠ Edge — 核心架构约束

### 3.1 明确禁止的理解

```
❌ 错误理解：
  CausalObject.related_causal_objects ≈ graph.add_edge()
  → Semantic Graph → Graph Traversal → Recommendation → AI Reasoning

✅ 正确理解：
  RelatedCausalObjectRef = Curator 提供的一条理解入口
  → 不是图结构
  → 不参与遍历算法
  → 不被任何自动系统消费（除 Explorer UI 展示外）
```

### 3.2 Runtime 禁止

```python
# ❌ 禁止：基于 related_causal_objects 构建图索引
semantic_graph = nx.DiGraph()
for obj in causal_objects:
    for ref in obj.related_causal_objects:
        semantic_graph.add_edge(obj.id, ref.target_id)

# ❌ 禁止：BFS/DFS traversal
def find_causal_chain(start_id):
    visited = set()
    queue = [start_id]
    ...

# ❌ 禁止：传递闭包推导
def infer_transitive(obj_a, obj_b, obj_c):
    if obj_a → obj_b and obj_b → obj_c:
        return obj_a → obj_c  # 不自动推导

# ❌ 禁止：基于 related_causal_objects 的推荐
def recommend_next(viewed_objects):
    # 不基于关系图推荐
    ...
```

### 3.3 允许的使用

```python
# ✅ 允许：静态查询
def get_related_objects(obj_id: str) -> list[RelatedCausalObjectRef]:
    obj = load_causal_object(obj_id)
    return list(obj.related_causal_objects)

# ✅ 允许：Explorer UI 展示
# CausalObjectDetailPage 底部：
#   "相关解释" section
#   遍历 related_causal_objects，每个渲染为可点击的链接
```

## 4. KG Boundary — C1 最终冻结

### 4.1 C1 修订历史

```
C1 初版（M85.0 Architecture Gate §4.3）：
  不把 KG 边包装成 Semantic Edge

C1 修订（M85.0 Architecture Gate §4.3 P2 案例后）：
  KG 关联不排除 Semantic 关系，
  关键是 explanation 提供 KG 不包含的理解层次

C1 最终版（M85.1 Model Freeze）：
  同一实体关系可以同时存在于 KG 和 Semantic Layer。
  区别不是连接对象，而是表达层次：
    KG 描述事实连接（What exists）
    Semantic 描述理解价值（Why worth understanding together）
```

### 4.2 判定示例

```
co-004（秦制→三省六部）和 co-001（科举→文官）

KG 视角：
  秦制（china_v1:idea-qinzhi）和科举（china_v1:idea-keju）
  在 KG 中无直接 Relationship → 无 KG 冲突

Semantic 视角：
  Curator 判断：理解秦制的中央集权框架，有助于理解
  科举为什么在中国而非其他地方出现 → 有理解价值

→ 纳入 related_causal_objects ✅
```

```
co-008（印刷术→知识传播）和 co-011（造纸术→知识传播）

KG 视角：
  两者 effect 相同（知识传播）→ KG 已表达关联

Semantic 视角：
  Curator 判断：理解造纸术降低书写材料成本，有助于理解
  印刷术为什么产生革命性影响（技术链前提关系）
  → explanation 提供 KG 不包含的理解层次

→ 纳入 related_causal_objects ✅（C1 修订后）
```

### 5.2 新增 C5：Relationship Value Validation

```
C5：验证 relationship explanation 本身有价值

问题：
  如果去掉 explanation 文本，只保留两个 CausalObject 的链接，
  Explorer 的跨对象理解深度是否下降？

验证方式：
  M85 Explorer Validation 中，对比：
    Group A：有 explanation 的 related_causal_objects
    Group B：仅有链接（无 explanation）

  如果 Group A 的跨对象理解深度 > Group B：
    → explanation 有价值 → Semantic Relationship 成立

  如果 Group A ≈ Group B：
    → Explorer 只需要"看到更多对象"，不需要"理解对象关系"
    → M85 方向需要重新审视
```
