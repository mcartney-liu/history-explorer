# M86.1.4 — Explorer Runtime Context Validation Scenario
### Strict Read-Only / Architecture Validation

> 模式声明：严格只读。用一条完整探索路径验证 M86.1.0~1.3 的所有冻结规则能否同时成立。不写代码、不设计组件。类似架构验收测试——在代码之前证明 Context 的生命周期、EP-006~009、各 Layer 的读写权限在真实场景中不自相矛盾。

---

## 第一部分：场景设定

**用户**：普通用户，首次使用，无历史专业知识。

**起始好奇**："为什么罗马能从一个城邦扩张成帝国？"

**探索路径**：Curiosity → Orientation → Discovery（罗马军团）→ Connection（军团→罗马道路系统）→ Connection（道路→罗马行省治理）→ Understanding（闭环）→ New Question（"为什么这种体系后来失效了？"）

---

## 第二部分：Context 生命周期全链路验证

### 阶段 1：Curiosity → Orientation（Context 创建）

Context 创建：
```
exploration_id: "exp-roman-expansion-001"
user_question: "为什么罗马能从一个城邦扩张成帝国？"
understanding_goal: "理解军事组织、道路网络、行省治理如何共同形成罗马的帝国扩张能力"
cognitive_stage: FACT
```

- Curiosity Entry 触发创建（通过宿主）
- ExplorePage 从 ExplorationPackage 读取 seed_topic → user_question，exploration_goals → understanding_goal
- Orientation 只读 user_question + understanding_goal
- ✅ EP-009：user_question/goal 来自 Curator 预写

### 阶段 2：Discovery（进入"罗马军团"）

Context 更新：
```
current_focus: "罗马军团"
previous_focus: null
relation_reason: null
cognitive_stage: FACT（Understanding Layer 判定：首个对象，确认事实）
```

- Navigation Context 记录锚点移动（current_focus 来自 Entity.name）
- Understanding Layer 判定 cognitive_stage = FACT
- AI Companion / Seeds / Workspace 只读 Context
- ✅ cognitive_stage 不由 Navigation 写入
- ✅ current_focus 不包含 Entity 数据副本

### 阶段 3：Connection（军团 → 罗马道路系统）

Context 更新：
```
current_focus: "罗马道路系统"
previous_focus: "罗马军团"
relation_reason: "军团扩张需要快速投送兵力，道路系统解释了这种后勤能力如何实现"
cognitive_stage: CONNECTION（Understanding Layer 判定：有语义跳转）
```

- relation_reason 来自 Causal Layer 已有关系数据（RelatedEntity）
- Understanding Layer 检测到语义跳转 → CONNECTION
- ✅ EP-009：relation_reason 来源 = Causal Layer
- ✅ cognitive_stage 仅由 Understanding Layer 写入

### 阶段 4：Connection（道路 → 罗马行省治理）

Context 更新：
```
current_focus: "罗马行省治理"
previous_focus: "罗马道路系统"
relation_reason: "道路连通各行省后，罗马需要一套制度来管理被征服地区"
cognitive_stage: CONNECTION
```

- 两次 CONNECTION 形成链：军团 → 道路 → 治理
- ✅ 每次 relation_reason 可追溯到 Causal Layer

### 阶段 5：Understanding（理解闭环）

Context 更新：
```
cognitive_stage: UNDERSTANDING（形成因果链：军团→道路→治理，对比 understanding_goal 达成）
unresolved_gap: "为什么这种军事+道路+治理的体系后来失效了？"
```

- Understanding Layer 判定：锚点链 ≥ 2 层 + 对比 goal → UNDERSTANDING
- unresolved_gap 推导：理解了扩张 → 缺口是衰落（基于理解结构 + Curator 种子）
- 理解闭环触发：展示"军团提供武力 → 道路解决投送 → 治理维持控制"
- ✅ unresolved_gap 来自理解结构推导，非 AI 生成
- ✅ 不由定时器或跳转次数自动触发

### 阶段 6：New Question（新问题孵化）

旧 Context → COMPLETED（保留全部数据供 Workspace）

新 Context 创建：
```
exploration_id: "exp-roman-decline-001"
user_question: "为什么罗马的扩张体系最终失效了？"（← 旧 unresolved_gap）
cognitive_stage: FACT
```

- Question Transition 读取 unresolved_gap → 显形为新问题
- 用户主动选择继续（非推送）
- 新 Context 新 exploration_id，不跨 Exploration 混合
- ✅ 新问题来自理解结构缺口，非算法推荐

## 第三部分：EP-006~009 验证矩阵

| EP | 场景中如何体现 | 通过 |

| EP-006 | 所有 Layer 从同一个 Context 读取，无人自行推断 | ✅ |

| EP-008 | cognitive_stage 仅由 Understanding Layer 判定 | ✅ |
| EP-009 | user_question/goal 来自 Curator，relation_reason 来自 Causal，unresolved_gap 来自推导 | ✅ |

## 第四部分：边界问题

1. **首个对象 cognitive_stage = FACT**：合理，用户需确认事实。规则确认：首个对象始终为 FACT。
2. **无语义跳转不改变阶段**：relation_reason 为空时 cognitive_stage 保持 FACT。规则确认：阶段上移需语义数据支撑。
3. **回退到 FACT 合法**：用户可能中途确认事实。规则确认：下移合法，stage 是认知需求类型非进度条。
