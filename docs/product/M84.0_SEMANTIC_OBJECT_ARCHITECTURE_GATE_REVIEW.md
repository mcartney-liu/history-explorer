## §2 Semantic Object Definition

### 2.1 定义

```
Semantic Object = Entity + Explanation Layer + Exploration Context
```

**不是**：CausalStatement 的包装层。CausalStatement 是 Semantic Object 的一种实例。

### 2.2 Core Responsibility

| 职责 | 说明 |
| --- | --- |
| **解释历史关系** | "为什么 A 导致了 B？" — 继承自 CausalStatement |
| **提供探索上下文** | "基于这个解释，你可以继续探索什么？" — M84 新增 |
| **关联知识图谱** | 引用 KG Entity/Relationship，但不修改它们 |
| **呈现理解路径** | 不只是文本卡片，而是一个可交互的探索入口 |

### 2.3 Non-Responsibility

| 不是 | 为什么不是 |
| --- | --- |
| 替代 Knowledge Graph | KG 回答 "What exists?"，Semantic Object 回答 "How to understand it?" |
| 生成新知识 | Semantic Object 是 curator 策展的解释，不是 AI 生成的事实 |
| 修改 Entity/Relationship | 只引用 KG GID，不写入 Graph Core |
| 推理引擎 | 不推导未知关系，不预测历史因果 |
| 通用 Schema 层 | Semantic Object 是特定于 History Explorer 的领域模型，不是跨项目抽象 |

### 2.4 Semantic Object 的四种可能实例

```
SemanticObject（抽象）
  ├── CausalObject     ← 因果解释（M82 已验证，M84 升级）
  ├── ThemeObject      ← 主题/概念（未来）
  ├── InfluenceObject  ← 影响关系（未来）
  └── NarrativeObject  ← 叙事链（未来）
```

**M84 只实现 CausalObject。** 其他三种是 M85+ 的方向。不在 M84 中定义未验证的 Object 类型。

## §3 KG Boundary

### 3.1 边界定义

```
Knowledge Graph（事实层）
  ├── Entity（谁/什么）
  ├── Relationship（什么关系）
  └── Properties（时间/地点/属性）

Semantic Object Layer（解释层）
  ├── CausalObject（为什么）
  ├── Exploration Context（接下来探索什么）
  └── Presentation（如何呈现给 Explorer）
```

### 3.2 交互方式

```
KG  → 提供 Entity GID + Relationship 结构
SO  → 引用 KG GID，附加解释和探索上下文
KG  ← SO 不写入 KG（单向引用）
```

### 3.3 禁止的交互

| 禁止 | 理由 |
| --- | --- |
| Semantic Object 写入 Graph Edge | KG 是事实层，SO 是解释层 — 解释不是事实 |
| Semantic Object 修改 Entity 属性 | 同上 |
| Semantic Object 替代 KG 查询 | KG 仍然是 Explorer 的主要数据源，SO 是增强层 |
| KG 依赖 Semantic Object | KG 可以独立运行，不依赖 SO |

### 3.4 Boundary Diagram

```

│              Explorer UI                │
│  ┌──────────┐  ┌────────────────────┐   │
│  │ KG Views │  │ Semantic Object    │   │
│  │ (Entity/ │  │ (CausalObject      │   │
│  │  Rel/    │  │  Detail Page)      │   │
│  │  Timeline│  │                    │   │
│  │  Map)    │  │                    │   │
│  └────┬─────┘  └─────────┬──────────┘   │
│       │                  │              │
├───────┼──────────────────┼──────────────┤
│       ▼                  ▼              │
│  ┌─────────┐      ┌──────────────┐      │
│  │   KG    │      │ Semantic Obj │      │
│  │ (Fact)  │◄─────│ (Explanation)│      │
│  └─────────┘ ref  └──────────────┘      │
│   独立运行          引用 KG GID          │
│   不依赖 SO         不写入 KG            │
```

## §4 CausalStatement Evolution

### 4.1 当前状态（M82/M83）

```
CausalStatement（7 字段 JSON）
  ├── id, cause_id, effect_id
  ├── mechanism, consequence
  ├── confidence, evidence_refs
  ↓
CausalStatementCard（UI 组件）
  ↓
Explorer 看到解释
```

### 4.2 M84 演进路径

```
CausalStatement（保持兼容）
  ↓ 实现
CausalObject（新抽象）
  ├── 继承 CausalStatement 全部字段
  ├── 新增：related_entities（关联的其他 Entity）
  ├── 新增：exploration_paths（推荐的探索路径）
  ├── 新增：detail_page（独立详情页）
  └── 新增：object_type = "causal"
  ↓
CausalObjectDetailPage（新 UI）
  ↓
Explorer 看到解释 + 探索入口 + 关联实体
```

### 4.3 兼容性保证

| 维度 | 兼容策略 |
| --- | --- |
| **数据** | CausalStatement 7 字段不变，CausalObject 是超集 |
| **API** | `PathCandidate.causal_statements` 和 `ExploredNode.causal_statements` 继续返回 CausalStatement 格式。新增 `CausalObject` 的 API 端点（M84 P1） |
| **UI** | `CausalStatementCard` 不变。新增 `CausalObjectDetailPage`（从 Card 点击进入） |
| **Event** | 现有 5 个 `cs_*` 事件不变。新增 `co_*` 事件（M84 P1） |

### 4.4 不做什么

| 不做 | 理由 |
| --- | --- |
| 重写 CausalStatement Schema | 7 字段已冻结（C-7），M84 不突破 |
| 废弃 CausalStatementCard | 它是已验证的入口组件，M84 保留 |
| 把所有 CS 批量迁移到 CausalObject | 渐进式 — 先为 3-5 条高价值 CS 创建 CausalObject |

## §5 Architecture Impact

### 5.1 新增模块

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `CausalObject`（Backend Model） | CausalStatement 的超集，新增 related_entities / exploration_paths / object_type | CausalStatement（已有） |
| `CausalObjectLoader`（Backend） | 加载 CausalObject 数据（JSON） | CausalLoader（已有） |
| `CausalObjectAdapter`（Backend） | 查询 CausalObject（get_by_entity / get_by_id） | CausalStatementAdapter（已有） |
| `CausalObjectDetailPage`（Frontend） | 独立详情页 | CausalStatementCard（已有） |

### 5.2 不变模块

| 模块 | 不变理由 |
| --- | --- |
| CausalStatement Schema（7 字段） | M82 Frozen（C-7） |
| CausalStatementCard | 已验证的入口组件，继续作为 CausalObject 的入口 |
| Graph Core（Entity/Relationship/Edge） | M82 Frozen（C-1/C-2/C-4） |
| Exploration Engine（explore/find_connections） | 不修改核心逻辑，仅扩展 CausalObject 查询 |
| Runtime/Package 数据流 | M83 Decision D7（永久分离） |

### 5.3 架构风险

| 风险 | 概率 | 缓解 |
| --- | --- | --- |
| CausalObject 过度抽象 → 变成通用 Schema 层 | 中 | M84 只实现 CausalObject 一种实例，不定义 "通用 Semantic Object 抽象类" |
| CausalObject 数据膨胀 → 与 KG 边界模糊 | 低 | CausalObject 只引用 KG GID，不写入 |
| Detail Page 过度设计 → 变成 Entity Page 的替代品 | 低 | Detail Page 聚焦 "解释 + 探索入口"，不重复 Entity Page 的 Timeline/Map 功能 |

## §7 Acceptance Criteria

### 7.1 产品指标

| 指标 | 定义 | 采集 |
| --- | --- | --- |
| CausalObject Open Rate | 从 CausalStatementCard 进入 Detail Page 的比例 | `co_detail_open` 事件 |
| Object Exploration Depth | Detail Page 中点击 related_entities 的次数 | `co_entity_follow` 事件 |
| Related Entity Follow Rate | Detail Page 中 related_entities 被点击的比例 | `co_entity_follow / co_detail_open` |
| Return Exploration Rate | 离开 Detail Page 后继续探索的比例 | 沿用 `cs_follow_entity` |

### 7.2 工程指标

| 指标 | 定义 |
| --- | --- |
| Schema Stability | CausalStatement 7 字段在 M84 全程不变 |
| Runtime Compatibility | 现有 `explore()` / `find_connections()` API 不受影响 |
| No KG Coupling | CausalObject 不修改 KG Entity/Relationship |

### 7.3 成功标准

```
M84 成功 ≠ "新增了 N 个 CausalObject"

M84 成功 = Explorer 是否愿意从 "看解释" 进入到 "围绕解释继续探索"
```

如果 CausalObjectDetailPage 的 Open Rate > 30% 且 Related Entity Follow Rate > 20%，说明 Explorer 接受了 "解释 → 探索" 的模式升级。

## §8 Architecture Decision

```
READY
```

### 核心判断

M84 的风险不是做少，而是做大。当前架构决策严格约束了 M84 的范围：

- **只实现 CausalObject 一种 Semantic Object 实例** — 不为未验证的类型（ThemeObject/InfluenceObject）预留抽象
- **不修改 Graph Core** — CausalObject 只引用 KG GID，不写入
- **不突破 M82 Freeze** — CausalStatement 7 字段不动
- **不引入 AI** — 策展内容的价值已被 M83 验证，AI 生成是 M85+ 的问题

### 与 M83 的继承关系

```
M83 证明：解释 → 用户探索增强
M84 实现：把解释从 CausalStatement 组件升级为 CausalObject 平台能力
M85 验证：多跳因果 + 更多 Object 类型
```
