## §3 Core Decisions

### Decision D1 — CausalStatement 保留

```
状态：APPROVED
Confidence：High
```

**证据**：E1（自然发现 4/4）+ E3（Recall 2.8/3）+ E4（Intent 4/4）

**含义**：CausalStatement 不是装饰性解释模块。它改变了 Explorer 对历史关系的理解方式。不应被移除或降级。

### Decision D2 — CausalStatement 从 Feature 升级为 Semantic Layer Capability

```
状态：APPROVED
Confidence：High
```

**证据**：E2（深度提升 4/4）+ E5（"缺少解释" 3/4）

**含义**：CausalStatement 不再只是 "一个 JSON 里的文本字段"。Explorer 已经形成了 "这个产品应该告诉我为什么" 的认知预期。CS 从 Feature 升级为 Capability——这是产品定位的变化。

### Decision D3 — M84 进入 Semantic Object Expansion

```
状态：PROCEED
Confidence：High
```

**范围**：从 `CausalStatement`（JSON 内容）升级为 `Causal Object`（独立 Exploration Object）

| 允许（M84） | 禁止（M84） |
| --- | --- |
| Causal Object Model（独立于 Entity/Relationship） | AI 自动生成 CS |
| Causal Detail Page | Graph Edge 写入 CS |
| Causal Presentation Enhancement | Multi-hop Runtime |
| Causal Data 扩展到 20+ 条 | CausalStatement Schema 扩展（7 字段不动） |
| 跨包 CS（罗马/丝路） | Runtime/Package 数据流合并 |

**继承 M83 的边界**：M84 是 Expansion，不是 Reasoning。不引入 AI、不修改 Graph Core、不突破 Semantic Layer Freeze。

### Decision D4 — Evidence Layer 暂缓

```
状态：HOLD
Confidence：Medium
```

**证据**：E6（Evidence Open 1/4）

**含义**：Explorer 认可因果解释（Recall 2.8/3），但没有主动追溯证据来源（Evidence Open 1/4）。当前用户需求是 "Why" 强、"Prove" 弱。Evidence UI 扩展属于 M84 的 P2（如果 M84 的 Causal Object 增加了证据展示需求）或 M85。

### Decision D5 — Multi-hop 暂不进入 M84

```
状态：DEFER TO M85
Confidence：Medium
```

**证据**：当前 CS 都是 1-hop（A→B），无链式 CS 数据。`cs_guide_next = 0` 在所有 Session 中——Explorer 更倾向自驱探索而非系统引导。

**含义**：单跳因果已验证，但多跳因果的前提（链式 CS 数据 + Explorer 沿因果链深入的行为）尚未满足。M85 继续等待。

### Decision D6 — AI 自动生成 CS 暂不引入

```
状态：REJECT（for M84）
Confidence：High（Reject）
```

**证据**：M82 Freeze C-6（AI 不作为事实来源）+ 无证据支持 AI 生成 CS 的价值。

**含义**：CausalStatement 的价值来自 curated content（人工策展），不是 AI 生成。M83 验证的是 "策展的因果解释是否有价值"——引入 AI 生成会破坏这个验证基础。M83.5+ 重新评估。

### Decision D7 — Runtime/Package 数据流合并 不做

```
状态：REJECT（永久）
Confidence：High（Reject）
```

**证据**：M83 Data Flow Review 确认两条路径长期共存是产品决策。

**含义**：Package 的静态特性是产品优势，不是技术债。不合并。
