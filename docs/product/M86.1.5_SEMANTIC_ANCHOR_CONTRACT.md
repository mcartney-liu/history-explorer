# M86.1.5 — Semantic Anchor Contract
### Strict Read-Only / Semantic Data Model Freeze

> 模式声明：严格只读。定义 Anchor 和 Relation 的语义数据模型。解决 Batch 1 的三个隐藏风险：currentFocus 字符串唯一性、relationReason provenance 缺失、Context 路径与 ExplorerPath 的边界。不写代码、不设计组件。

---

## 第一部分：Anchor 定义

> **Anchor = 用户在理解过程中对某个知识对象的注意力锚定。不是 Entity 本身，而是 Entity 在用户当前认知过程中的引用。**

```
Anchor {
  entityId: string          // Knowledge Layer 唯一标识（Entity.global_id）
  entityType: string        // 对象类型（person/event/civilization/concept/institution）
  displayName: string       // 用户语言名称（来自 Entity.name，用于展示）
  provenance: {
    source: 'knowledge_layer' | 'causal_layer' | 'curator_layer'
    dataset?: string
    version?: string
  }
  semanticRole?: string     // 在当前理解线中的角色（Batch 3 使用）
}
```

Anchor 不是 Entity 副本——通过 entityId 指向 Knowledge Layer，显示时查询完整信息。

---

## 第二部分：Relation 定义

> **Relation = 用户从上一个 Anchor 到当前 Anchor 的认知推进理由。不是自由文本，而是对 Causal Layer 已有关系数据的引用。**

```
Relation {
  relationId: string          // Causal Layer 关系标识
  fromAnchor: string          // 上一个 Anchor 的 entityId
  toAnchor: string            // 当前 Anchor 的 entityId
  relationType: string        // causes/supports/influences/explains/precedes/contrasts
  provenance: {
    source: 'causal_layer' | 'curator_layer'
    dataset?: string
    version?: string
  }
  descriptionRef: string      // 关系描述引用键（渲染时从 Causal Layer 查询展示文本）
}
```

Context 不保存展示文本，保存 descriptionRef。EP-009：展示文本在渲染时从 Causal Layer 查询。

---

## 第三部分：创建规则

**Anchor**：Knowledge Layer 提供数据 → Navigation Layer 触发创建 → Context 保存引用。

**Relation**：仅在 (1) previousAnchor 存在 (2) 不同 Anchor (3) Causal Layer 有 from→to 关系数据时创建。不满足条件则不创建 Relation。

---

## 第四部分：Context 路径 vs ExplorerPath 边界

| 维度 | ExplorerPath | Context 锚点链 |
|---|---|---|
| 记录什么 | 访问过哪些节点 | 理解如何推进 |
| 数据单位 | visitedObjects: string[] | Anchor + Relation 对象 |
| 语义 | 无（ID 序列） | 有（类型/来源/描述引用） |
| 用途 | 行为分析 | 理解追踪 |

> **ExplorerPath 是行为记录层，Context 是语义理解层。不合并、不替代。**
