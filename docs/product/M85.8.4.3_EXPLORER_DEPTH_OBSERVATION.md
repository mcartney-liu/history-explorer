# M85.8.4.3 Explorer Depth Observation

> **阶段**：M85.8.4.3 — 验证 Explorer 是否因理解而持续探索
> **类型**：Observation（非实验设计，非 Validation Protocol）
> **日期**：2026-08-06
> **基线**：M85.8.4.2 Explorer Experience Contract（含 C6）

---

## 0. 核心问题

```
不是：
  "用户点击了多少次？"

而是：
  "用户是不是因为理解而继续探索，
   而不是因为页面好看而点击？"

不是：
  "用户喜不喜欢产品？"

而是：
  "用户是否形成了自己的理解？"
```

---

## 1. 三个观察指标

### O1 — Understanding Depth（理解深度）

| 指标 | 定义 | 采集方式 |
| --- | --- | --- |
| Depth 1 | 打开一个 CausalObject | 自然行为 |
| Depth 2 | 点击一个 Semantic Relationship | 观察记录 |
| Depth 3 | 形成跨对象理解链（≥2 步） | 观察记录 + 复述验证 |
| Depth 4+ | 主动寻找新的关联 | 观察记录 |

**关键验证**：Session 结束后问——

> "你觉得刚才几个历史对象之间是什么关系？"

| 回答类型 | 判定 |
| --- | --- |
| "秦制提供治理框架，科举解决人才选拔，形成官僚体系" | Depth 3 — 真正的理解链 |
| "它们都跟制度有关" | Depth 1 — 表面关联，未形成理解 |
| "不知道" | Depth 0 — 点击但未理解 |

### O2 — Relationship Acceptance（关系接受度）

| 指标 | 定义 |
| --- | --- |
| Accepted | 用户表达了 "这个关系合理"/"原来如此" 类似的认可 |
| Questioned | 用户表达了 "为什么放一起？"/"这个关系不太对" 类似的质疑 |
| Ignored | 用户看到了但未点击/未评论 |

**关键验证**：如果 O2 Questioned 比例高 → curator relationship 质量需要审查。

### O3 — Self-generated Question（自主产生问题）

| 指标 | 定义 |
| --- | --- |
| Yes | 用户在看完后主动提出新问题（如 "那西方为什么没有走这条路线？"） |
| Hinted | 用户表达了困惑但未形成明确问题 |
| No | 用户看完后停止探索 |

**关键验证**：O3 是最高价值指标。如果用户产生了新问题 → Explorer Engine 开始工作。

## 2. C6 — 探索必须留下认知路径（补充）

### 规则

```
C6: Exploration Path Preservation

用户完成一次理解旅程后，系统应该能够表达认知路径：

  "你从 [问题] 出发，
   经过 [对象A] → [关系] → [对象B]，
   理解了 [认知结论]。"

不是推荐。
不是画像。
是理解轨迹。
```

### 当前实现

NavNode history 已记录 `causal_object` 类型的导航节点。breadcrumb 已展示探索路径。Journey trace 已记录入口和步骤。

### 待验证

```
Session 后观察：
  用户能否回溯自己的探索路径？
  breadcrumb 是否帮助用户理解 "我怎么走到这里的"？
```

## 3. Session 设计

### Session 1 — 首次用户（制度演化链）

| 维度 | 内容 |
| --- | --- |
| **Explorer** | P1（新用户，对中国历史有基础认知） |
| **入口** | Discover → "为什么中国形成中央官僚体系？" → co-004 |
| **观察** | 是否自然走通 秦制 → 科举 → 形成理解 |
| **重点** | O1 Depth / O2 Acceptance / O3 Self-generated |

### Session 2 — 返回用户（文明对比链）

| 维度 | 内容 |
| --- | --- |
| **Explorer** | P2（参与过 M85.8.3，已有探索经验） |
| **入口** | Discover → "不同文明如何解决治理问题？" → co-009 |
| **观察** | 是否从罗马法反向进入秦制 → 是否形成跨文明理解 |
| **重点** | O2 Acceptance（文明对比关系的接受度） |

### Session 3 — 技术链用户

| 维度 | 内容 |
| --- | --- |
| **Explorer** | P3（新用户，对技术史有兴趣） |
| **入口** | Discover → "技术如何改变知识传播？" → co-008 |
| **观察** | 造纸术 → 印刷术 技术链是否被接受 |
| **重点** | O1 Depth / O3 Self-generated |

### Session 4 — 长探索用户

| 维度 | 内容 |
| --- | --- |
| **Explorer** | P4（新用户，无特定兴趣） |
| **入口** | Discover → 任意 Seed |
| **观察** | 5-10 分钟内是否持续探索，探索深度上限 |
| **重点** | O1 Depth 上限 / C6 回溯能力 |

### Session 5 — 回归用户

| 维度 | 内容 |
| --- | --- |
| **Explorer** | P5（参与过 Session 1，间隔一段时间后回归） |
| **入口** | Discover → 上次未探索的 Seed |
| **观察** | 是否记住之前的理解，是否产生新的探索链 |
| **重点** | C6 认知路径保留 / O3 新问题产生 |

```
  [原话]

  Yes / Hinted / No
  [原话]

C6 认知路径：
  能否回溯：[YES/NO]
  breadcrumb 是否帮助理解：[原话]

信号判定：
  Strong — O1≥3 + O2 Accepted + O3 Yes
  Medium — O1≥2 + O2 Accepted
  Weak   — O1≤1
```

---

## 5. 判定标准

```
M85.8.4.3 通过条件：
  ≥3/5 Session 达到 Strong 或 Medium 信号
  且 O3 Self-generated Question ≥2 次（Explorer Engine 启动信号）

如果全部 Strong：
  → M86 方向确认：Explorer 需要更高层理解结构

如果 Mixed（Strong + Weak）：
  → M85.8.5 体验优化（非 M86）

如果全部 Weak：
  → 重新审视 Understanding Journey 的呈现方式
```
