# Transition Function（过渡函数）— 核心能力课题

> 立项：2026-08-15 · 提出人：翔哥（PO）· 状态：课题立项（v1 已落地，演进待研究排期）
> 定位：**产品核心能力**，不是一次性小功能——所有"实体 A → 实体 B"的承接与过渡都依赖它。

---

## 1. 一句话定位

> 给定任意一对实体（A, B），回答"**用户从 A 到 B 时，应该看到怎样的过渡描述**"。
> 它决定探索的"接缝处"是光滑还是断裂——是产品"连续感"的底层能力。

### 消费场景（同一个函数，多处复用）
| 场景 | 调用 |
|---|---|
| 探索包站间衔接（前后站） | describeTransition(上一站, 本站) |
| 入口桥（任意实体跳转） | describeTransition(来源A, 本站B) |
| 下一步探索推荐 | describeTransition(当前, 推荐目标) |
| 因果对象页 / 关系视图 / 跨主题跳转 | describeTransition(A, B) |
| 未来：轨迹回放、旅程总结、对比页 | 同源复用 |

---

## 2. 现状：v1（已实现，2026-08-15）

### 三层设计
```
describeTransition(A, B)
  → ① 有中文 evidence claim → 讲 claim 叙述（最有意义）
  → ② 无 claim 但有直接关系边 → 关系短句（"唐 早于 宋"）
  → ③ 无直接边 → null（由场景决定降级文案）
```

### v1 的本质
**数据检索 + 语言化**：查 A↔B 关系边 → 语言化。诚实、图 grounded、零编造。

### v1 的边界（= 它还"简单"在哪）
- 只回答"**是什么关系**"，不回答"**为什么是这段旅程**"
- 无直接边时直接放弃（返回 null），不尝试找路径
- 不感知场景（包内衔接 / 入口桥 / 推荐，讲法都一样）
- 不携带证据分级（这个过渡有多确定？）
- claim 英文时降级为关系短句（数据侧未双语）

---

## 3. 差距：v1 → 终极（研究主线）

> v1 回答"**A 和 B 有关系**"；终极要回答"**A 和 B 为什么连着走、走的这一步意味着什么**"。

| 维度 | v1（数据层） | 终极（叙事层） |
|---|---|---|
| 内容 | 关系类型 / claim 事实 | 过渡的**动机与意义**（"唐的科举制度在五代动荡中延续，成为宋重文政治的根基"）|
| 无直接边 | 放弃（null） | **找路径**：A→C→B，讲"通过 C 连接" |
| 场景 | 一律相同 | **场景感知**：包内讲"行程衔接"、入口桥讲"你从哪来"、推荐讲"为什么推荐" |
| 证据 | 无分级 | 带**证据强度/来源分级**（P09 真值层）|
| 语言 | 中文 claim 才用 | 双语策展（数据侧补齐）|
| 连续 | 单段 | **N 元连续过渡**（A→B→C 的旅程弧线）|

---

## 4. 演进路线（分阶段研究，不一口气做完）

### v1（已落地）
三层检索 + 语言化。**先让所有承接场景都有"桥"可讲**（站间衔接 ✓ / 入口桥 ✓ / 后续场景接入）。

### v2（进行中）
- **多跳路径桥 ✅（已落地 2026-08-15）**：A↔B 无直接边时，找**共同邻居 C**（A—C、B—C 均为真实边），讲"A 与 B 通过 C 相关联"。实现：实体详情邻居**会话缓存**（entityCache，App fetchNode 写入）→ 共同邻居查找零网络请求。describeTransition 升级 4 层：①claim ②关系短句 ③共同邻居路径 ④null 降级。已接入入口桥 + 站间衔接。
- **场景感知（评估后不引入）**：经分析为伪参数——三处场景的差异已由各 UI 的 kicker 文案承担（入口桥"从「A」来"、站间衔接"从上一站来"），过渡函数的职责是给"事实叙述"（唯一事实），context 参数会导致三处输出相同。**结论：不引入，YAGNI**。
- **数据前置（OD-11）**：中文 claim / 过渡句双语策展补齐——这是叙事层的原料，需策展人排期

### v3（远景）
- **策展叙事弧**：人工撰写的站间过渡（OD-11 数据）或**受控模板**（非 AI 编造）——真正的故事感
- **证据分级标注**：过渡描述的确定性分级（P09）
- **N 元连续过渡**：多站旅程的整体承接

## 5. 开放研究问题（课题待研）

1. 无直接边时，多跳路径的"最短路径"是否总是有意义？（A→C→B 可能跨度过大）
2. 场景感知的边界：同一 A→B 在"包内衔接"和"入口桥"讲法应差多少？会不会反而混乱？
3. 过渡描述是否应该带"确定性/证据分级"？如何不破坏简洁性？
4. v3 的"叙事弧"由策展写（人工，质量高成本高）还是受控模板（自动，需严格防编造）？
5. 过渡函数与"因果解释层"（Causal）的关系：机制/后果是否算一种过渡？
