## 2026-08-03 产品愿景讨论（Founder / Partner 对话）

### 愿景三层结构（待提炼进 DNA）
1. **底座可横扩**：以"探索体验"交互为壳，知识域为可换芯；历史为首个验证域，未来铺到军事、政治、文学作品、科技作品（例：《时间简史》）、各类课题主题。
2. **对用户的核心意义——兴趣培养**：让原本不以为然的东西先"起兴趣"→"真有兴趣"→"找到适合自己性格的发展方向"。本质是把"要我学"扭成"我要学"。
3. **新学习范式**：以前=给一本书自己读；现在=给一本书+兴趣驱动+辅助，让人"通透地"理解知识。终局是兴趣驱动+辅助通透的新学习方式。

### Partner 判断（待验证链条补齐）
- 愿景每一层需**独立验证**，不能一层成立推导下一层：
  - 探索壳转不转 → M81a（进行中）
  - 横扩各域能否同样转 → 各域需各自 M81a 级验证
  - 兴趣能否被培养 → 学习科学命题，需长期留存/回访数据
  - 辅助通透学习 → 教育成效评估，远在 PRD/DNA 外数步
- PRD/DNA 写愿景时应**同时写每层验证方式**，避免沦为口号。

### 待 Founder 确认 / 补充
- "DNA" 指代：产品核心范式 / 底层定义类纲领文件（Founder 已确认此理解）。
- 落文档时机：M81a 收尾后、进 M83 前，系统梳理写进 PRD/DNA。

## 2026-08-04 探索层（Exploration Layer）概念讨论（Founder / Assistant + 外部视角）

> 来源：Founder 提出「边界层」概念 → Assistant 初版映射为「原子 / 图谱 / 结论边界」三层 → Founder 转发外部视角（Side Index 与本产品差异）→ Assistant 修正。
> 以下为产品级灵感暂存，**非决策、非 ADR、非 PRD/DNA 修改**。待 M81a 收尾、进 M83 前与 Founder 联合评审升格。

### 核心概念：三层边界模型
1. **原子信息层（Atomic Layer）**：所有知识打散成原子单元，策展级、带 provenance、不可被对话 / 探索改写。
2. **图谱关联关系层（Graph/KG Layer）**：在原子间建立连接与解释（Relationship Layer observe-only + Causal Layer M79 仅 6 字段解释）。
3. **探索层（Exploration Layer）**：用户 / AI 探索过程中产生的"新结论、新问题、新路径"——**永不写回原子层**；其推理产物作为资源供未来扩展，但不干扰事实。

### 与外部 Side Index 的关键区分（外部视角贡献）
- **Side Index 本质 = 旁路存储 / AI 工作内存**：缓存、Embedding、RAG 召回索引、会话摘要——方便检索，以后拿回来继续回答。
- **本产品探索层 = 人类探索知识过程的长期资产**：不仅存结论，还存——人们如何提问、如何连证据、哪些路径最有价值、哪些地方反复暴露知识缺口、哪些推理值得未来验证。
- 命名建议**不要叫 Side Index**（太技术、易被理解成缓存 / Embedding / Vector），更贴切：**Exploration Memory / Exploration Layer / Collective Exploration Graph**。
- 真正创新点：把旁路层从"系统内部辅助索引"提升为"探索过程的长期资产"。

### 最有趣的推论：探索智能 ≠ 知识智能
- 假设百万用户都停在「王安石变法」→ 继续探索财政 / 官僚 / 教育 / 税制 → 系统识别出"此处存在强探索需求" → **演化的是探索引擎（主动推荐"很多人在这里继续探索财政制度"），而非修改知识本身**。
- 信任基石：**原子知识永不被旁路层自动修改；旁路层只影响探索，不影响事实。**

### Assistant 修正要点（避免过度兴奋）
- **区分技术基底与产品层**：vM81 Side Index（observe-only 存储机制）= 技术基底；Exploration Layer = 产品层概念，比基底宽。初版误将顶层直接等同 Side Index。
- **层内 schema 应存**：问题模式 · 高价值路径 · 知识缺口 · 需求信号 · 假设候选（非仅"结论"）。
- **消费端 = 探索引擎**（推荐 / 导航），演化的是探索而非事实。
- **诚实限定**：这是 North-Star 愿景，非已建架构；当前 0 用户，现实做法是先建单用户 / 会话级探索记忆、schema 预留可聚合，不假设已有集体数据。

### M82 核心开放问题（持久化方式，触及冻结红线）
- 探索记忆如何持久化 / 聚合而不破"无运行时 DB"红线？三选一（待 Founder 拍板）：
  - **A（推荐）git 版本化聚合**：会话级探索记忆存本地 / 会话，周期离线批合成"探索洞察"，以 git 版本化产物（非运行时 DB）入仓，作确定性推荐配置。
  - **B 周期批合成 → 固化成配置**：记忆只做输入，输出 = 主动推荐规则，规则变普通代码 / JSON 配置，记忆不长期驻留。
  - **C Freeze Gate 建库**：若确需跨用户聚合查询，走 ADR + 架构评审 + Founder 批准，引入受控存储（红线正式例外，非偷偷加）。

### 待 Founder 确认 / 升格时评审
