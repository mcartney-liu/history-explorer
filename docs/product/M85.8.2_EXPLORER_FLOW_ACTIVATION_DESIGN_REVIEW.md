## 1. 现有导航架构分析（只读）

### 1.1 NavNode 类型

```typescript
// frontend/src/components/navigation.ts
export type NavNode =
  | { type: 'topic'; topic: string; title: string }
  | { type: 'entity'; id: string; name: string }
```

**仅两种类型**：`topic` 和 `entity`。没有 `causal_object`。

### 1.2 App.tsx 渲染分支

```
current?.type === 'topic'  → SummaryPanel + MainEntityCard + RelationshipView + Timeline + ...
current?.type === 'entity' → EntityPage + RecommendationPanel + ContinueExploringPanel
!current && !packageSlug     → DiscoverPage + LandingPage（首页）
!current && packageSlug      → ExplorationPackagePage
loading                      → LoadingSkeleton
errorKind                    → ErrorCard
```

**CausalObjectDetailPage 当前未被任何分支渲染。**

### 1.3 fetchNode 数据加载

```typescript

  if (node.type === 'topic') {
    // fetch /explore/{topic} → setResult

    // fetch /entity/{id} → setEntityData
  }

```

**topic/entity 都依赖后端 API。CausalObject 数据当前在前端静态加载（JSON import）。**

### 1.4 探索流转方式

## 2. 设计方案

### 2.1 方案：最小接入 — 新增 `causal_object` NavNode 类型

#### NavNode 扩展

```typescript
export type NavNode =
  | { type: 'topic'; topic: string; title: string }
  | { type: 'entity'; id: string; name: string }
  | { type: 'causal_object'; objectId: string }  // ← M85.8.2 新增
```

#### nodeKey / eqNode 扩展

```typescript
export function nodeKey(node: NavNode): string {
  if (node.type === 'causal_object') return `causal_object:${node.objectId}`
  return node.type === 'topic' ? `topic:${node.topic}` : `entity:${node.id}`
}
```

#### App.tsx 渲染分支新增

```typescript
// 在 entity 分支之后，新增：
{!loading && !errorKind && current?.type === 'causal_object' && causalObjectData && (
  <CausalObjectDetailPage
    object={causalObjectData}
    objectTitleMap={causalObjectTitleMap}
    onEntityClick={(gid) => openEntity(gid)}
    onCausalObjectClick={(objectId) => navigateTo({ type: 'causal_object', objectId })}
    onBack={goBack}
  />
)}
```

#### App.tsx fetchNode 扩展

```typescript
async function fetchNode(node: NavNode, targetCursor: number) {
  if (node.type === 'causal_object') {
    // 静态数据加载 — 不依赖后端
    const obj = causalObjectsById[node.objectId]
    if (!obj) { setErrorKind('notfound'); return }
    setCausalObjectData(obj)
    setResult(null)
    setEntityData(null)
    setLoading(false)
    return
  }
  // ... 原有 topic/entity 逻辑不变
}
```

### 2.2 数据加载方式

```
CausalObject 数据：
  当前：data/causal_objects.json → frontend 静态 import
  方案：App.tsx 中 import + 构建 causalObjectsById Map

不需要新后端 API。
不需要新数据格式。
M85.2 数据集已冻结，直接使用。
```

### 2.3 objectTitleMap 构建

```typescript
// 从 cause_id + effect_id 推导人类可读标题
// 例如：co-004 → "秦制 → 三省六部"
const causalObjectTitleMap: Record<string, string> = Object.fromEntries(
  causalObjects.map(obj => {
    const causeName = entityNameByGid[obj.cause_id] ?? obj.cause_id
    const effectName = entityNameByGid[obj.effect_id] ?? obj.effect_id
    return [obj.id, `${causeName} → ${effectName}`]
  })
)
```

**注意**：`entityNameByGid` 需要从 KG 数据中解析 Entity 名称。当前 M85.8.1 中 related_entities 仍显示 GID 原始字符串。Phase 2 不解决所有名称解析问题——先用 GID 作为后备，Phase 3 再完善。

### 2.4 第一条探索链


## 4. 影响分析

### 4.1 影响的文件

| 文件 | 变更类型 | 说明 |
| --- | --- | --- |
| `navigation.ts` | 类型扩展 | NavNode + 'causal_object' |
| `useNavigationHistory.ts` | 无变更 | NavNode union 自动适配 |
| `App.tsx` | 新增渲染分支 + fetchNode 扩展 | causal_object 数据加载 + 渲染 |
| `CausalObjectDetailPage.tsx` | 无变更 | M85.8.1 已完成 |

### 4.2 不影响的部分

```
✅ topic 探索：不变（NavNode union 向后兼容）
✅ entity 探索：不变
✅ package 探索：不变
✅ search / discover：不变
✅ exploration persistence：不变（NavNode 序列化已支持任意字段）
✅ history / back / forward：不变（nodeKey + eqNode 扩展后自动适配）
```

### 4.3 风险评估

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| NavNode 扩展破坏序列化 | 低 | `nodeKey` 和 `eqNode` 使用 type 匹配，新增类型默认 fall through |
| CausalObject 数据加载失败 | 低 | 静态 import，无网络依赖 |
| entityNameByGid 未构建 | 中 | Phase 2a 先用 GID 作为后备标题 |
| 与现有 ExploreShell 布局冲突 | 低 | CausalObjectDetailPage 是独立全宽组件，不需要 Shell 的 workspace/companion/timelineStrip |

## 6. Architecture Decision

### 6.1 判定

```
READY FOR IMPLEMENTATION
```

### 6.2 理由

```
1. NavNode 扩展是向后兼容的（union type 新增分支不破坏现有逻辑）
2. CausalObject 数据是静态的（无网络依赖，零后端变更）
3. 现有渲染架构直接支持（causal_object 分支独立于 topic/entity）
4. M85.8.1 的 CausalObjectDetailPage 已经是完整组件
5. 探索流转逻辑（onCausalObjectClick → navigateTo）已有完整类型支持
```

### 6.3 一句话

```
M85.8.2 不是新增路由系统，而是在现有 NavNode 导航模型中新增一个分支。
CausalObjectDetailPage 从孤立组件变成可探索路径的一部分。
这是 History Explorer 第一个真正的 Explorer Loop。
```
