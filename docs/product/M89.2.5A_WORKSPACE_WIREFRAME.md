# M89.2.5A — Workspace Wireframe
### Product Wireframe / The Product Itself

> 模式：产品线框。Workspace 不是第三屏，Workspace 就是 History Explorer 本体。

---

## 零、理解驱动的 UI（非内容驱动）

```
错误（Content-driven）：
  左侧：法国大革命内容
  右侧：附一个理解地图

正确（Understanding-driven）：
  用户当前在理解什么？
        ↓
  为什么是这一步？
        ↓
  这里的内容帮助用户理解什么？
        ↓
  下一步是什么？
```

**理解状态决定内容。不是内容旁边放个地图。**

## 一、Visual Reading Flow（视觉阅读路径）

用户打开 Workspace，眼睛的移动顺序：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  ① 为什么现在来到这里？                                      │
│     "你刚理解了财政危机，因为财政导致三级会议，                │
│      所以下一步理解政治冲突。"                                │
│                          ↓                                   │
│  ② 我要理解什么？                                            │
│     "财政危机如何演变成政治危机。"                             │
│                          ↓                                   │
│  ③ 这一页的关键信息是什么？                                   │
│     "三级会议 / 国民议会 / 巴士底狱..."                       │
│                          ↓                                   │
│  ④ 我现在理解多少了？                                        │
│     理解地图 → ▰▰▱▱▱▱ 2/6                                   │
│                          ↓                                   │
│  ⑤ 然后呢？                                                 │
│     [继续探索：社会结构]  [换一个方向]                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**认知顺序（非 Layout 顺序）**：

```
① 为什么现在来到这里？     — Navigation Card
② 我要理解什么？           — 内容标题/核心问题
③ 关键信息                 — 内容主体
④ 我现在理解多少了？       — 理解地图
⑤ 然后呢？                 — 行动条
```

## 二、Information Hierarchy（信息层级）

```
Level 1 — 认知定位
  "为什么现在看这个？" / "这一步帮我理解什么？"
  字体最大、最突出
  来源：ExplorationAction.reason + narrativeHook

Level 2 — 内容核心
  当前实体/关系的关键描述
  来源：HistoricalKnowledgeProjection.entities

Level 3 — 理解状态
  覆盖进度 / 已理解维度 / 还缺维度
  来源：ExplorationState

Level 4 — 行动选择
  [继续探索] / [换一个方向]
  来源：ExplorationAction（用户决策）
```

## 四、关键变化：从左右分栏到垂直流

```
之前（Content-driven）：
┌──────────────┬───────────┐
│  左侧内容     │ 右侧地图   │  ← 并列关系，内容为主
└──────────────┴───────────┘

现在（Understanding-driven）：
┌──────────────────────────┐
│ ① 为什么这里？            │  ← 认知定位
├──────────────────────────┤
│ ② 理解什么？              │  ← 核心问题
├──────────────────────────┤
│ ③ 内容                    │  ← 信息
├──────────────────────────┤
│ ④ 理解地图                │  ← 状态
├──────────────────────────┤
│ ⑤ 下一步                  │  ← 行动
└──────────────────────────┘
```

垂直流 = 认知顺序 = 用户眼睛自然从上到下的阅读习惯。

理解地图不是"侧栏"，是流程中第④步——在理解了内容之后，看一眼"我现在在哪"。

## 七、实现优先级

```
P0 — ⑤②① 认知定位 + 核心问题 + 行动
    用户先看到"为什么"、再看到"理解什么"、最后看到"然后呢"
    消费：ExplorationAction + ExplorationState

P0 — ④ 理解地图
    覆盖进度 + 已理解/还缺维度 + 探索深度
    消费：ExplorationState

P1 — ③ 内容区
    当前实体/关系的关键信息
    消费：HistoricalKnowledgeProjection.entities

P2 — 状态转换
    初始 Orientation → 探索中 → Closure
```
