## 一、Renderer 的定位

```
ExplanationContext  →  ExplanationRenderer  →  ExplanationArtifact
        ↑                      ↑                      ↑
  结构化叙事上下文         语言渲染接口             结构化输出（非裸字符串）
```

Renderer 是语言表达系统，不是认知系统。它的唯一职责是把结构化叙事上下文转换为人类可读文本。

---

## 二、核心声明

> **LLM is a Renderer, not a Reasoner.**

| 组件                    | 职责        | 类比            |
| ----------------------- | ----------- | --------------- |
| CompanionPolicy         | 决定回答策略 | 大脑（判断）     |
| Decision                | 记录判断结果 | 记忆（不可变）   |
| ExplanationProjection   | 转换表达上下文 | 翻译（结构化）  |
| ExplanationRenderer     | 生成语言     | 嘴巴（表达）     |

## 三、Renderer Contract

### 3.1 接口定义

```typescript
interface ExplanationRenderer {
  render(
    context: ExplanationContext,
    config: RendererConfig
  ): Promise<ExplanationArtifact>
}
```

### 3.2 输入：ExplanationContext（M87.4.1）

```typescript
ExplanationContext {
  subject, intent, narrativeGoal,
  facts, references, forbiddenClaims,
  style, sourceDecisionId, sourcePolicyVersion, sourceReferences
}
```

### 3.3 输出：ExplanationArtifact（非裸字符串）

```typescript
interface ExplanationArtifact {
  artifactId: string              // 唯一标识
  sourceDecisionId: string        // 来源 Decision ID
  rendererVersion: string         // Renderer 版本
  modelProvider: string           // 模型提供方
  modelVersion: string            // 模型版本
  promptVersion: string           // Prompt 版本
  generatedAt: number             // 生成时间戳
  content: string                 // 最终文本
}
```

为什么不是裸 string：
- `sourceDecisionId` → 可回答"为什么 AI 这么说"
- `modelVersion + promptVersion` → 可回答"用哪个版本生成的"
- `artifactId` → 可回放、可对比

### 3.4 RendererConfig

```typescript
interface RendererConfig {
  modelProvider: string
  modelVersion: string
  promptVersion: string
  maxTokens?: number
  temperature?: number
}
```

## 四、Renderer 约束

### 允许 ✅

- 语言转换（结构化上下文 → 自然语言）
- 叙事组织（段落结构、语气调整）
- 格式化（Markdown、列表、强调）
- 多语言表达（按 style.language）
- 风格调整（按 style.tone / style.depth）

### 禁止 ❌

- 修改 ExplanationContext
- 修改 Decision（Renderer 不接触 Decision）
- 写 Memory / MemoryStore
- 写 Runtime State
- 创建新的 Recommendation
- 调用 Policy / Evaluator
- 生成新事实（只能基于 context.facts 表达）
- 声称 forbiddenClaims 中的内容
- 调用任何 Knowledge Graph / Search API

## 五、Renderer 与模型解耦

### 5.1 当前：NoopRenderer（默认）

M87.4.2 第一版提供 NoopRenderer——不调用任何 LLM，直接将 ExplanationContext 序列化为结构化文本。

目的：
- 验证 Renderer Contract 接口正确
- 验证 ExplanationContext 可渲染
- 验证 ExplanationArtifact 包含完整元数据
- 不绑定任何具体模型

### 5.2 未来：ModelRenderer（M87.4.3+）

```typescript
class OpenAIRenderer implements ExplanationRenderer {
  async render(context, config): Promise<ExplanationArtifact> {
    const prompt = buildPrompt(context, config)  // M87.4.3
    const response = await openai.chat.completions.create({ ... })
    return buildArtifact(context, config, response)
  }
}
```

Renderer 实现可替换——接口不变。
