# M89.2.8 — Understanding Workspace Prototype
### Visual Prototype / Experience Design

> 模式：体验原型。Workspace = Understanding Path 的可视化和交互空间。不写代码。

---

## 零、Workspace 的定义

> **Workspace 是 Understanding Path 的可视化和交互空间。**

它回答用户脑中的五个问题：
1. 我为什么看到这个？
2. 我正在理解什么？
3. 这个证据改变了什么？
4. 我的理解走到哪里？
5. 下一步为什么？

---

## 一、用户视觉焦点顺序（Attention Flow）

```
① 我为什么看到这个？           — 最顶部，最突出
    ↓
② 我正在理解什么？             — Starting Belief 的变化
    ↓
③ 这个证据改变了什么？          — Evidence 的核心内容
    ↓
④ 我的理解走到哪里？           — Understanding Path 可视化
    ↓
⑤ 下一步为什么？               — 底部行动
```

## 三、五个区域与产品抽象的对应

| 区域 | 回答的问题 | 消费的抽象 |
|------|-----------|-----------|
| ① Navigation | "为什么看到这个？" | ExplorationAction.reason + narrativeHook |
| ② Belief Change | "理解在怎么变？" | Evidence.beforeBelief → afterBelief |
| ③ Evidence | "这个证据是什么？" | Evidence.materials |
| ④ Path | "走到哪里了？" | UnderstandingPath（Nodes + Connections） |
| ⑤ Action | "下一步为什么？" | ExplorationAction + nextConnections |

```

全覆盖（6/6）：
  ●→●→●→●→●→●     显示完整因果链
```

---

## 五、交互规则

| 操作 | 行为 |
|------|------|
| 点击"继续探索" | 采纳当前 ExplorationAction → 加载新 Evidence → 更新 Path → 重新 evaluate |
| 点击"换一个方向" | 拒绝当前 Action → 保持 State → 重新 evaluate → 新建议 |
| Path 自动更新 | 每完成一个 Evidence，Path 的当前节点后移，连接线出现 |
| Closure 触发 | coverageRatio 达到阈值 → 区域①变为"原来如此"总结 |
