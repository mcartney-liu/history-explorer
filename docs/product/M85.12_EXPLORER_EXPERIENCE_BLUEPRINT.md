## Part 1 — First Explorer Journey

模拟一个完全不了解 History Explorer 的普通人（下称"他"）。描述其**认知旅程**，不描述页面。

### 1. Landing（初次抵达）
- **用户心理**
  - 想知道：这是什么？我能在这干嘛？会不会很学术、我看不懂？
  - 为什么点击：他还不知道，先观望。
  - 期待看到：一句人话，告诉我"这东西对我有什么用"。
- **产品回应**
  - 告诉我：这不是一份时间线，而是一个能和"历史"对话、慢慢看懂一件事为什么重要的地方。
  - 为什么让我看到这个：先消除"这是给学者用的数据库"的预设，建立"为我而存在"的安全感。
- **认知变化**
  - 从"不知道这和我有什么关系"
  - 到"哦，它是帮我理解历史的，而且不要求我先懂很多"。

### 2. 第一次选择（选定一个想理解的主题）
- **用户心理**
  - 想知道：我该从哪开始？有没有我本来就好奇的东西？
  - 为什么点击：他想起自己一直隐约好奇"一个文明怎么活下来又消失"。
  - 期待看到：被选中的主题被认真对待，而不是丢给我一堆资料。
- **产品回应**
  - 告诉我：你选的这条线，本质上是"一个文明如何兴起、繁荣又走向终结"——并预告接下来会陪我一步步看。
  - 为什么让我看到这个：把模糊好奇变成明确承诺，让他知道"路已经铺好"。
- **认知变化**
  - 从"我有个说不清的好奇"
  - 到"我知道我要理解的是：文明的生死"。

### 3. 第一次发现（撞见具体的人/事/文明）
- **用户心理**
  - 想知道：具体是谁、发生了什么？
  - 为什么点击：他顺着一个名字点进去，想看看"活生生的例子"。
  - 期待看到：不是定义，而是一个能被想象的真实片段。
- **产品回应**
  - 告诉我：这一个对象，是整条线上的关键一环，并解释"为什么它在这条线上"。
  - 为什么让我看到这个：让抽象主题落地为可感知的实在，确认"我真的看见了什么"。
- **认知变化**
  - 从"文明生死是个抽象词"
  - 到"原来它具体体现在某个人/某件事身上"。

### 4. 第一次理解（把碎片连成关系）
- **用户心理**
  - 想知道：这件事和刚才那个，为什么有关？它们连起来说明什么？
  - 为什么点击：他注意到两个对象之间的"为什么相关"，而不是被强迫跳转。
  - 期待看到：一个解释——"这两件事连起来，意味着文明的某条规律"。
- **产品回应**
  - 告诉我：这两个碎片不是随机并排，而是因果/影响上的相连，并点明"这帮你理解文明如何传承或断裂"。
  - 为什么让我看到这个：这是体验的核心转折——从"知道很多"到"看懂为什么在一起"。
- **认知变化**
  - 从"我看到了几个孤立事实"
  - 到"我看懂了它们为什么构成一条逻辑"。

### 5. 第一次产生新问题（理解催生好奇）
- **用户心理**
  - 想知道：那它后来又影响了什么？别的文明也这样吗？
  - 为什么点击：旧疑问闭合，新疑问自然升起，他想继续。
  - 期待看到：一个更聪明的问题被显形，而非被推回首页。
- **产品回应**
  - 告诉我：你刚刚理解的东西，自然会引出下一个问题——并把这个问题递回给他，作为下一轮探索的起点。
  - 为什么让我看到这个：完成"理解→新疑问"的螺旋，让探索可持续，而非在理解处封口。
- **认知变化**
  - 从"我懂了这条线"
  - 到"我还想懂更大的那张网"。

### 6. 第一次结束探索（带着结构离开）
- **用户心理**
  - 想知道：我今天走到哪了？我算看懂了吗？
  - 为什么点击：他累了，但想确认"没白来"。
  - 期待看到：一个对自己认知变化的回顾，而不是"你看了 8 个页面"。
- **产品回应**
  - 告诉我：你从"好奇文明生死"走到了"看懂一条传承逻辑，并提出了更大的问题"。可以停，也可以接着走。
  - 为什么让我看到这个：给休止点与成就感，让他敢随时回来，不恐惧迷失。
- **认知变化**
  - 从"我经历了一堆浏览"
  - 到"我完成了一轮理解，并带着新问题离开"。

## Part 2 — Explorer Loop Model

### Curiosity
1. **心理状态**：有模糊疑问，但说不清、不知从哪下手。
2. **产品应提供**：一个能接住"我随便想想"的入口，不要求先验知识。
3. **完成行为**：用户选定了一个他想理解的方向。
4. **失败情况**：入口用内部术语/指标吓退他，或只给"搜索框"把负担全甩给用户。

### Orientation
1. **心理状态**：选定后第一反应是"这大致是什么、我接下来会经历什么"。
2. **产品应提供**：用一句话承诺这段旅程的本质与走向。
3. **完成行为**：用户知道"我要理解 X，且路已铺好"。
4. **失败情况**：直接进入数据洪流，无任何定位，用户怀疑走错。

### Discovery
1. **心理状态**：想看见具体的、可想象的实在，确认"真的有这个"。
2. **产品应提供**：关键而具体的对象，并说明它为何在这条线上。
3. **完成行为**：用户感到"我撞见了真实的东西"。
4. **失败情况**：只给列表/代号/指标，无具体锚点，无"为什么在这"。

### Connection
1. **心理状态**：注意到碎片之间似乎有关，想知道"为什么相关"。
2. **产品应提供**：带语义的关系解释，而非仅并排或超链接。
3. **完成行为**：用户说出"原来 A 和 B 是这样连起来的"。
4. **失败情况**：无限横向跳转同密度数据，转圈无进展。

### Understanding
1. **心理状态**：碎片连成结构，想确认"我是不是看懂了"。
2. **产品应提供**：点明"这些在一起，意味着什么更大的理解"。
3. **完成行为**：用户产生"原来如此"的闭合感。
4. **失败情况**：信息更多但结构未现，用户仍不知"所以呢"。

### New Question
1. **心理状态**：旧疑问闭合，自然冒出更深层好奇。
2. **产品应提供**：把新疑问显形，递回为下一轮起点（非推荐，是用户自己的疑问）。
3. **完成行为**：用户主动想继续，带着更聪明的问题。
4. **失败情况**：体验在理解处封口，或算法替他决定"下一步该懂什么"。

### 回到 Curiosity
循环成立条件：每一次 Understanding 都自然孵化 New Question，而非终结。体验是螺旋，不是直线。

## Part 3 — Information Architecture Translation

把内部概念翻译为**用户理解概念**（完整词典）：

| 内部概念 | 用户理解概念 |
|---|---|
| Entity | 一个历史对象（具体的人、地方、事物、制度） |
| CausalObject | 一个改变历史走向的关键原因 |
| Relationship | 为什么两个历史对象有关 |
| Semantic Relationship | 为什么这些对象值得被放在一起理解 |
| Knowledge Graph | 文明里各种事物之间真实的相连网络 |
| Exploration Package | 一条预铺好的理解路线（围绕一个主题） |
| Seed Topic | 一个能展开成一整片理解的问题种子 |
| Exploration Goal | 走完这条路，你会看懂什么 |
| Relation Type | 这两个对象之间具体是"因果 / 影响 / 同源"中的哪一种 |
| Global Id | （对用户不可见，属系统寻址，不翻译、不暴露） |
| Understanding Seed | 一个帮你换个角度看历史的提问 |
| Companion / Historian | 随时能问的历史对话伙伴 |
| Workspace / 工作台 | 你走过的路、能随时回看续接的地方 |
| Timeline | 一件事在时间上前后发生了什么 |
| Causal Statement | 对"为什么发生"的一个可溯源的解释 |
| Validation | 这个解释为什么值得被相信 |

原则：凡是用户不需要知道"系统怎么存"的词，一律译为"它帮我理解什么"。

## Part 4 — Ideal Exploration Path

十条典型路径（每条：起始问题 → 理解节点 → 为何出现 → 最终理解）：

**路径 A — 一个国家如何治理巨大人口？**
- 起始：一个王朝怎么管这么多人而不崩？
- 节点：制度出现 → 官僚体系 → 科举 → 现代国家组织
- 为何出现：每步都是上一步"如何落地"的答案
- 最终理解：治理巨量人口的本质，是把"人"变成"可被理性组织的角色"。

**路径 B — 知识如何跨越千年保存？**
- 起始：没有互联网，古人怎么让思想活过千年？
- 节点：文字 → 教育 → 印刷 → 互联网
- 为何出现：每步都是"传播成本"的一次断崖式下降
- 最终理解：知识留存不是记性好，而是复制成本归零。

**路径 C — 一种信仰如何改变文明？**
- 起始：一个想法怎么变成千万人行为？
- 节点：教义 → 传播网络 → 政治结盟 → 文明价值观
- 为何出现：每步回答"观念如何获得现实力量"
- 最终理解：宗教改变文明，靠的是把抽象信念嵌入日常制度。

**路径 D — 一项技术如何重塑时代？**
- 起始：冶铁/造纸为什么是拐点？
- 节点：技术突破 → 军事/经济优势 → 社会结构变化 → 文明格局重写
- 为何出现：每步是"能力"转化为"权力"再转化为"结构"
- 最终理解：技术不是工具，是重新分配文明力量的杠杆。

**路径 E — 一片土地如何连起不同文明？**
- 起始：丝绸之路为什么重要？
- 节点：地理通道 → 贸易 → 文化混杂 → 文明互鉴
- 为何出现：每步是"连接"如何孕育"新东西"
- 最终理解：文明从不是孤岛，通道本身就是文明的一部分。

**路径 F — 一个人如何在时代中做选择？**
- 起始：历史人物面对巨变时怎么选？
- 节点：处境 → 约束 → 抉择 → 后果
- 为何出现：每步把抽象"历史"还原为具体"人"
- 最终理解：历史的方向，由无数个体的可理解选择叠成。

**路径 G — 一个文明为何走向终结？**
- 起始：辉煌的文明怎么没了？
- 节点：鼎盛 → 内部张力 → 外部冲击 → 解体/转型
- 为何出现：每步是"可持续"如何被侵蚀
- 最终理解：文明死亡很少因外敌，多因内部逻辑失效。

**路径 H — 一场事件如何改变世界走向？**
- 起始：某件事为什么是转折点？
- 节点：导火索 → 连锁反应 → 格局重置 → 长期遗产
- 为何出现：每步回答"局部如何撬动全局"
- 最终理解：转折不是偶然，是结构张力找出口。

**路径 I — 人类如何逐步理解"时间"？**
- 起始：古人怎么看待时间？
- 节点：历法 → 历史记录 → 周期观 → 线性进步观
- 为何出现：每步是"时间意识"的进化
- 最终理解：人对时间的理解，决定了文明如何规划自己。

**路径 J — 权力如何被约束？**
- 起始：巨大的权力怎么不被滥用？
- 节点：集权 → 制衡设计 → 法治 → 公共监督
- 为何出现：每步回答"信任如何制度化"
- 最终理解：文明成熟标志，是把权力关进可理解的结构。

## Part 5 — Navigation Philosophy

定义"用户为什么从 A 到 B"——禁止"点击即跳转"，每次移动必须携带三元：

**Explorer Navigation Contract（探索导航契约）**

每一次跳转必须显式回答：
- **来源（From）**：我从哪里来？—— 保留来路，用户随时可退回。
- **原因（Why）**：为什么此刻看到它？—— 不是"系统有这个"，而是"你刚才的理解自然引出它"。
- **价值（Value）**：它帮我理解什么？—— 指明这一步在认知地图上的位置。

示例（非页面，是契约实例）：
- 从"一个王朝" → 到"科举"：
  - 来源：你正在理解"如何治理巨量人口"。
  - 原因：治理需要选拔人，科举是这套选拔的成熟形态。
  - 价值：帮你理解"制度如何把人变成可组织的角色"。
- 从"看懂一条线" → 到"新问题"：
  - 来源：你刚闭合了"文明生死"的疑问。
  - 原因：理解总会自然引出更大的网。
  - 价值：把你的新疑问显形，作为下一轮起点。

契约失败信号：用户跳转后问"我怎么到这的""这和我刚才看的有什么关系"。

## Part 6 — Completion Model

**Cognitive Completion Model（认知完成模型）**

一次探索的结束，不由点击数/页数/时长定义，而由两个认知事件定义：

### "原来如此"何时产生？
当用户能用自己的话，把**至少两个孤立碎片连成一条他认可的因果/影响逻辑**，并意识到"这些在一起说明了某件更大的事"。
- 触发条件：Connection 阶段完成 + Understanding 阶段被点明。
- 产品此刻应给的，是"你刚才走通了"的确认，不是"你看了 X 个对象"。

### "那接下来呢？"何时自然产生？
当"原来如此"闭合的同时，用户脑中旧疑问消失、一个**更宽或更深的新疑问自动浮现**（如"别的文明也这样吗""它后来怎样了"）。
- 触发条件：Understanding → New Question 的自然孵化。
- 产品此刻应把新疑问递回，而非封口或推送。

### 结束的两类合法状态
1. **完成一轮，带着新问题离开**：认知结构已改变，且有明确续接点。这是健康结束。
2. **完成一轮，选择停在此处**：用户感到"我懂了这段"，有成就感与休止点。

两类都算"探索完成"。失败状态是：用户仍在转圈、仍不知"所以呢"、或被迫在伪终点（空 tab/即将推出）前停下。

## Part 7 — M86 Candidate Scope

仅做分层，不规划开发。每条标注违反的宪法条款（见 M85.11.3）。

### A 类 — 必须改变体验本质
- **A1 入口用主题名替代技术代号**：当前用里程碑代号与内部指标作卡片。违反 P01（不知为何在此）、P03（未翻译为人话）。
- **A2 每次跳转携带导航契约（来源/原因/价值）**：当前跳转丢失上下文。违反 P01、P09。
- **A3 关系必须带"为什么相关"语义**：当前仅列名字/超链接。违反 P08。
- **A4 理解完成需有闭环信号**：当前无"看懂了"的休止。违反 P06。
- **A5 核心价值（对话伙伴、理解种子）主动可见**：当前藏在收起面板/脚注。违反 P04。

### B 类 — 提升体验
- **B1 内部概念全量翻译为用户语言**：消除架构词裸露。违反 P03。
- **B2 提供"我在哪/去过哪/能回哪"的持续方向感**：违反 P09。
- **B3 探索允许暂停与回归**（退出到起点、回看轨迹）。违反 P10。
- **B4 入口用"人会好奇的问题"替代哲学化文案**：违反 P01、P12。
- **B5 无终止横向循环改为有认知目的地**：违反 P05。

### C 类 — 暂时观察
- **C1 时间线/地图等载体重写时是否守住八条宪法**：待 M86 形态验证，先观察不动作。
- **C2 AI Agent 介入时是否滑向"推荐驱动"**：红线监测，观察而非实现。
- **C3 移动端是否因空间限制重新隐藏核心价值**：观察是否重蹈 P04 覆辙。
- **C4 Video 载体如何承载"理解"而非"播放"**：观察其是否仍守 P02 认知推进优先。

## 最终产物定位

M85.12 Explorer Experience Blueprint 把 M85.11.3 的**不可妥协原则**，翻译为一个普通用户**15 分钟内能经历的一次完整文明理解**：

- 从 Landing 的安全感，到第一次选择、发现、理解、新问题、带着结构离开；
- 抽象为可循环的 Explorer Loop；
- 把内部三层架构译为用户语言；
- 用十条路径证明"理解过程"真实可设计；
- 用 Navigation Contract 约束每一次移动的意义；
- 用 Cognitive Completion Model 定义"何时算懂"。

它未写一行代码，却已规定：未来无论 Timeline / Map / Agent / Video / Mobile 如何重做，**八条核心宪法不可议价**。History Explorer 由此从"拥有历史知识能力的平台"，定义为"让人自然理解文明的探索系统"。

**完成 M85.12，方有资格进入 M86。**
