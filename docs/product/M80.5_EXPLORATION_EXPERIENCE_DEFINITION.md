# M80.5 — Exploration Experience Definition

> **Product Gate（产品闸门），非 Engineering Milestone。**
> 本文件不写代码、不进 `freeze-check`、不修改 `domain/` 或 `backend/`。
> 它输出的是后续 M81 / M82 / M83 共同引用的**产品母文档**。

## 0. 定位声明：History Explorer 从工程转向产品的分界线

History Explorer 此前的推进方式是：

```
能力建设 → 架构冻结 → 功能实现
```

本里程碑起，推进方式变为：

```
用户价值定义 → 探索行为设计 → 体验验证 → 能力实现
```

**M80.5 不是"多加一个里程碑"，而是项目从工程项目转向产品项目的分界线。**
它要回答的不是"我们能展示什么"，而是"用户为什么探索、为什么继续、为什么回来"。

## 1. First 5 Minutes（产品 North Star）

> 这不是验收指标，是产品的北极星。M81/M82 的所有工程产出，最终要用这一节反验。
> 标注：这是 North Star，不是 KPI 清单——它定义方向，不定义逐项打分。

**问题**：用户第一次成功是什么？

**一句话价值陈述（产品价值锚）**：
> History Explorer 让一个历史门外汉，在第一次进入的 5 分钟内，不是"看到一堆知识"，而是**亲自走通一段历史理解**——他看懂了一个变化为何发生，撞见了一个跨时空的关联，并因此产生一个属于自己的下一步问题。

**5 分钟成功的可观察信号**（3 个，用于 M81a 原型反验，非考核打分）：
1. **理解一个历史变化**：用户能用自己的话复述"秦为什么能统一"（而非仅看到卡片）。例：5 分钟后他可以说出"郡县制降低了地方割据风险，所以秦能整合六国"。
2. **发现一个跨文明关联**：用户在界面中主动点开一个非当前文明的对照节点。例：从"秦统一"跳到"同期罗马共和国转帝国"，并停留 > 某阈值。
3. **产生并点击一个下一步未知问题**：用户发出或在推荐中点击一个"我还想知道…"类动作。例：点击"为什么汉承秦制？"作为 Trail 的未完成问题留存。

**首屏剧本（参考路径，非强制）**：
```
用户："中国古代文明"
  → 系统给初始理解锚点（秦统一六国的因果骨架，非罗列）
  → 用户看到一条关系链：秦统一 → 中央集权 → 汉承秦制
  → 系统提示跨文明关联：同期罗马的治理差异（SEMANTIC_MATCH 信号）
  → 用户点击罗马节点，发现"东西方治理分岔"
  → 系统留下未完成问题："为什么汉延续而非推翻秦制？"
  → 用户关闭，Trail 保存该路径 + 未完成问题
```
> 此剧本是 North Star 的具象化，用于 M81a 原型验证靶子；不要求每次都相同，但要求每次都能命中上述 3 个信号。

## 2. Exploration Loop

**问题**：用户为什么继续？

**行为链（含闭环）**：

```
进入主题
  ↓
获得上下文（初始理解）
  ↓
发现关联 / 异常
  ↓
提出问题
  ↓
探索下一节点
  ↓
形成个人路径（Trail）
  ↓
留下未完成问题
  ↓
回来继续（回访闭环）
```

**每一步的"为什么点下一个"动机机制**：

| 步骤 | 用户动作 | 内在动机（为什么继续） | 系统职责 |
|---|---|---|---|
| 进入主题 | 选/搜一个文明或事件 | 我有初始好奇 | 给可理解的入口，不抛全库 |
| 获得上下文 | 看初始理解锚点 | "原来如此，但…"的空白感 | 用因果骨架而非罗列满足初懂，同时制造缺口 |
| 发现关联/异常 | 看到跨节点 Signal | 认知失调驱动探索（这俩为啥像/不像？） | 主动暴露 SEMANTIC_MATCH / PARTIAL_HINT / GAP |
| 提出问题 | 形成"我还想知道" | 缺口变问题，问题变目标 | 把问题固化为 Trail 的未完成项 |
| 探索下一节点 | 点击关联/推荐 | 目标导向，非漫逛 | Guide 类推荐给"下一跳"，不替用户走 |
| 形成个人路径 | 路径沉淀 | "这是我的"，所有权感 | Trail 实时记录路径/上下文 |
| 留下未完成问题 | 暂离 | 悬念留存，非结束 | 未完成问题显式留存 |
| 回来继续 | 重开 Trail | 回访钩子：我的探索没结束 | Trail 恢复状态，从未完成问题续接 |

**回访闭环如何成立**：
- 依赖 **Personal Exploration Trail**（M63-B / M83）保存：路径、上下文、未完成问题、下一步方向。
- 回访不是"回到收藏"，是"回到我未走完的探索"——未完成问题即回访锚。
- 这与 ChatGPT 聊天"刷新即丢失"的痛点同源，Trail 是其产品级解药。

**单次会话 vs 长期留存被同一 Loop 覆盖**：
- 单次会话：进入→理解→关联→问题→探索→路径，在 5 分钟内完成 North Star。
- 长期留存：路径+未完成问题跨会话存续，下次从"未完成"续接，Loop 不重置而是续转。
- 因此 Loop 既是首体验引擎，也是回访引擎；M81a 验证单次，M86 Pilot 验证长期。

## 3. Exploration Object Model

> **探索对象模型是用户认知层，不是知识结构层。**
> Exploration Object Model is a semantic presentation layer, NOT a knowledge ontology layer.
> 它不新增 Entity / Relationship，不触碰冻结红线（ENTITY=8 / RELATIONSHIP=18）。

### 3.1 Cognitive Mapping（认知映射）

**定义**：Cognitive Mapping 是 Graph World（存储契约）到 Human Exploration World（用户心智）的**一对一语义投影规则**。它规定每一个底层对象在被呈现前，必须翻译成用户能直接理解的"历史概念"，且翻译过程不新增、不合并、不改义任何底层对象。

**映射规则表（投影，非扩展）**：

| 数据库世界（存储契约，冻结） | 用户世界（心智概念） | 投影约束 |
| --- | --- | --- |
| Entity（8 类之一） | 一个"可理解的历史主体"：人物 / 事件 / 文明 / 思想 / 技术 / 制度 / 地点 / 文本 | 仅做语义命名，不拆分 Entity，不新增第 9 类 |
| Relationship（18 类之一） | 一条"历史作用力"：冲突 / 影响 / 继承 / 因果 / 同源 / 对照… | 仅呈现关系*含义*，不暴露 `RELATION_TYPE` 枚举值 |
| Signal | 一个"探索提示"：已确认关联 / 可能相关 / 已知未知 | 把引擎内部信号翻译为用户可行动的"下一步线索" |
| CausalStatement | 一个"变化解释"：为何发生 / 导致什么 / 通过什么机制 | 把因果三元组翻译为自然语言句式，不暴露主语谓语句法 |

**映射不变量**：
- 投影是**无损下采样**——用户看到的概念数量 ≤ 底层对象数量，绝不反向膨胀（不因为"好展示"就新建展示型 Entity）。
- 任何 Signal 的呈现都必须可追溯到其底层 Evidence（Entity / Relationship / CausalStatement），不可凭空呈现"推荐"。
- Cognitive Mapping 只管"对象叫什么、是什么意思"，不管"点开之后怎样"（后者归 3.3 Interaction Contract）。

### 3.2 Presentation Semantics（呈现语义）

**定义**：Presentation Semantics 回答——**用户看到的不是数据库对象，而是什么？** 它规定每一类对象在用户体验中的*意义角色*，使前端呈现时退化不成"图谱浏览器"（即：不是节点+边的 CRUD 视图，而是意义叙事视图）。

**每类对象在用户世界中的意义**：

- **Entity → "我正在理解的主角"**
  用户看到的不是一个带属性的节点，而是一个"此刻历史舞台上的角色"。呈现重点是它的*历史身份与它在叙事中的位置*，而非字段清单。例：不是 `Entity: Qin, type=CIVILIZATION, founded=-221`，而是"秦——一个用郡县制整合六国的中央集权文明"。

- **Relationship → "一段历史作用力，带着为什么"**
  用户看到的不是边，而是"这件事如何作用于那件事"。呈现重点是*关系含义 + 成立理由*，边本身隐入背景。例：不是 `RELATION_TYPE: CAUSED_BY`，而是"秦统一六国 ↓ 形成了延续两千年的中央集权制度"。

- **Signal → "系统递给我的一张下一步线索卡"**
  用户看到的不是算法输出，而是"这里有个值得你去看的东西"。Signal 的呈现必须带*行动暗示*，使它能直接驱动 Loop 的'发现关联/异常'步。三种语义：
  - `SEMANTIC_MATCH` → "这两个东西其实是一回事的不同面向"（已确认关联）
  - `PARTIAL_HINT` → "这个可能和你正在看的有关，但不确定"（待探索）
  - `GAP` → "这里有一片你还没触及的未知"（制造缺口，诱发问题）

- **CausalStatement → "一个历史变化的故事句式"**
  用户看到的不是三元组 `(cause, mechanism, effect)`，而是一句"为什么这样、如何发生、导致什么"的自然语言解释。呈现重点是*可复述性*——用户 5 分钟后能用自己的话重说（对应 North Star 信号 1）。

**呈现红线（防止退化为图谱浏览器）**：
- 禁止在一级视图展示 `RELATION_TYPE` / `ENTITY_TYPE` 等枚举原值。
- 禁止把 Signal 呈现为"相似度 0.83"类机器分数；必须翻译为线索语义。
- 禁止默认铺开全库节点；呈现永远从"当前探索上下文"出发（与 Loop 的'获得上下文'步一致）。

### 3.3 Interaction Contract（交互契约）

> 防止前端拿到数据后自由发挥成"知识图谱浏览器"。
> 本契约定义每个认知对象出现后，用户**可以且应当**做什么，并强制每条交互回到 Exploration Loop 的某一步，使交互始终服务于"继续探索"而非"浏览数据"。

**通用对象级交互原语（五类，全对象适用）**：

| 交互原语 | 语义 | 在 Loop 中的归属 |
| --- | --- | --- |
| 点击（Tap） | 选中对象，展开其呈现语义（3.2）详情，不离开当前上下文 | 获得上下文 / 发现关联 |
| 展开（Expand） | 揭示该对象指向的下游对象（因果链、关联 Signal），制造下一步缺口 | 发现关联/异常 |
| 深入（Drill） | 进入该对象的子叙事（前因/后果/机制/对照），形成"下一跳" | 探索下一节点 |
| 返回（Back） | 回到上一探索层级，**保留**已展开的上下文与路径 | 形成个人路径（Trail 不丢） |
| Trail 记录（Record） | 任何点击/展开/深入动作自动写入 Personal Exploration Trail（路径+上下文），不显式"保存" | 形成个人路径 / 留下未完成问题 |

**分对象交互规则（在通用原语上叠加）**：

- **Entity**
  - 点击：展开其历史身份与叙事位置（3.2 Entity 语义）。
  - 展开：显示它参与的 Relationship 与 Signal（"它和谁发生作用力"）。
  - 深入：进入其前因/后果/同时代对照。
  - 返回：回到来源上下文，Trail 记录"我曾理解过这个主角"。
  - 契约约束：Entity 不可被"编辑/删除"（只读呈现），防止前端误做成 CRUD。

- **Relationship**
  - 点击：显示"为什么连接 + 证据是什么"（呈现语义中的关系含义）。
  - 展开：揭示支撑该关系的 CausalStatement 与 Source Evidence。
  - 深入：跳到关系另一端 Entity，形成 Loop 的'探索下一节点'。
  - 返回：回到关系起点 Entity 的上下文。
  - Trail 记录：记录"我理解了一条作用力及其理由"。

- **Signal**
  - 点击（SEMANTIC_MATCH）：直接深入已确认关联对象。
  - 展开（PARTIAL_HINT）：暴露"为什么可能相关"的弱证据，交由用户判断。
  - 深入（GAP）：进入未知区域，触发 Loop 的'提出问题'（缺口变问题）。
  - 返回：从线索回到原探索上下文。
  - Trail 记录：Signal 被点击即记为"用户感兴趣的关联方向"，作为回访锚。

- **CausalStatement**
  - 点击：显示完整故事句式（为何发生/如何/导致什么）。
  - 展开：揭示机制细节与证据来源 Entity。
  - 深入：跳到后果 Entity，驱动'探索下一节点'。
  - 返回：回到 cause Entity 上下文。
  - Trail 记录：记录"用户理解了一个变化解释"，可反验 North Star 信号 1。

**契约闭环校验（防止退化）**：
- 每条交互终态必须可映射回 Loop 八步之一；若某交互只产生"看了数据"而无 Loop 进展，视为契约违约（前端设计需回炉）。
- `返回` 永远伴随 Trail 保留；不存在"返回即丢失"的路径（对标 ChatGPT 刷新即丢的痛点）。
- 所有对象的写操作（除 Trail 自身记录外）在本契约中**不存在**——Exploration Object Model 是只读探索层，写只发生在 Trail（M83）。

## 4. Exploration Shell

**问题**：空间如何承载探索？

**约束前提**：M63-B 已定 **Personal Exploration Trail（个人探索轨迹）**，非收藏夹、非存档。

> Personal Exploration Trail:
> A persistent exploration trail that preserves user's discovered paths, context, unresolved questions and future exploration directions.
> 持续保存用户历史探索路径、上下文、未完成问题和下一步方向的个人探索轨迹。

---

### 4.1 Shell 的产品定义（区别于三类常见误读）

**Exploration Shell** 是承载用户"正在发生的探索"的产品空间，不是一个静态容器。它的本质区别于以下三者：

| 误读模型 | 它是什么 | Shell 为何不同 |
| --- | --- | --- |
| 收藏夹（Bookmark） | 用户主动"存"的离散条目，无顺序、无上下文 | Shell 不要求用户"存"；路径与上下文由探索行为自动沉淀，且条目间有因果/叙事顺序 |
| 浏览历史（History） | 按时间罗列去过的页面，回到任一点即脱离原叙事 | Shell 回到任一点会**恢复该点的探索上下文**，而非孤立重开；且只保留"有探索意义的"路径，非全量点击流 |
| 百科目录（TOC） | 预先编排的静态知识结构，用户在其中导航 | Shell 的结构由**用户自己的探索**生成，不是系统预先摆好的目录；同一底层 KG，千人千面 |

**一句话定义**：
> Exploration Shell 是一个"活着的探索现场"——它呈现用户走到哪、为什么走到这、还差什么没走完；它不是仓库，是用户历史理解的**进行时态**。

### 4.2 Personal Exploration Trail 如何承载探索状态

Trail 是 Shell 的持久化内核（M63-B / 落地在 M83，本处只定义其*承载的语义*，不实现）。它承载四类状态：

1. **路径（Path）**：用户实际走过的对象序列（Entity/Relationship/Signal/CausalStatement 的呈现语义实例），带顺序。
2. **上下文（Context）**：每一步所处的"为什么在看这个"——来源问题、上游因果、触发 Signal。
3. **未完成问题（Unresolved Questions）**：探索中生成的、尚未走通的"我还想知道"，是回访锚。
4. **下一步方向（Future Directions）**：系统基于当前 Trail 推导的可续接线索（非强制推荐，是候选）。

Trail 的关键性质：**写入是探索的副产物，不是显式动作**（对应 3.3 Interaction Contract 的 Record 原语）。用户"返回"不丢 Trail，"暂离"不丢 Trail，"重开"从未完成问题续接。

### 4.3 三层模型：Current State / Trail / Open Threads

Shell 在逻辑上由三层构成，三者都是*状态*而非*页面*（本处不设计 UI 组件）：

- **Current Exploration State（当前探索态）**
  用户此刻所在的对象 + 其展开上下文 + 当前未决问题。是 Shell 的"焦点层"，每步交互（3.3 原语）改写它。它是易失的、随交互流动的。

- **Personal Exploration Trail（个人探索轨迹）**
  上述所有 Current State 的历史沉淀序列，持久化。是 Shell 的"记忆层"，记录"我来过哪、怎么来的"。

- **Open Exploration Threads（开放探索线程）**
  从 Trail 中抽出的、尚未闭合的"未完成问题 + 其关联路径"集合。是 Shell 的"悬念层"，每个 Thread = 一个可独立续接的探索线。用户可同时存在多个 Open Threads（例如"秦制为什么被汉继承"与"罗马为何未走中央集权"两条并行）。

**三层关系**：
```
Current State  ──(交互沉淀)──▶  Trail  ──(抽取未闭合项)──▶  Open Threads
     ▲                                                              │
     └──────────────(重开/续接某 Thread)───────────────────────────┘
```
即：当前态流动进 Trail；Trail 孕育 Open Threads；用户从任一 Thread 重开，又生成新的 Current State。Shell 因此不是"一个页面"，而是这三层的持续循环。

### 4.4 Shell 与 Exploration Loop 的映射关系

Shell 是 Loop 的**空间载体**，不是 Loop 的输入或输出。Loop 八步在 Shell 三层中的落点：

| Loop 步骤 | 落在 Shell 的哪层 |
| --- | --- |
| 进入主题 | Current State 初始化 |
| 获得上下文 | Current State 填充上下文 |
| 发现关联/异常 | Current State 暴露 Signal；可能生成 Open Thread 候选 |
| 提出问题 | 写入 Trail 的"未完成问题"；显式化为 Open Thread |
| 探索下一节点 | Current State 转移；Trail 追加路径 |
| 形成个人路径 | Trail 固化本段路径 |
| 留下未完成问题 | Open Thread 保持开启（暂离） |
| 回来继续 | 从某 Open Thread 恢复 → 重建 Current State |

结论：**Shell 是 Loop 的"可视化时态"**——Loop 负责"用户为什么继续"，Shell 负责"这个继续在空间中如何被看见、被留存、被续接"。

### 4.5 Shell 设计红线

防止 Shell 在实现（M83）时滑回"收藏夹/历史/目录"三误读，立以下红线：

1. **禁止"显式保存"动作**：Trail 必须由探索行为自动沉淀，不得出现"保存到收藏夹"类按钮（否则退回收藏夹模型）。
2. **禁止全量点击流**：Shell 只呈现有探索意义的路径，不罗列每一次点击（否则退回浏览历史）。
3. **禁止预编排结构**：Shell 的呈现顺序来自用户 Trail，不得用系统预设目录覆盖（否则退回百科目录）。
4. **禁止"返回即丢失"**：任何返回/暂离必须保留 Current State 对应的 Trail 与 Open Threads（对标 ChatGPT 刷新即丢痛点）。
5. **禁止在 Shell 内做写操作**：Shell 是只读探索层；除 Trail 自身记录外，用户不可在 Shell 中编辑/删除底层对象（与 3.3 契约闭环校验一致）。
6. **禁止引入新本体承载 Shell**：Shell 三层状态全部建立在既有的 Entity/Relationship/Signal/CausalStatement 呈现语义之上，**不新增 Entity / Relationship 类型**，不触碰 8/18 冻结边界。

> 本节约产品定义。Trail 的持久化机制、Open Threads 的存储结构、Shell 的具体呈现，归 M83 实现，不在 Product Gate 范围。

## 5. AI Role Discovery（AI 需求点记录，非决策）

### 5.0 定位声明

**AI Role Discovery 的目的不是决定 AI 形态。**

本节回答：
> "用户探索过程中，哪些瞬间需要智能辅助？"

而不是：
> "我们应该做什么 AI 产品？"

AI 形态选择（**Companion / Toolbox**）延迟到 **M83 前**，依据本节记录的需求点与 M81a Prototype 的真实验证结果共同决定。本节约是需求发现（Discovery），不是架构设计、不是产品方案、不是选型。

### 5.1 AI 需求来源映射（Loop → AI Opportunity）

基于第2节 Exploration Loop 八步骤，逐步识别"用户在哪里产生 AI 需求"与"没有 AI 会在哪受阻"。每点只定义需求，不定义实现。

**1. 进入主题**
- 用户问题：从全库海量主题中，我该从哪开始？初访者容易空茫。
- AI 潜在价值：基于用户初始表达，建议一个可理解的入口主题与初始方向。
- 无 AI 受阻点：用户面对空白入口，缺乏"第一脚踩哪"的引导，易放弃或漫逛。

**2. 获得上下文（初始理解）**
- 用户问题：背景太厚、关系太密，我看不懂"为什么这样"。
- AI 潜在价值：把复杂关系与因果用自然语言简化解释（解释既有的 CausalStatement）。
- 无 AI 受阻点：用户卡在"看懂"门槛，North Star 信号1（用自己的话复述变化）难以达成。

**3. 发现关联/异常**
- 用户问题：哪些跨文明/跨节点其实相关？我看不见隐藏线索。
- AI 潜在价值：主动提示跨文明连接、暴露隐藏关系、推荐下一探索方向（基于既有 Signal 重组呈现）。
- 无 AI 受阻点：用户只能看到显式关系，错过 SEMANTIC_MATCH / GAP 类弱信号，Loop 的"发现"步弱化。

**4. 提出问题**
- 用户问题：我的好奇是自然语言，系统怎么接住？
- AI 潜在价值：理解用户自然语言问题，将其转译为可探索意图（对应某个 Entity/Relationship/CausalStatement）。
- 无 AI 受阻点：用户问题无法被结构化承接，"缺口变问题"断裂，Trail 的未完成问题无法自然生成。

**5. 探索下一节点**
- 用户问题：点完这个，我该去哪？容易迷路或绕回。
- AI 潜在价值：基于当前 Trail 给出"下一跳"路径建议，帮助规避迷失。
- 无 AI 受阻点：用户在对象海中失去方向感，探索变成随机游走，Loop 的"探索下一节点"低效。

**6. 形成个人 Trail**
- 用户问题：我刚走完一段，但说不清自己探索了什么。
- AI 潜在价值：总结当前探索脉络，帮助恢复/固化上下文。
- 无 AI 受阻点：Trail 有路径但缺"叙事总结"，用户回访时难以快速接回状态。

**7. 留存 / 回访**
- 用户问题：隔几天回来，我之前卡在哪、想看什么？
- AI 潜在价值：从 Open Threads 恢复未完成探索，提醒此前兴趣方向。
- 无 AI 受阻点：回访靠用户自己回忆，未完成问题易被遗忘，Loop 的"回来继续"闭环松动。

> 小结：AI 需求分布在 Loop 的 7 个步骤（"留下未完成问题"本身是 Trail 状态沉淀，无需 AI 中介）。所有需求均围绕"降低理解成本 / 承接意图 / 防迷失 / 助回访"，而非替代探索。

### 5.2 AI 潜在职责分类（非产品选型）

沿用既有四类标签，仅作需求归类，**不代表最终产品形态**：

**Interpreter（解释者）**
1. 用户痛点：看不懂复杂关系与因果，卡在"为什么"。
2. 对应 Loop 阶段：获得上下文（步骤2）、发现关联（步骤3）。
3. AI 提供价值：把既有 Relationship / CausalStatement 翻译为可理解的自然语言解释。
4. 当前实现范围：**不进入 M80.5**；实现归 M83.5（按 v3.1 计划）。

**Guide（向导）**
1. 用户痛点：不知道下一步探索什么，错失关联。
2. 对应 Loop 阶段：发现关联（步骤3）、探索下一节点（步骤5）。
3. AI 提供价值：基于既有 Signal 与 Trail，推荐"下一跳"方向。
4. 当前实现范围：**不进入 M80.5**；实现归 M83.5。

**Analyst（分析者）**
1. 用户痛点：想比较不同文明/事件但缺乏对照框架。
2. 对应 Loop 阶段：发现关联（步骤3）、提出问题（步骤4）。
3. AI 提供价值：基于事实层对象做对照性重组呈现（如秦 vs 罗马治理）。
4. 当前实现范围：**不进入 M80.5**；实现归 M83.5。

**Navigator（导航者）**
1. 用户痛点：从当前位置到目标理解节点，路径不清易迷失。
2. 对应 Loop 阶段：进入主题（步骤1）、探索下一节点（步骤5）、留存/回访（步骤7）。
3. AI 提供价值：规划可达路径、恢复上下文、提醒兴趣方向。
4. 当前实现范围：**不进入 M80.5**；实现归 M83.5。

> 明确：以上四类是**需求标签**，用于归类 Loop 中的智能辅助诉求；它们如何打包进 Companion 或 Toolbox，是 M83 的前期决策，不在本节裁定。

### 5.3 AI 与现有数据契约关系

**KG（事实层，冻结边界内）提供**：
- 事实（fact）
- Entity（8 类，冻结）
- Relationship（18 类，冻结）
- Signal（关联/线索）
- CausalStatement（因果解释）

**AI（解释层）提供**：
- 解释（interpret）：把事实翻成可懂语言
- 重组（recompose）：按用户上下文重新排列呈现
- 引导理解（guide）：指向值得探索的方向

**AI 绝不**：
- 创造事实（no fact invention）
- 修改知识结构（no schema mutation）
- 扩展 Ontology（不新增 Entity / Relationship 类型）

**结论**：
> **AI 是 Exploration Layer（探索层），不是 Knowledge Layer（知识层）。**
> 一切 AI 输出必须可回溯到 KG 中的既有对象，否则不可呈现（与 3.3 契约闭环校验、M74 Trust Boundary 一致）。

### 5.4 AI 插入原则

为 M83.5 实现立产品级约束（本处只定义原则，不实现）：

1. **按需出现**：AI 出现在用户遇到理解成本的位置，而不是所有页面常驻。
2. **优先解释已有**：AI 优先解释既有关系与因果，而不是主动生成未知事实。
3. **可回溯**：AI 输出必须能回溯到已有数据对象（Entity/Relationship/Signal/CausalStatement），无法溯源的输出禁止呈现。
4. **不替代探索**：AI 只降低探索门槛，不替用户走完路径；"下一跳"是建议不是代劳。
5. **不越界**：AI 绝不写入 KG、绝不改动 8/18 边界；其所有产物属于 Exploration Layer 临时态。
