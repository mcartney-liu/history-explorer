# M83.3 Explorer Validation Protocol Freeze

> **阶段**：M83.3 Explorer Validation Protocol Freeze — 实验方法冻结
> **模式**：严格只读 | **日期**：2026-08-05
> **基线**：M83.1 Instrumentation Acceptance + M83.2 Content Selection Freeze
> **依据**：M83 Governance Contract

---

## Executive Summary

M83.4 的验证不是 "看看用户感觉如何"，而是一个**有预设假设的产品实验**。

核心假设：**CausalStatement 会改变 Explorer 的探索行为** — 具体表现为：
- Explorer 看到 CS 后，探索深度增加
- Explorer 主动阅读 CS 内容（不只是扫一眼）
- Explorer 沿 CS 暗示的因果方向继续探索
- CS 理由比模板 reason 更有效地引导下一步

本 Protocol 冻结：验证目标、测试场景、指标、成功标准、样本量、Session 流程。

---

## 1. Validation Goal

### 1.1 核心问题

```
Explorer 是否理解并使用 CausalStatement？
```

拆分为 3 个子问题：

| # | 子问题 | 验证方式 |
| --- | --- | --- |
| Q1 | Explorer 是否**看到**了 CS？ | `cs_card_view` 事件 + Session Review 确认 |
| Q2 | Explorer 是否**理解**了 CS 的内容？ | Session Review 口头复述 + `cs_card_expand` 事件 |
| Q3 | Explorer 的**行为**是否因 CS 而改变？ | `cs_follow_entity` / `cs_guide_next` 事件 + 探索深度对比 |

### 1.2 核心假设

```
H0（零假设）：CausalStatement 不改变 Explorer 的探索行为
H1（备择假设）：CausalStatement 改变 Explorer 的探索行为

M83.4 的目标：拒绝 H0，接受 H1
```

---

## 2. Test Scenario

### 2.1 Session 结构

每个 Explorer Session 包含 3 个阶段：

```
Phase A — 首次探索（无 CS 基线）
  任务：自由探索一个主题（如 "文官"）
  目的：建立无 CS 时的探索行为基线
  时长：5-8 分钟

Phase B — 引导探索（有 CS）
  任务：通过 GuidePanel 引导进入含 CS 的路径
  目的：观察 CS 出现后的行为变化
  时长：8-12 分钟

Phase C — 自由继续
  任务：继续自由探索
  目的：观察 CS 体验后是否产生持续的行为改变
  时长：5 分钟
```

### 2.2 Session 流程

```
1. 开场（2 min）
   - 介绍 History Explorer 是什么
   - 不提及 "因果解释" / "CausalStatement" / "为什么"
   - 目的：避免引导 Explorer 关注 CS

2. Phase A（5-8 min）
   - 任务："请探索一个你感兴趣的历史主题"
   - 不提供任何关于 CS 的提示
   - 目的：采集无 CS 时的探索基线

3. Phase B（8-12 min）
   - 任务："请打开 '中国历史' 探索包"
   - Package 中包含 CS
   - 观察 Explorer 是否注意到 CS Card
   - 如果 Explorer 忽略了 CS，观察员不提示

4. Phase C（5 min）
   - 任务："请继续自由探索"
   - 观察 CS 体验后行为是否改变

5. 复盘访谈（10-15 min）
   - "你注意到路径上有一段解释吗？"
   - "你能用自己的话复述一下那个解释吗？"
   - "看完那个解释后，你想继续了解什么？"
   - "你觉得这个解释可靠吗？为什么？"
```

## 3. Metrics

### 3.1 事件 → 指标映射

| 指标 | 事件 | 计算 | 采集阶段 |
| --- | --- | --- | --- |
| **View Rate** | `cs_card_view` | 含 CS 的路径中，CS Card 被渲染的次数 | Phase B |
| **Expand Rate** | `cs_card_expand` / `cs_card_view` | 看到 CS 后主动点击/交互的比例 | Phase B |
| **Causal Conversion Rate** | (`cs_follow_entity` \| `cs_guide_next`) after `cs_card_view` / `cs_card_view` | CS 触发后续探索的比例 | Phase B + C |
| **Guide Follow-through** | `cs_guide_next` after `cs_card_view` / `cs_card_view` | CS 理由引导下一步的比例 | Phase B |
| **Evidence Open Rate** | `cs_evidence_open` / `cs_card_view` | 打开证据来源的比例 | Phase B |
| **Exploration Depth** | `open_entity` 序列长度（含 CS vs 不含 CS 的 session 对比） | 含 CS 的 session 中探索步数 | Phase A vs B |

### 3.2 定性指标（Session Review）

| 指标 | 采集方式 | 评分标准 |
| --- | --- | --- |
| **Mechanism Recall** | 复盘访谈 — "你能用自己的话复述这个解释吗？" | 3=完整复述，2=部分复述，1=不能复述，0=没注意到 |
| **Exploration Intent** | 复盘访谈 — "看完解释后你想继续了解什么？" | 3=明确方向，2=模糊方向，1=不想继续，0=没注意到 |
| **Confidence Awareness** | 复盘访谈 — "你觉得这个解释可靠吗？" | 3=注意到 confidence 标识并正确理解，2=注意到但理解有偏差，1=没注意到 |

### 3.3 不采集的指标

| 不采集 | 理由 |
| --- | --- |
| CS 阅读时间 | 需要 timer，且阅读时间 ≠ 理解程度 |
| 眼动追踪 | 设备/环境限制，M83 不需要 |
| NPS / 满意度评分 | M83 不是产品满意度调研，是行为验证 |

## 4. Success Criteria

### 4.1 定量标准

| 指标 | 成功阈值 | 临界值 | 失败阈值 |
| --- | --- | --- | --- |
| **Expand Rate** | ≥ 60%（多数 Explorer 主动阅读 CS） | 30-60% | < 30% |
| **Causal Conversion Rate** | ≥ 50%（半数 CS 触发后续探索） | 20-50% | < 20% |
| **Exploration Depth** | 含 CS 的 session 深度 ≥ 不含 CS 的 session 深度 | 持平 | < 不含 CS 的 session |
| **Evidence Open Rate** | ≥ 20%（少数 Explorer 关心证据来源） | 5-20% | < 5% |

### 4.2 定性标准

| 指标 | 成功阈值 |
| --- | --- |
| **Mechanism Recall** | ≥ 3/4 Explorer 评分 ≥ 2（能部分复述） |
| **Exploration Intent** | ≥ 3/4 Explorer 评分 ≥ 2（有探索方向） |
| **Confidence Awareness** | ≥ 2/4 Explorer 评分 ≥ 2（注意到 confidence） |

### 4.3 综合判定

| 结果 | 条件 | M84 方向 |
| --- | --- | --- |
| **PASS** | 定量 4/4 成功 + 定性 3/3 成功 | Semantic Object Expansion — CausalStatement 升级为独立 Object |
| **PARTIAL** | 定量 2-3/4 成功，或定性 2/3 成功 | Causal Presentation Enhancement — 优化 CS 呈现方式 |
| **FAIL** | 定量 ≤1/4 成功，或定性 ≤1/3 成功 | Causal Presentation Redesign — 重新设计因果信息呈现 |

### 4.4 特别关注：M85 决策依赖

| 如果... | M85 决策 |
| --- | --- |
| `cs_follow_entity` 率高但 `cs_guide_next` 率低 | Explorer 更喜欢自驱探索而非引导 — M85 的 Multi-hop 应设计为自驱路径而非引导路径 |
| `cs_guide_next` 率高但 `cs_follow_entity` 率低 | Explorer 更依赖引导 — M85 的 Multi-hop 应以 Guide 为主 |
| 两者都低（Causal Conversion < 20%） | 因果解释未改变探索行为 — M85 不应引入 Multi-hop |
| cs-008（印刷术→知识传播）的 Expand Rate 显著高于其他 | 多跳潜力被验证 — M85 的 Multi-hop 应优先从技术传播类 CS 开始 |

## 5. Sample Size

### 5.1 数量

```
4-5 场 Explorer Session
```

| 理由 | 说明 |
| --- | --- |
| **定性为主** | M83.4 是定性验证，Session Review 是主要方法，事件数据是辅助 |
| **M81a 经验** | M81a 的 5 场 Session 已证明 4-5 场足以发现产品问题 |
| **饱和点** | 4-5 场后，Explorer 行为模式通常开始重复，新增 Session 的边际信息量下降 |

### 5.2 Explorer 画像

| 维度 | 要求 |
| --- | --- |
| **历史知识水平** | 混合 — 2-3 名有一定历史兴趣（非专业），1-2 名对历史无特别兴趣 |
| **产品熟悉度** | 首次使用 History Explorer（不熟悉 Package 概念） |
| **探索动机** | 自然探索（非被要求 "找到因果解释"） |

## 7. Protocol Freeze Boundary

### Allowed

| 操作 | 范围 |
| --- | --- |
| 按本 Protocol 执行 4-5 场 Session | M83.4 |
| 采集事件数据（`cs_*` 事件 + `open_entity`） | localStorage |
| 进行复盘访谈 | Session Review |
| 汇总分析并产出 M83 Validation Report | M83.5 |

### Forbidden

| 操作 | 理由 |
| --- | --- |
| 在 Session 中引导 Explorer 关注 CS | 会产生观察者效应 — "你觉得这个解释怎么样？" 会改变 Explorer 的自然行为 |
| 新增事件类型 | M83.1 Instrumentation 已冻结 |
| 修改 CS 内容 | M83.2 Content Selection 已冻结 |
| 修改 CausalStatement Schema | C-7 |
| 新增 AI Runtime | C-6 |
| 在 Session 中使用 A/B 测试 | M83 是验证当前 CS 效果，不是对比不同版本 |

## 8. Verdict

```
READY (Frozen)
```

M83.3 Explorer Validation Protocol 已冻结：

- **验证目标**：拒绝 H0（CS 不改变行为），接受 H1（CS 改变行为）
- **Session 结构**：Phase A（基线）→ Phase B（有 CS）→ Phase C（持续）
- **指标**：6 项定量（事件驱动）+ 3 项定性（Session Review）
- **成功标准**：3 级判定（PASS / PARTIAL / FAIL → 不同的 M84 方向）
- **样本量**：4-5 场
- **特别关注**：cs-008 的多跳验证 + M85 的决策依赖
