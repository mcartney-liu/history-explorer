## Executive Summary

原始 M83.1 Design Review 的方向正确（扩展现有事件系统），但在三个地方违反了 M82 架构约束：
1. `causalConfidence` 字段将内容属性混入行为数据
2. `cs_confidence_notice` 事件将 M82 已降级的 curator metadata 重新提升为交互目标
3. 7 个事件对 M83 验证目标而言过度设计

修正后：5 个核心事件 + 1 个字段（`causalId`），增加 Causal Conversion Rate 指标。

## Check 1 — Event Schema Boundary

### 1.1 causalConfidence 字段审查

**原始设计**：

```typescript
interface UserBehaviorEvent {
  causalId?: string;
  causalConfidence?: string;  // "high"|"medium"|"low"|null
}
```

**问题**：`causalConfidence` 是 Semantic Layer 的内容属性，不是用户行为维度。将其放入 UserBehaviorEvent 会：

1. 违反 **Semantic/Behavior 分离** — M82 Trust Boundary 要求 Fact Layer / Semantic Layer / Behavior Layer 独立
2. 产生**错误归因** — 分析者可能直接解读 "用户更信任 high confidence 解释"，但用户可能根本没看到 confidence 标识
3. 在**离线关联中可替代** — `event.causalId` → `causal_statements.json` → `confidence` 即可完成关联

**判定**：**删除 `causalConfidence`**。保留 `causalId`。

### 1.2 cs_confidence_notice 事件审查

**原始设计**：

```typescript
"cs_confidence_notice"  // Confidence 标识被 hover/点击
```

**问题**：

1. Confidence 在 M82 中已被**降级**为 curator assessment metadata，不是用户交互目标
2. M83 的核心验证问题是 "用户是否理解因果解释"，不是 "用户是否注意到 confidence"
3. 采集 `cs_confidence_notice` 会**反向影响 UI 设计** — 开发者可能为了让这个事件好看而加大 confidence 标识，污染 Explorer 体验

**判定**：**删除 `cs_confidence_notice`**。如果确实需要了解用户是否关注 confidence，应在 Session Review 中定性询问，而非通过事件采集。

### 1.3 修正后 Event Schema

```typescript
// 仅新增 1 个可选字段
interface UserBehaviorEvent {
  action: BehaviorAction;
  entityGlobalId?: string;
  entityType?: string;
  tab?: string;
  packageSlug?: string;
  sourceId?: string;
  timestamp: string;
  causalId?: string;           // M83.1 — CausalStatement ID
  // causalConfidence 不采集 — 通过 causalId 离线关联 causal_statements.json
}
```

### 1.4 需要 confidence 时如何获取

```
event.causalId = "cs-001"
    ↓
causal_statements.json[cs-001].confidence = "high"
    ↓
离线关联（Session Review 时手动执行，不需要事件携带）
```

**这保持了 Behavior Data 和 Semantic Data 的分离。**

## Check 2 — Event Minimalism

### 2.1 原始 7 事件 vs 建议 5 事件

| 原始事件 | 保留？ | 说明 |
| --- | --- | --- |
| `cs_card_view` | ✅ | 用户看到 CS — 最小验证闭环的起点 |
| `cs_card_click` | → `cs_card_expand` | 重命名 — "click" 太泛，"expand" 表示主动展开/阅读 |
| `cs_mechanism_read` | ❌ 合并 | 合并到 `cs_card_expand` — 展开即表示阅读，细分 mechanism/consequence 对 M83 验证无额外价值 |
| `cs_consequence_read` | ❌ 合并 | 同上 |
| `cs_evidence_click` | → `cs_evidence_open` | 重命名 — "open" 表示打开证据源，"click" 太泛 |
| `cs_guide_next` | ✅ | 用户接受 CS 理由后的 Guide 推荐 — Causal Conversion 的关键信号 |
| `cs_confidence_notice` | ❌ 删除 | 违反 Semantic/Behavior 分离（Check 1.2） |

### 2.2 修正后 5 事件

```typescript
type BehaviorAction =
  | ...  // 已有 17 种事件
  | "cs_card_view"       // CS Card 被渲染（曝光）
  | "cs_card_expand"     // 用户主动展开/阅读 CS（点击 Card 或展开详情）
  | "cs_follow_entity"   // 用户沿因果链继续探索（点击 cause/effect 实体）
  | "cs_guide_next"      // 看到 CS 理由后点击 Guide 下一步
  | "cs_evidence_open"   // 用户打开证据来源
```

### 2.3 5 事件覆盖的验证维度

| 验证维度 | 事件 | 能回答的问题 |
| --- | --- | --- |
| **曝光** | `cs_card_view` | 用户有机会看到 CS 吗？ |
| **参与** | `cs_card_expand` | 用户主动阅读了吗？（View-to-Expand Rate） |
| **因果跟随** | `cs_follow_entity` | 用户沿因果继续探索了吗？ |
| **引导转化** | `cs_guide_next` | CS 理由比模板 reason 更有效吗？ |
| **证据追溯** | `cs_evidence_open` | 用户关心证据来源吗？ |

**5 事件足以覆盖 M83 的 3 个验证目标（Understanding / Comprehension / Exploration Behavior）。**

## Check 3 — Metrics

### 3.1 修正后指标集

| # | 指标 | 公式 | 事件 | M83 验证目标 |
| --- | --- | --- | --- | --- |
| M1 | **CS View Rate** | `cs_card_view` / 含 CS 路径的 session 数 | `cs_card_view` | 曝光基线 |
| M2 | **CS Expand Rate** | `cs_card_expand` / `cs_card_view` | `cs_card_view` + `cs_card_expand` | 用户是否主动阅读 |
| M3 | **Causal Conversion Rate**（新增） | `cs_follow_entity` or `cs_guide_next` after `cs_card_view` / `cs_card_view` | `cs_card_view` + `cs_follow_entity` + `cs_guide_next` | **核心指标** — 因果解释是否改变探索行为 |
| M4 | **CS Guide Follow-through** | `cs_guide_next` after `cs_card_view` / `cs_card_view` | `cs_card_view` + `cs_guide_next` | CS 理由 vs 模板 reason 对比 |
| M5 | **Evidence Open Rate** | `cs_evidence_open` / `cs_card_view` | `cs_card_view` + `cs_evidence_open` | 用户是否关心证据来源 |

### 3.2 Causal Conversion Rate — 详细定义

```
Causal Conversion Rate

= CS-triggered sessions with next exploration action
  / CS-triggered sessions

CS-triggered session:
  session 中出现 ≥1 次 cs_card_view

Next exploration action:
  cs_follow_entity OR cs_guide_next（发生在 cs_card_view 之后）

阈值：
  > 30% → 因果解释有效改变了探索行为
  < 10% → 因果解释没有改变探索行为，M84 应重新设计呈现方式
```

### 3.3 为什么不把 "点击 cause/effect 实体" 和 "Guide 下一步" 合并为 Causal Conversion

两个事件代表了不同的用户意图：

- `cs_follow_entity` = 用户**主动**选择因果链中的实体继续探索（自驱探索）
- `cs_guide_next` = 用户**接受**系统的引导推荐（引导探索）

如果只采集一个，会丢失这个关键区别。两个事件加起来 = Causal Conversion。
