# M89.1 — Explorer User Journey v2
### Strict Read-Only / Experience Design Freeze

> 模式声明：严格只读。冻结 5 Phase 用户旅程、心理状态转换、Runtime 消费关系。不写代码。

---

## 一、核心目标

不是设计页面。是定义：**一个陌生用户 15 分钟内经历 Curiosity → Understanding → New Question 的心理状态转换过程。**

---

## 二、五阶段总览

```
Phase 1: Curiosity     — "不知道，但想知道"
    ↓
Phase 2: Orientation   — "我要理解什么？"
    ↓
Phase 3: Exploration   — "我知道下一步为什么"
    ↓
Phase 4: Understanding — "我真的理解了吗？"
    ↓
Phase 5: Growth        — "下次还能继续"
```

---

## 三、Phase 1 — Curiosity（好奇入口）

### 用户心理状态
"不知道，但想知道。" 带着模糊好奇进入产品，第一秒需要知道：这里能帮我理解什么？

### 用户目标
30 秒内找到一个自己真正想理解的问题并选择它。

### 系统责任
- 用问题而非主题名引导用户
- 展示"这个问题涉及哪些维度"
- 不让用户面对技术代号或搜索框

### 消费 Runtime 数据

| Runtime 能力 | 前端使用 |
|-------------|---------|
| `HistoricalKnowledgeProjection.topicName` | 入口标题 |
| `HistoricalKnowledgeProjection.description` | 入口副标题 |
| `HistoricalKnowledgeProjection.dimensions[]` | "这个问题涉及 X 个维度" |
| `understandingTemplate.requiredDimensions` | 维度预览 |

### 页面表达目标
- 一个入口 = 一个问题（如"法国大革命为什么发生？"）
- 显示问题 + 一句话描述 + 涉及维度数量
- 点击后进入 Phase 2

### 成功信号
用户能回答："我现在想弄明白什么？"

### 失败信号
用户说："这是什么意思？""我该选哪个？"

### 对应 M85 EO
EO-001

---

## 四、Phase 2 — Orientation（定位锚定）

### 用户心理状态
"我要理解什么？" 选定问题后，需要确认自己没走错，知道前方有什么。

### 用户目标
获得一段定位承诺——"你要理解的是 X，涉及 A/B/C 维度，我们先从 Y 开始。"

### 系统责任
- 展示当前主题 + 理解目标
- 展示维度清单（已覆盖 / 未覆盖）
- 展示 coverage 进度
- 预告第一步

### 消费 Runtime 数据

| Runtime 能力 | 前端使用 |
|-------------|---------|
| `ExplorationState.currentTopic` | 主题标题 |
| `ExplorationState.coveredDimensions` | 已理解维度（初始为空） |
| `ExplorationState.missingDimensions` | 尚未探索的维度 |
| `ExplorationState.coverageRatio` | 覆盖进度（0/N） |
| `ExplorationAction.narrativeHook` | 第一步预告 |

### 页面表达目标
- Orientation Panel：主题 + 维度地图 + 第一步预告
- 维度地图：每个维度显示名称 + 状态（已覆盖 / 待探索）
- 不展示任何实体列表或数据卡片

### 成功信号
用户注意力转向"那第一个是什么？"，不再退回重选。

### 失败信号
用户退回入口；随机点击第一个实体。

### 对应 M85 EO
EO-002

---

## 五、Phase 3 — Guided Exploration（引导探索）

### 用户心理状态
"我知道下一步为什么。" 这是 History Explorer 区别于 Wikipedia 的核心——每一次跳转都有认知理由。

### 用户目标
完成 3-5 次有意义跳转，每次能回答"因为 A，所以探索 B。"

### 系统责任
- 每次跳转展示 Navigation Contract：From / Why / Value
- 展示当前实体/关系的内容
- 展示下一步探索建议（来自 ExplorationAction）
- 更新维度覆盖状态

### 消费 Runtime 数据

| Runtime 能力 | 前端使用 |
|-------------|---------|
| `ExplorationAction.reason` | "为什么看这个" |
| `ExplorationAction.narrativeHook` | 叙事钩子 |
| `ExplorationAction.targetRef` | 跳转目标 |
| `ExplorationAction.expectedGrowth` | 预期认知收益 |
| `Decision.trace` | 可审计的来源 |
| `ExplorationState`（更新后） | 维度覆盖变化 |

### 页面表达目标
- **Navigation Card**：每次跳转前显示 From（你刚才看了 X）→ Why（因为 Y 关系）→ Value（帮你理解 Z）
- **Exploration Workspace**：核心页面——不是文章、不是聊天，而是"理解地图"
  - 左侧：当前探索内容
  - 右侧：维度覆盖状态 + 下一步建议
- **ExplorationAction** 渲染为可点击的"下一步"引导
- 用户主动选择是否采纳（不推送）

### 成功信号
连续 3 次跳转后，用户能解释"A 为什么带我到 B"。不产生"我怎么到这了"的困惑。

### 失败信号
用户说"我怎么到这了"；连续跳转无认知推进。

### 对应 M85 EO
EO-003

---

## 六、Phase 4 — Understanding Completion（理解闭环）

### 用户心理状态
"我真的理解了吗？" 经历了探索，需要确认自己获得了什么。

### 用户目标
产生"原来如此"的感受，能够复述因果链。

### 系统责任
- 当 coverageRatio 达到阈值或触发 reflect 时，展示理解总结
- 展示探索过程中的认知增长
- 引出新问题

### 消费 Runtime 数据

| Runtime 能力 | 前端使用 |
|-------------|---------|
| `ExplorationPolicy` 的 `reflect` Action | 触发总结 |
| `ExplorationMetrics.understandingGrowthScore` | 认知增长可视化 |
| `ExplorationMetrics.depthDelta` | 探索深度变化 |
| `ExplorationMetrics.dimensionDelta` | 维度覆盖变化 |
| `ExplorationMetrics.connectionDelta` | 关系发现变化 |
| `ExplorationState.coverageRatio` | 最终覆盖比例 |

### 页面表达目标
- **Understanding Completion Panel**：
  - "你从 X 维度到 Y 维度，覆盖了 Z 个维度"
  - 因果链总结（非 AI 生成，来自 RuleTrace）
  - "原来如此"的信号
- **New Question**：
  - 基于当前理解结构自然引出的下一个问题
  - 用户主动选择是否继续

### 成功信号
用户能复述因果链："因为 X，导致 Y，影响 Z，所以形成这个结果。"产生"原来如此"。

### 失败信号
用户只能说"我看了很多资料"。

### 对应 M85 EO
EO-004

---

## 七、Phase 5 — Growth Continuation（持续成长）

### 用户心理状态
"下次还能继续。" 确认自己的理解被记住，知道可以回来。

### 用户目标
看到探索记录的认知价值（非页面浏览历史）。

### 系统责任
- 展示本次探索的认知总结
- 展示记忆中的理解状态
- 提供"下次继续"的入口

### 消费 Runtime 数据

| Runtime 能力 | 前端使用 |
|-------------|---------|
| `MemoryProjection` | 长期认知成长视图 |
| `ExplorationMetrics` | 本次探索的认知收益 |
| `ExplorationState.missingDimensions` | 尚未完成的方向 |

### 页面表达目标
- 不是"浏览历史"——是"理解记忆"
- 显示"你上次理解了 X，还缺 Y 维度"
- "继续探索"入口

### 成功信号
用户知道"我上次理解到哪里，还可以继续什么"。

### 对应 M85 EO
EO-005（持续可发现性）

## 八、最小体验闭环验证

### 条件
- 1 个主题：法国大革命
- 1 个用户：无历史专业知识
- 15 分钟

### 必须经历
```
问题产生（Phase 1）
    ↓
知道为什么探索（Phase 2）
    ↓
完成 3-5 次有意义跳转（Phase 3）
    ↓
形成理解（Phase 4）
    ↓
产生新问题（Phase 4 → Phase 5）
```

### 验收
用户能回答三个问题：
1. "你现在比开始时更理解这个历史问题吗？"
2. "你知道下一次可以继续探索什么吗？"
3. "你觉得它是在回答问题，还是带你理解一个主题？"
