# M85.3 Explorer Validation Design

> **阶段**：M85.3 — Explorer Validation（C5 验证设计）
> **类型**：Validation Design（遵循 M83.3 Protocol Freeze 模式，但更轻量）
> **日期**：2026-08-05
> **基线**：M85.2 Dataset Freeze + M85.1 Model Freeze
> **验证目标**：C5 — Relationship Explanation 本身有价值

---

## 1. 验证问题

```
C5：验证 relationship explanation 本身有价值

核心问题：
  用户需要的是 Relationship Link（两个对象之间的连接），
  还是 Relationship Explanation（为什么值得一起理解）？

子问题：
  Q1: 去掉 explanation 后，Explorer 的跨对象理解深度是否下降？
  Q2: explanation 是否帮助 Explorer 形成"对象之间的关系认知"？
  Q3: 不同 relation_type 的 explanation 价值是否不同？
```

## 2. 实验设计

### 2.1 Group A：仅链接（无 explanation）

```
CausalObjectDetailPage 底部：

相关解释：
  · 科举 → 文官体系
```

仅显示 target_id 对应的 CausalObject 名称，无任何解释文本。

### 2.2 Group B：完整 Semantic Relationship

```
CausalObjectDetailPage 底部：

相关解释：
  · 科举 → 文官体系
    秦代建立的中央治理模式，推动后续官僚选拔制度的发展，
    最终形成科举体系。
```

显示 target_id + relation_type 标签 + explanation 全文。

### 2.3 Session 结构

```
Phase 1：自由探索（5-8 分钟）
  → 打开至少 2 个含 related_causal_objects 的 CausalObject
  → Group A 或 Group B（随机分配）

Phase 2：复盘访谈（5 分钟）
  → 4 个固定问题（见 §3.3）
```

**不做对照实验**（不像 M83 的 Topic A-B 对照）。M85.3 的目标更窄：只验证 explanation 的价值。

### 2.4 样本

```
3-4 场 Session
  Group A：2 场
  Group B：2 场
```

不追求统计显著性。M85.3 是方向判断，不是能力验证。

## 3. 指标

### 3.1 保护变量：Relationship Discovery

在测量 explanation 价值之前，必须先控制一个混淆变量：**用户是否注意到了 Relationship 的存在**。

如果 Group B 的提升只是因为 explanation 文本增加了可见性（而非提供了理解价值），那么 C5 的结论是错误的。

| 变量 | 定义 | 评分 |
| --- | --- | --- |
| R1 — Discovery | 用户是否主动注意到 Relationship 区域 | 0=没注意 / 1=注意到但无兴趣 / 2=主动探索 |
| R2 — Understanding | 用户是否理解为什么这两个对象关联 | 0-3（§3.3 Q2） |
| R3 — Continuation | 从 Relationship 进入后是否继续探索 | 步数 |

**真正的 Semantic Value = R2（理解）的提升，不是 R1（可见性）的提升。**

### 3.2 定量指标

| 指标 | 定义 | 采集 |
| --- | --- | --- |
| Related Object Click Rate | 点击 related_causal_objects 中任意链接的比例 | 观察记录 |
| Cross-Object Exploration Depth | 从 related_causal_objects 进入后继续探索的步数 | 观察记录 |
| Explanation Read Time | 在 explanation 文本上的停留时间（仅 Group B） | 观察记录 |

### 3.3 定性指标

| 指标 | 定义 | 评分 |
| --- | --- | --- |
| Relationship Recall | Explorer 能否复述两个 CausalObject 之间的关系 | 0-3 |
| Relationship Understanding | Explorer 是否理解"为什么这两个对象放在一起" | 0-3 |
| Explanation Value Perception | Explorer 是否认为 explanation 有帮助（仅 Group B） | 0-3 |

### 3.4 复盘访谈（4 个固定问题）

```
Q1: "你注意到页面底部的「相关解释」了吗？"
    → 采集 R1（Discovery）

Q2: "你觉得秦制和科举之间是什么关系？"
    → 采集 R2（Understanding）+ Relationship Recall

Q3（仅 Group B）: "那段解释文字对你有帮助吗？为什么？"

Q4: "如果只给你一个链接（没有解释文字），你还会点进去看吗？"
```

## 4. 判定标准

### 4.1 四种可能结果

| 结果 | 条件 | M85 走向 |
| --- | --- | --- |
| **Strong Universal** | 3/3 relation_type 的 Group B > Group A（R2 显著提升） | Semantic Relationship Framework 成立，全类型推进 |
| **Strong Selective** | 部分 relation_type 的 Group B > Group A，部分无差异 | Semantic Relationship 按类型选择性建设 |
| **Weak** | Group A ≈ Group B（R2 无差异），但 Click Rate 高 | M85 退化为 Navigation（链接足够，不需要 explanation） |
| **No Signal** | Click Rate < 20%（两组都低），R2 < 1 | M85 停止扩展，CausalObject 是稳定终态 |

### 4.2 Strong Universal 的详细条件

```
条件：
  1. R2（Understanding）Group B > Group A（至少 2/3 relation_type）
  2. Relationship Recall ≥ 2（Group B）
  3. ≥1 Explorer 在 Q4 中表示 "没有解释就不会点"
  4. R1（Discovery）在两组之间无显著差异（排除可见性偏差）

含义：
  explanation 提供了链接无法替代的理解价值。
  Semantic Relationship 作为独立的概念层成立。
  不是某一种关系类型有效，而是 Semantic Relationship Framework 有效。
```

### 4.3 Strong Selective 的详细条件

```
条件：
  1. 至少 1 个 relation_type 的 Group B > Group A
  2. 至少 1 个 relation_type 的 Group A ≈ Group B
  3. 差异与 relation_type 相关（非随机）

含义：
  不同 relation_type 的 explanation 价值不同。
  例如：civilization_contrast 可能比 institutional_evolution 更需要 explanation。
  M85 应该按 relation_type 选择性建设，而非全类型推进。
```

### 4.4 Weak 的详细条件

```
条件：
  1. Group A 和 Group B 的 Click Rate 相似
  2. R2（Understanding）在两组之间无显著差异
  3. Explorer 在 Q2 中只能说出表面关系（"都跟制度有关"），
     而非深层理解（"中央集权需要标准化选官"）
  4. Explorer 在 Q4 中表示 "有链接就够了"

含义：
  Explorer 需要"看到更多对象"，但不需要"理解对象关系"。
  M85 应该简化为 Navigation 而非 Semantic Relationship。
```

### 4.5 No Signal 的详细条件

```
条件：
  1. Related Object Click Rate < 20%（两组都低）
  2. R2（Understanding）< 1

含义：
  跨对象探索需求在真实环境中不显著。
  CausalObject 是稳定终态。
```

## 5. 特殊验证：不同 relation_type 的 explanation 价值

### 5.1 假设

```
institutional_evolution（#1 秦制→科举）：
  explanation 价值高 — 制度逻辑延续需要解释

technological_chain（#2 印刷术→造纸术）：
  explanation 价值高 — 技术链前提关系需要解释

civilization_contrast（#3 罗马法→秦制）：
  explanation 价值最高 — 跨文明对比完全依赖解释

ideological_influence（#4/#5）：
  待验证
```

### 5.2 观察方式

```
在复盘访谈 Q2 中，根据 Explorer 打开的 relation_type 提问：

  institutional_evolution：
    "秦制和科举之间是什么关系？"

  civilization_contrast：
    "罗马法和秦制有什么不同？"

观察：Explorer 是否能独立说出接近 explanation 内容的理解。
如果可以 → explanation 价值低（Explorer 自己能推导）
如果不可以 → explanation 价值高（Explorer 需要 curator 引导）
```

## 8. 一句话

```
M85.3 不是验证 "Semantic Relationship 是否被使用"，
而是验证 "explanation 是否提供了链接无法替代的理解价值"。

如果 explanation 只是链接的装饰 → M85 退化为 Navigation。
如果 explanation 改变了 Explorer 的理解 → M85 作为 Semantic Layer 成立。
```
