# M81a — Exploration Prototype Plan

> **Product Validation Gate（产品验证闸门），非 Engineering Milestone。**
> 本文件只定义一次探索体验验证实验，不写任何 frontend/backend 代码，不创建实际页面，不修改 M80.5 母文档，不进入 M83 / M83.5 实现。
> 它消费 `M80.5_EXPLORATION_EXPERIENCE_DEFINITION.md`（A2 Exit PASS），产出验证证据供 M63-A 选型与后续里程碑反验。

---

## 1. Prototype 定位

**M81a 为什么存在：**

M80.5 已从产品层定义了"用户为什么探索、为什么继续、为什么回来"。但这些定义是否成立、用户是否真能走通，必须做一次低成本的体验验证，而非直接进入工程实现。

M81a **不是**：
- 做 UI（无 React / Figma 生产页面）
- 做产品重构（不改既有的 domain / backend）
- 落地 Trail / Shell（归 M83）
- 实现 AI（归 M83.5）

M81a **是**：
- 一次 **Exploration Loop 验证实验**
- 验证 M80.5 定义的以下四项是否成立：
  - **First 5 Minutes**（North Star 三信号是否可命中）
  - **Exploration Loop**（八步是否自然发生、闭环是否成立）
  - **Object Model**（Graph Contract ≠ User Mental Model 是否站得住）
  - **Shell 三层状态模型**（Current State / Trail / Open Threads 是否可被用户感知）

**明确性质**：M81a 是 **Product Validation Gate**——过了它，M81b（Experience Repair）与 M82（语义增强）才并行展开；不过则回 M80.5 修正定义。

---

## 2. 验证目标（Validation Goals）

围绕 M80.5 第1节 First 5 Minutes 三个信号，验证用户是否能够：

1. **理解一个历史变化**
   用户能用自己话复述"某变化为何发生"（非仅看到卡片）。
   对应 North Star 信号 1。

2. **发现一个跨文明关联**
   用户主动点开一个非当前文明的对照节点并停留。
   对应 North Star 信号 2。

3. **主动点击一次未知方向**
   用户发出或在推荐中点击一个"我还想知道…"类动作，作为 Trail 未完成问题留存。
   对应 North Star 信号 3。

同时验证（Loop 层）：
- **Loop 是否自然发生**：进入→理解→关联→提问→探索→路径，是否无需引导即出现。
- **用户是否形成探索路径**：是否产出带顺序、带上下文的对象序列。
- **用户是否产生未完成问题**：是否出现"我还想知道"类悬念。
- **用户是否愿意继续探索**：暂离后是否表达回访意愿（Open Thread 成立性）。

## 3. Prototype 场景定义

选取 **2 个**历史探索场景作为验证样本，均基于现有 KG 数据，**不扩展新数据需求**。

**场景 A：制度承袭 — 一项制度的跨代演化**（v2，2026-08-03 替换）
- 体现：时间变化（唐→宋→元→明→清）、因果关系（科举确立→文官体系→明代内阁）、跨文明关联（佛教本土化融入中华文明 → 印度起源）。
- 映射 M80.5 首屏剧本（第1节 L43–53），作为主验证靶。
- **替换说明**：原场景「秦统一与汉承秦制」经运行态核验，秦朝实体在当前 KG 中不存在，秦汉制度承袭链无数据支撑；本阶段禁止补数据，故按 PO 决策替换为认知任务同构、数据完整的制度承袭链。依据 `M81a_VALIDATION_READINESS_SUMMARY.md`。

**场景 B：思想流动 — 某思想/技术的跨文明传播**
- 体现：时间变化（起源→扩散）、因果关系（传播动因）、跨文明关联（不同文明对同一思想的接受差异）。
- 用于交叉验证 Loop 在非"帝国"主题下的泛化性。

两个场景共用同一套 Object Model 语义与 Interaction Contract，验证其是否跨主题成立。

---

## 4. 用户任务设计（User Tasks）

不设计功能测试，只给测试者一个开放式探索任务，观察其自然行为。

**任务 A（主）**：
> "请探索：一项制度是怎样一代代传下来、又慢慢变样的？你在探索中想到任何问题都可以记下来。"

观察点：
- 是否理解入口（First 5 Minutes：知道自己在探索什么）
- 是否找到变化原因（North Star 信号 1）
- 是否发现跨文明关联（是否自发走出中华文明范围？North Star 信号 2）
- 是否产生下一步未知问题（North Star 信号 3）
- 是否形成路径、是否愿意继续

**任务 B（交叉）**：
> "请探索：某个思想或技术是如何在不同文明间流动的？"

观察点：
- Loop 是否在非帝国主题下同样自然发生
- Object Model 语义是否跨主题可懂
- 是否重复出现 A 中的受阻模式

两类任务均为**探索式任务**，不预设点击顺序，不考核功能覆盖率。

---

## 5. 验证指标

### 成功指标（5 分钟内应可观察）

- 用户**知道自己正在探索什么**（First 5 Minutes 锚点成立）。
- 用户**能够用自己的话描述一个变化原因**（信号 1 达成）。
- 用户**主动点击一个未知 / 跨文明方向**（信号 2 或 3 达成）。
- 用户产出**至少一条探索路径**（对象序列带顺序）。
- 用户表达**至少一个未完成问题**或**回访意愿**（Loop 闭环成立）。

### 失败信号（出现任一即判 M81a 未过 Gate）

- 用户**不知道下一步点什么**（Navigator 缺口，Loop 断裂）。
- 用户**只浏览节点列表**而未进入叙事（退化为图谱浏览器，Object Model 防退化失败）。
- 用户**把产品理解成百科**（Shell 误读为 TOC，第4节红线被破）。
- 用户**没有产生探索欲望**（North Star 失效，Loop 动机机制不成立）。
- 用户**要求"保存/收藏"**才肯离开（Trail 被误读为收藏夹，第4节红线被破）。

### 量化 Gate 判定（M81a PASS 硬阈值）

为避免"感觉验证成功"式主观结论，M81a 是否 PASS 不以定性印象裁定，而以**测试者行为达标率**硬阈值裁定。设有效测试者样本 N（建议 N ≥ 5，不足则仅作探索性参考、不裁定 Gate）。

**M81a PASS 须同时满足：**

- **≥ 80%** 测试者：完成 First 5 Minutes 三信号中的**至少两个**（理解变化 / 跨文明关联 / 主动点未知）。
- **≥ 60%** 测试者：**主动产生下一探索方向**（信号 3 或等价"我还想知道"动作）。
- **≥ 50%** 测试者：**产生未完成问题或回访意愿**（Loop 闭环成立性证据）。

**附加约束：**
- 任一**失败信号**（L109–115）在 ≥ 50% 测试者身上出现，即使达标率满足也判 **NEED REVISION**（主观误读类问题不可被数量掩盖）。
- 阈值用途：作为 **M83 是否大规模投入 / M63-A 是否启动选型** 的决策依据——达标则放行资源，未达标则回 M80.5 修正定义，不进入大规模工程。

> 阈值比例为首版建议值，PO 可在执行前按样本规模微调，但**必须在验证执行前锁定**，不得事后改动以迎合结果。

## 6. Prototype 范围边界

**包含（本计划允许的验证载体）**：
- **Flow**：用户从进入到暂离的完整行为流描述。
- **页面状态草图**：用文字/ASCII 描述每步的"状态"（非生产 UI），对应 Shell 三层。
- **用户路径模拟**：基于 M80.5 首屏剧本推演典型路径。
- **交互假设验证**：用 3.3 Interaction Contract 五原语检验前端原型是否守住防退化。

**不包含（明确排除）**：
- 生产 UI / React 组件开发
- 数据模型 / 后端 API
- Trail 存储结构（归 M83）
- AI 功能 / Agent / Runtime（归 M83.5）
- 任何对 Ontology / Schema / Runtime / Freeze Boundary 的修改

> 本阶段产物是**验证计划 + 后续验证记录**，不是可运行系统。

## 7. 与 M80.5 的映射关系

| M80.5 定义 | M81a 验证方式 |
| --- | --- |
| **First 5 Minutes**（第1节） | 任务 A/B 观察三信号是否 5 分钟内命中；首屏剧本作为主验证靶 |
| **Exploration Loop**（第2节） | 记录用户自然行为是否出现八步；标注断裂步与动机失效点 |
| **Object Model**（第3节） | 检验用户是否把对象理解为"主角/作用力/线索卡/故事句式"，而非节点/边/分数；出现图谱浏览器倾向即失败 |
| **Interaction Contract**（3.3） | 用五原语（点击/展开/深入/返回/Record）核对原型交互是否每条回 Loop；出现"看了数据无进展"即违约 |
| **Exploration Shell**（第4节） | 用三层模型（Current/Trail/Open Threads）核对用户是否感知"活着的探索"而非收藏/历史/目录；出现三误读即失败 |
| **AI Role Discovery**（第5节） | 仅观察受阻点（5.1 七步），记录 AI 需求位置；不实现、不选型 |

## 8. AI 观察项

只记录用户在探索中**自然产生**的以下四类信号，作为 M83 前 M63-A 决策依据：

- **理解困难**：在哪一步卡住看不懂（对应 Interpreter 需求，步骤2/3）。
- **下一步选择困难**：在哪一步不知点哪（对应 Navigator/Guide 需求，步骤1/5）。
- **比较需求**：是否主动想对照不同文明/事件（对应 Analyst 需求，步骤3/4）。
- **深入追问需求**：是否就某关系/因果追问"为什么/怎么样"（对应 Interpreter/Guide，步骤2/5）。

记录形式：按 Loop 步骤归类的受阻频次表（复用 5.1 七步框架）。

**禁止**：基于本观察**提前决定** Companion / Toolbox。选型留待 M83 前，与本计划 5.5 一致。

## 10. Validation Session Design（验证会话设计）

**问题**：第4节定义了"用户任务"，但缺少"谁观察、怎么记录"。若无观察规范，验证易退化为"用户觉得不错"的主观反馈，使第5节量化 Gate 失去数据来源。

**三方角色（每次验证会话至少就位）**：

| 角色 | 职责 | 禁止 |
| --- | --- | --- |
| **Explorer（普通用户）** | 执行第4节探索任务，自然行为，不被引导 | 不得被提示"应该点哪"；不得被暗示预期答案 |
| **观察者（Observer）** | 静默记录行为发生表（见下），不介入 | 不得与 Explorer 对话、不得解释界面 |
| **主持人（Facilitator）** | 仅提供任务脚本（第4节原文），回答"怎么操作"级问题 | 不得引导探索方向、不得评价内容 |

**行为记录表（观察者逐人填写，客观发生项打勾）**：

| 行为 | 是否发生 | 备注（步骤/场景） |
| --- | --- | --- |
| 用户是否主动探索下一节点 | ☐ | 对应 Loop 步骤5 |
| 用户是否回看之前路径 | ☐ | 对应 Shell Trail/Open Threads |
| 用户是否提出"为什么" | ☐ | 对应 Interpreter 需求（步骤2/3） |
| 用户是否比较其他文明 | ☐ | 对应 Analyst 需求（步骤3/4） |
| 用户是否询问来源 | ☐ | 对应 Evidence 溯源需求 |
| 用户是否停留（超阈值） | ☐ | 对应信号2 停留判据 |

**记录纪律**：
- 只记**可观察行为**，不记"用户好像感兴趣"类推断。
- 主观感受（如"用户觉得不错"）**禁止**进入验证记录，仅允许在独立问卷区另列、且不参与 Gate 裁定。
- 该表直接供给第5节量化 Gate 的行为计数与第8节 AI 观察证据。
