## 二、Understanding Workspace State（唯一状态对象）

UI 不读取 Entity、不读取 KG、不判断关系。UI 只消费这一个对象。

注意：**`UnderstandingWorkspaceState` 不是新的 Runtime 状态。它是 Experience Projection（体验投影层）——把系统能力翻译成人能理解的状态。** 它不反向影响 Runtime，避免循环依赖。

```typescript
UnderstandingWorkspaceState {
  // ── 大问题 ──
  question: string                          // "法国大革命为什么发生？"

  // ── 理解信念 ──
  startingBelief: string                    // 用户最初的 belief（不变）

  // ── 当前 Evidence ──
  currentEvidence: {
    id: string
    questionAnswered: string                // 这个 Evidence 回答什么小问题
    understandingGap: string                // 它填补了什么理解缺口
    materials: {
      text: string                          // 核心描述
      facts: string[]                       // 关键事实
    }
    transition: {
      before: string                        // 进入前理解
      after: string                         // 离开后理解
      dimensionAdded: string                // 新维度
    }
  } | null                                  // null = 初始 Orientation 状态

  // ── 理解路径 ──
  understandingPath: {
    nodes: { dimension: string; completed: boolean }[]
    connections: { from: string; to: string; reason: string }[]
    currentNodeIndex: number
    totalNodes: number
  }

  // ── 下一步 ──
  nextAction: {
    reason: string                          // 为什么下一步是这个
    hook: string                            // 叙事钩子
    targetEvidenceId: string
  } | null                                  // null = Closure 状态

  // ── 反思（Closure 时） ──
  reflection: {
    observedChange: string                  // 系统观察到的理解变化
    newQuestion: string                     // 自然引出的下一个问题
  } | null                                  // null = 非 Closure 状态

  // ── 阶段 ──
  phase: 'orientation' | 'exploring' | 'closure'
}
```

关键区别：
- `currentBelief` 移除 → 系统不替用户定义"你现在理解了什么"
- `reflection.observedChange` 新增 → 系统描述观察到的变化（非"你应该理解"）
- `currentEvidence.questionAnswered` + `understandingGap` 新增 → Evidence 是"对一个理解缺口的回应"，防止退化为 Entity Detail Page

### Phase 3: closure（coverage=3/3）

```typescript
{
  phase: 'closure',
  question: "法国大革命为什么发生？",
  startingBelief: "革命就是人民不满意国王，把他推翻了。",
  currentEvidence: null,                    // 不再展示 Evidence
  understandingPath: {
    nodes: [
      { dimension: '财政', completed: true },
      { dimension: '政治', completed: true },
      { dimension: '社会', completed: true },
    ],
    connections: [
      { from: '财政', to: '政治', reason: '财政危机迫使召开三级会议' },
      { from: '政治', to: '社会', reason: '政治制度不公根源于社会结构不平等' },
    ],
    currentNodeIndex: 3,
    totalNodes: 3,
  },
  nextAction: null,                        // Closure 无下一步
  reflection: {
    observedChange: "从'革命=人民推翻国王'到'革命=财政、制度、社会结构多重危机叠加的过程'",
    newQuestion: "为什么革命最后产生了拿破仑？",
  },
}
```

注意：`reflection.observedChange` 是系统观察到的变化，不是"你应该理解..."。系统不替用户定义理解——用户可能说"原来不是一个坏国王导致的"，这已经成功。

## 四、法国大革命最小闭环（3 个 Evidence）

**不是 6 个维度。真人实验只需要 3 个。**

```
Evidence 1 — 财政危机
  before: "国王没钱"
  after:  "旧制度无法解决财政问题"

Evidence 2 — 三级会议（政治）
  before: "国王开会"
  after:  "制度暴露了特权与平民的矛盾"

Evidence 3 — 第三等级（社会）
  before: "人民反抗"
  after:  "98%的人无权力——结构性的不平等"

Closure
  财政 → 政治 → 社会
  你的理解从"人民推翻国王"变为"多重危机叠加的必然结果"
```

**为什么只做 3 个**：真人实验验证的是"用户有没有感受到理解变化"，不是"法国大革命知识是否完整"。

## 五、UI 消费规则

```
✅ UI 只读取 UnderstandingWorkspaceState
❌ UI 不读取 Entity / KG / ExplorationPolicy
❌ UI 不判断关系、不决定下一步

数据流：
  FRENCH_REVOLUTION_PROJECTION
      ↓
  buildExplorationState() → ExplorationState
      ↓
  evaluateExploration() → ExplorationAction
      ↓
  buildWorkspaceState() → UnderstandingWorkspaceState
      ↓
  UI 渲染
```

`buildWorkspaceState()` 是一个新函数，负责将 Runtime 数据转换为 UI 可消费的单一状态对象。
