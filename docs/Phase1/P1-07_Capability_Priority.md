## 0. 定级规则与判据

### 0.1 定级的唯一尺子：产品使命

定级不按实现难度、不按代码量、不按已有页面，只按**去掉这项能力之后，使命的哪一句会落空**。

| # | 使命句 | 出处 |
|---|--------|------|
| 使命一 | 帮助用户逐渐形成文明、理解、认知结构的探索系统 | Product_Constitution Article 0 · 对象层 |
| 使命二 | 帮助用户找到自己的兴趣和自己的学习方法 | Article 0 · 主体层 |
| 使命三 | 帮助用户无限逼近真相 | Article 0 · 真值层 |
| 使命四 | 用户进来时好奇，离开时有一个更聪明的自己 | 北极星 understandingGrowthScore |

### 0.2 三档定义

| 档位 | 定义 | 判定测试 |
|------|------|---------|
| **P0** | 使命必需。缺它，产品的存在理由直接失败 | 删掉它，四句使命中至少一句**完全无承接者**，且没有任何其它能力能代偿 |
| **P1** | 完整可信的体验所必需 | 删掉它，使命仍有承接者，但体验残缺、不可信或链条易断 |
| **P2** | 增强 / 未来 / 依附于未裁决项 | 已被裁决降级、对三层定位支撑最弱、或其存在形态本身取决于一项未决问题 |

### 0.3 三项修正因子（按任务书要求逐项落实）

| 因子 | 处理方式 |
|------|---------|
| (a) 今天是否真的在服务用户 | **不下调优先级**。实现状态是第 3 节「优先级 vs 现实」的输入，不是定级的输入。若按已实现程度定级，会把「已交付」误当成「重要」，正是 FRW 要消除的偏差 |
| (b) 是否被未决问题阻塞 | 若未决问题决定「这项能力是否应当存在」→ 计入 P2；若只决定「由谁实现 / 走哪条路径」→ 保持原档，在第 4 节标注条件性 |
| (c) 供需倒挂严重度 | **上调优先级**。需求强而供给弱不是降级理由，是最高优先级的理由。C14 据此定 P0 |

### 0.4 纪律

本文档不讨论 UI、不讨论视觉、不讨论交互、不讨论实现方式。能力身份一律沿用 P1-01 的 C01–C30，不新增、不合并、不改名。

## 3. 优先级 vs 现实（本文档的核心交付）

本节回答 Phase 2 最需要知道的一件事：**被定为 P0 的能力，今天有几项真的在服务用户。**

判定口径：能力必须从服务路径可达，且其产出对用户构成可用的能力，才计「在服务」。仅有数据、仅有类型定义、仅存在于游离白名单的前端语义层，一律不计。

### 3.2 三条最刺眼的落差

**落差一：P0 能力位上跑着一个禁止项（最危险）**

C16 不只是「缺席」。它的产品位置**正被一个违反 M88.0 的实现占据**：`/entity/{id}/recommendations` 是公开 REST 端点、有正式立项编号 M9-001、被 15 个测试用例冻结为既成事实（P1-05 C-01）。按 M88.0 §3 的五维判定表，它有四个维度落在「禁止」一侧。

含义：用户今天已经在使用一个「下一步」能力，但那不是 C16，是 X01 的实质形态。每多存在一天，前端与用户心智就多绑定一天（P1-04 §6）。**这不是「P0 没做」，是「P0 被反向实现了」。**

**落差二：使命二（找到自己的兴趣与学习方法）交付率为 0**

主体层的四项支撑 C18 / C19 / C20 / C22 全部不在服务：C22 纯纸面、C18 无持久化、C19 的连续性分量因此不可得、C20 两套并行且定义互斥。四者互为依赖（P1-04 图 A：Mirror → Trail / State / Metrics），因此不是四个独立缺口，而是**一条完整链路整体缺失**。Article 0 明文「三层缺一不可」，当前实际交付的是两层。

**落差三：真值底座数据齐备，却没有一条通向用户的路**

C06（43 条三级来源）、C07（76 条证据主张）数据完整、代码完整、测试完整，但来源分级与异议叙述**没有任何出口**（P1-03 §2.6、P1-04 断点 4）。P09 承诺的「在任一结论处都能看见证据强度、来源分级与异议叙述」，在依赖图上是断的。

含义：使命三目前是一项**后台质量属性**，不是用户可感知的能力。它是三条落差里修复成本最低的一条——料在、线不在。

### 3.3 按使命句统计的交付率

| 使命句 | P0 能力数 | 完整在服务 | 交付状态 |
|--------|----------|-----------|---------|
| 使命一 形成认知结构 | 5（C01 C02 C10 C13 C14） | 2 | 只有事实与关系结构在服务；解释、理解、对比三层全断 |
| 使命二 找到兴趣与方法 | 3（C18 C20 C22） | 0 | 整层缺失 |
| 使命三 无限逼近真相 | 3（C06 C07 C08） | 0（1 项部分） | 料齐、出口无 |
| 使命四 离开时更聪明 | 4（C15 C16 C19 C23） | 0（1 项部分） | 缺口输入不存在，度量不可得，方向被违规实现占据 |

**给 Phase 2 的一句话**：优先级矩阵与交付实况几乎不重叠。任何以「我们已有这些 P0 能力，前端把它们接起来即可」为前提的方案都会落空——15 项 P0 中有 11 项**没有可接的东西**。

## 4. 定级的条件性（依赖 PO 裁决）

以下定级不是终局，其成立与否取决于未决问题。本节只标注条件，不代替 PO 裁决。

| 未决项 | 受影响能力 | 定级的条件性 |
|--------|-----------|-------------|
| **Q-01** Next Node 决定权（AI / 推荐算法 / ExplorationPolicy 三选一） | C16、C15、C27 | C16 定 P0 的依据是「由认知缺口决定方向」。若裁决取(甲)保留 AI/推荐决定方向，则 C16 的 P0 依据消失、C15 失去唯一消费者、X01 防火墙须自宪法层重写；若取(乙)或(丙)，C16 维持 P0 且 C15 升为其硬前置。C27 的「顺序由谁写」同随此裁决 |
| **Q-02 / OD-02** Cognitive Mirror 层归属 | C22、C20、C15、C19 | C22 定 P0 的依据是 Article 0 第二句，与落层无关，因此**不因未裁决而降级**。但不裁决则 C22 的上游无法定义（P1-05 C-07），该 P0 无法转化为任何 Phase 2 工作项；其三项原料 C20 / C15 / C19 的排期亦随之待定 |
| **Q-03** `/entity/{id}/recommendations` 处置 | C16 | 决定 C16 的位置是被腾出还是继续被占据。裁「保留」则 C16 的 P0 在实现上无处落地——两个「决定下一步」的能力不可并存（P1-05 R-1） |

1. **P0 15 项 / P1 11 项 / P2 4 项。** P0 占半数，与 P1-04 独立得出的「9 项不可删除」同向，不是分级过宽。
