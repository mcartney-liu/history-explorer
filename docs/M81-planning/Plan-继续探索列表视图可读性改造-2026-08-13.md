# 方案：「继续探索 / 可解释关联」列表视图——可读性改造

> 提出：PO（翔哥）2026-08-13
> 状态：**待 PO 审批，未动工**（FRW 铁律：审批前不写代码）

---

## 一、问题现象（PO 截图实证）

实体页「研究 tab → 继续探索」区块（`ConnectionsExplainedPanel` 列表视图），每条形如：

```
civ-greek
Roman Civilization (Civilization) influenced Ancient Greek Civilization (Civilization)

civ-persian
Roman Civilization (Civilization) influenced Ancient Greek Civilization (Civilization);
Ancient Greek Civilization (Civilization) was influenced by Achaemenid Persi… (Civilization)
```

**用户看懂成本高**。

## 二、4 个具体痛点 + 根因

| # | 痛点 | 根因（代码定位） |
|---|------|-----------------|
| 1 | 实体 ID 是英文（`civ-greek`） | 列表视图 `displayName(item.global_id)` 对 path 数组里的中间节点失效，只翻译了主节点 |
| 2 | 关系描述是英文句式（`influenced`、`was influenced by`） | 后端返回的 explanation 是英文，列表视图直接 `.ce-item` 展示，无翻译 |
| 3 | 标题"可解释关联"不直观 | `t('common.explainableConnections')` = `可解释关联`（技术化） |
| 4 | "已查看"标记无说明 | 来自 JourneyCard 的 `visited`，但列表视图未渲染这块 |

## 三、改造方案

### 3.1 列表视图改为「卡片式」实体条目

每条从「ID + 整段英文描述」改为「**实体卡片 + 关键关系**」：

```
┌─────────────────────────────────────────────┐
│ 古代希腊文明          [文明]  已查看·距离 2  │
│ ────────────────────────────────             │
│ 罗马文明 → 影响 → 古代希腊文明              │
│ 古代希腊文明 → 受影响于 → 阿契美尼德波斯     │
│                                             │
│ 关键发现：地中海文明之间通过征服/贸易互相影响│
│                                  [查看详情 →] │
└─────────────────────────────────────────────┘
```

### 3.2 三处具体改动

| 改动 | 解决 |
|------|------|
| **实体 ID 翻译**：列表里的 ID 用 `getEntityDisplayName(gid, locale)` 翻译为本地化名称（已存在，**只需对 path 数组所有节点也调一次**） | 痛点 1 |
| **关系描述翻译**：把 "X influenced Y" 这种英文结构化句式翻译成中文——用 `getRelationshipLabel(rel, locale)`（已存在）+ 模板拼接 | 痛点 2 |
| **标题/文案改直白**：`可解释关联` → `继续探索`（在 JourneyCard 里已是这个名字，保持一致），加一行副标题说"按推理链展示与该实体的关联" | 痛点 3 |
| **"已查看"语义化**：JourneyCard 里的 visited 在 list 视图也展示，标 `[已查看]` 小角标 | 痛点 4 |

### 3.3 关系描述的中文化模板（新增小工具）

把英文结构化句 `X influenced Y` 翻译成中文模板 `X 影响 Y`：

```ts
// 数据/ai/relationshipZhFormatter.ts
function formatRelationshipZh(item: ConnectionExplained, locale: string): string {
  // 把 path 和 steps 拼成中文"罗马文明 → 影响 → 希腊文明 → ... → 波斯"
  // 用 getRelationshipLabel + getEntityDisplayName
}
```

## 四、涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/src/components/ConnectionsExplainedPanel.tsx` | 列表视图重写：用 `displayName(path[i])` 翻译所有节点 + 用中文模板拼关系描述 |
| `frontend/src/locales/zh/common.ts` | `'common.explainableConnections'` → `继续探索`（与其他位置命名一致） |
| `frontend/src/data/ai/relationshipZhFormatter.ts` | 新增：把后端英文结构化句翻译成中文"X → 影响 → Y"模板 |
| 测试 | 新增 formatter 测试 + ConnectionsExplainedPanel list 视图断言 |

**不改后端、不动 AI、不改数据、不改 freeze 白名单**。

## 五、验收标准

1. 列表里所有实体显示**中文名**（不再有 `civ-greek` 这种英文 ID）
2. 关系描述是**中文结构化句**（`罗马文明 → 影响 → 古代希腊文明`）
3. 标题与下方 JourneyCard 一致（`继续探索`）
4. 「已查看」标记有上下文（紧贴对应卡片）
5. 全量测试绿，TS 零错误，Freeze 通过

## 六、风险与回退

- 纯前端 UI 改造，列表视图本身就是「视觉/文字」层；改坏易 revert
- 推理链视图（默认 chain）不受影响
