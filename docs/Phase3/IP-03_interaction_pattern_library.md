## 0. 文档定位与铁律遵守

本文从 IP-01（统一规则）与 IP-02（逐触点契约）抽取**可复用的交互模式**。实现 Phase 4 时，任何交互必须映射到本库某一模式；不得新造未在本文登记的交互范式（守 X-R3 禁用多套范式）。

每个模式包含：

| 字段 | 含义 |
|------|------|
| 模式名 | P-xxx 标识 |
| 触发条件 | 何时启用 |
| 交互行为序列 | 用户动作 → 产品响应的标准序列 |
| 状态变化 | 触发哪些常驻层/认知态变化 |
| 适用触点 | 对应 IP-02 的 TP 编号 |
| 反例 | 禁止的变种（守红线） |

**一致性根基**：所有模式在四主干同构语法下表达一致；差异仅来自提问角度，不来自操作方式。

---

## 1. P-Anchor 锚点激活模式

- **触发条件**：用户对准一个对象（实体/结论/可比组/自身轨迹段）准备落定。
- **交互行为序列**：
  1. 单击锚点 → 激活并载入锚点内容（C-1）。
  2. 留在 Explorer Session 容器，不新开窗口/不跳转外部（N-1）。
  3. 原上下文保留为来源，写入 TP-20 轨迹链（B-1/B-2）。
- **状态变化**：更新 TP-15 覆盖态（已覆盖该锚点）。
- **适用触点**：TP-01/02/03/04/05/10/12/13/14/19/22/24/25/26。
- **反例**：点击锚点跳转到外部站点 / 新开标签页 / 离开 Session 容器（违反 N-1、守则 ①）。

---

## 2. P-Relation 关系展开模式

- **触发条件**：锚点存在连向其他锚点的关系（因果/邻接/同时/分岔）。
- **交互行为序列**：
  1. 单击关系目标端 → 以该端为新锚点展开（C-2/E-2）。
  2. 原锚点保留为来源（写入 TP-20）。
  3. 关系中的因果链可经 TP-16 `follow_cause` 转 Understand（IP-01 §3.1）。
- **状态变化**：更新 TP-15 已覆盖关系。
- **适用触点**：TP-02（主）/ TP-03 / TP-04 / TP-05 / TP-11（理由格关系）。
- **反例**：关系目标端不可点击 / 点击替换而非展开 / 丢失来源锚点（违反 C-2、E-2）。

---

## 3. P-Scale 真相刻度呈现模式

- **触发条件**：任一结论（Explore / Understand / Compare 下）出现，需附着可信度信息。
- **交互行为序列**：
  1. 刻度三件套（TP-06 来源分级 / TP-07 证据强度 / TP-08 溯源异议）**贴住结论出现**（TS-1）。
  2. 单击刻度 → 就地展开明细，不跳外链（TS-2）。
  3. 弱证据不隐藏；异议叙述按 ADR-0015 D7 呈现，解读权归用户。
  4. 折叠 = 与结论同显隐（F-2）。
- **状态变化**：无状态切换（只读呈现）。
- **适用触点**：TP-06 / TP-07 / TP-08（贴住 TP-01/10/13/14 等结论）。
- **反例**：刻度要求换主干才能看 / 跳外部链接查证 / 弱证据隐藏 / 空入口（违反 TS-1/TS-2、B1 §5、X-R7）。

---

## 4. P-Next 下一步呈现模式

- **触发条件**：用户一段探索完成，存在认知缺口（`coverageRatio` / `missingDimensions` / `missingConnections`）。
- **交互行为序列**：
  1. 常驻层 TP-16 呈现 A2 `ExplorationAction`（唯一出口，X-R6）。
  2. 五项候选对应五 actionType（IP-01 §3.1）：`open_dimension`→Explore / `follow_cause`→Understand / `deep_continue`→下沉 / `compare_context`→Compare / `reflect`→收束或引向 Mirror。
  3. 每项携带 `rationale.text`(理由可读) + `coverageBeforeAfter.delta`(缺口可见)（NP-2/E-3）。
  4. 单击 → `onNodeClick(targetEntity)` 依 actionType 导航（C-4）。
- **状态变化**：推进后更新 TP-15 覆盖。
- **适用触点**：TP-16（四主干下均在场）。
- **反例**：出现「推荐/猜你喜欢/相关内容/其他用户也看了」语汇（X-R1）；多出口（旧 `/recommendations`，X-R6）；个性化/打分表达（守 X01）；与 TP-24/TP-27 互相伪装（B3 §4.3）。

---

## 5. P-Switch 主干切换模式

- **触发条件**：用户从当前提问角度转向另一角度（Rail 点击）。
- **交互行为序列**：
  1. 单击 Rail 主干入口 → 切换主干（R-1/S-1）。
  2. 换提问角度，**不重建容器、不丢失常驻层**（S-1/PP-1）。
  3. 携带物：TP-23 叙述连续、TP-20 轨迹累加、TP-15 覆盖唯一、From/Why/Value 不清空（PP-2/守则 ⑧）。
  4. 不存在「切换主干 = 开始新探索」。
- **状态变化**：无覆盖态丢失；语言态不变（S-2）。
- **适用触点**：Rail（TP-14/10/01/19 各主干入口）；尤其 TP-16 `follow_cause`/`compare_context`/`open_dimension` 触发。
- **反例**：切换主干重置常驻层 / 清空轨迹 / 重建新容器 / 出现第五种主干（X-R4、X-R8、B3 §3 约束 3）。

---

## 6. P-Panel 面板模式

- **触发条件**：需在当前上下文就地展开一块信息（关系/理由/刻度/溯源）。
- **交互行为序列**：
  1. 触发展开 = 就地展开 Panel，不改变导航位置（A-1）。
  2. 面板内容承载关系列表/理由 `rationale`/刻度三件套/溯源清单（TP-08）。
  3. 折叠 = 收起回锚点，保留来源痕迹于轨迹（F-1/A-2）。
- **状态变化**：无。
- **适用触点**：TP-02(关系面板) / TP-11(理由面板) / TP-06/07/08(刻度面板) / TP-08(溯源面板)。
- **反例**：面板展开即跳转新页面 / 模态霸屏阻断主区 / 折叠丢失来源（违反 A-1、F-1）。

---

## 7. P-Rail 轨道模式

- **触发条件**：用户需要切换四条主干之一。
- **交互行为序列**：
  1. Rail 常驻呈现四条主干入口（R-1）。
  2. 单击 = 触发 P-Switch 主干切换模式。
  3. Rail 不可扩展出第五种主干（R-2/X-R4）。
- **状态变化**：无（切换由 P-Switch 处理）。
- **适用触点**：Rail（四主干切换入口）。
- **反例**：Rail 出现第五入口 / 主干以「模式/频道/产品线」形态分裂（违反 R-2、B3 §1.2 注）。

---

## 8. P-Dock 停靠模式

- **触发条件**：用户需查看/使用常驻层六项坐标之一。
- **交互行为序列**：
  1. Dock 常驻呈现 TP-15/16/18/20/23/28（D-1）。
  2. 单击任一项 = 展开其明细，不重置其他项（D-2）。
  3. 主干切换时 Dock 保持不消失（PP-1/守则 ⑧）。
- **状态变化**：D-2 不重置；状态更新由具体项决定。
- **适用触点**：TP-15/16/18/20/23/28（常驻层全项）。
- **反例**：切换主干时 Dock 隐藏/重置某一项 / 常驻层随主干分裂成多份（违反 D-2、PP-2、ST-1）。

---

## 9. P-Companion 伴随模式

- **触发条件**：当前锚点需同显辅助解释（解释粒度得当）。
- **交互行为序列**：
  1. Companion 与当前锚点同显（P-1），承载 TP-21 解释粒度。
  2. 不抢占 Workspace 主区焦点（P-2）；可独立折叠（P-3）。
  3. 解释权威顺序 = TP-12(AI Gateway) > TP-10(Causal) > TP-11(模板)（D4）；高阶不可用低阶以自身身份出场。
- **状态变化**：无。
- **适用触点**：TP-21（承载 TP-10/11/12 解释）。
- **反例**：Companion 抢占主区焦点 / 解释顺序颠倒（低阶冒充高阶）/ 到处生硬模板（违反 P-2/P-3、D4、TP-21 违约感受）。

---

## 10. P-Feedback 反馈模式

- **触发条件**：用户对任何动作需要可感响应。
- **交互行为序列**：
  1. 动作即时回执：接受 / 进行中 / 完成 / 缺口可见（FB-1）。
  2. 反馈只表状态不表评判（FB-2）。
  3. TP-27 确定性动作提示与 TP-16 方向决策语义不互相替代（FB-2/B3 §4.3）。
  4. 无推荐语汇（FB-3/X-R1）。
- **状态变化**：无（反馈不触发状态判定）。
- **适用触点**：全触点（尤其 TP-16/24/27 三者分野）。
- **反例**：反馈含「猜你喜欢」/ 对用户的个性化评判 / TP-27 伪装成 TP-16 推荐（X-R1、FB-2、B3 §4.3）。

---

## 11. P-State 状态切换模式

- **触发条件**：认知覆盖态 / 语言态 / 会话态发生变化。
- **交互行为序列**：
  1. 认知覆盖态（TP-15）全局唯一，不按主干各算（ST-1/PP-2）。
  2. 语言态（TP-28）切换只改术语不改对象身份（ST-2/S-2）。
  3. 会话态（TP-18/20）不持久化，离场即清空口径明示（ST-3/D6）。
  4. 切换即更新常驻层对应项。
- **状态变化**：覆盖态/语言态/会话态按上述规则更新。
- **适用触点**：TP-15 / TP-18 / TP-20 / TP-28。
- **反例**：覆盖态按主干分裂 / 语言切换改变对象身份 / 会话态持久化为长期画像（违反 ST-1/ST-2/ST-3、X-R5、D6）。

---

## 12. P-Animation 动画逻辑模式

- **触发条件**：状态变化需可见过渡（进入/退出/展开/折叠）。
- **交互行为序列**：
  1. 仅功能性过渡：进入 / 退出 / 展开 / 折叠（AN-1）。
  2. **禁用弹跳缓动** `cubic-bezier(0.68,-0.55,0.265,1.55)`；仅线性或缓入缓出 ease-in-out（AN-2/X-R2）。
  3. 动画可降级为瞬时切换（无障碍/低性能）（AN-3）。
  4. 动画不产生新交互含义（AN-4）。
- **状态变化**：无（仅表达既有变化）。
- **适用触点**：所有展开/折叠/切换/进入/退出场景（P-Panel / P-Switch / P-Dock / P-Anchor 等）。
- **反例**：使用弹跳缓动 / 装饰性无意义动效 / 动画承载推荐暗示（X-R2、AN-1~4）。

## 13. 容器族统一规范（Workspace / Companion / Panel / Dock / Rail）

> 四主干同构语法下，容器族交互完全一致。容器不是产品、不是模式、不是频道。

| 容器 | 角色 | 统一规范 | 反例红线 |
|------|------|---------|---------|
| **Workspace** | 主工作区，承载当前主干锚点/关系/理由/推进 | 单一主区；同一时刻仅一条主干活动；切换主干不换工作区（W-1~3） | 多工作区并存 / 切换主干重建工作区（X-R3） |
| **Companion** | 解释伴随层（TP-21） | 与锚点同显、不抢焦点、可独立折叠、守权威顺序 D4（P-1~3） | 抢占主区 / 顺序颠倒（P-2/P-3、D4） |
| **Panel** | 就地侧载信息块 | 就地展开不改导航、折叠回锚点保留来源（A-1/A-2） | 展开即跳页 / 模态霸屏（A-1） |
| **Dock** | 常驻层六项归所 | 常驻不消失、单项点击不重置其他、切换主干保持（D-1/D-2） | 切换重置 / 分裂多份（D-2、PP-2） |
| **Rail** | 四主干切换轨 | 四入口、点击切换、不可扩第五主干（R-1/R-2） | 第五入口 / 主干裂变（R-2、X-R4） |

**容器族一致性原则**：任意触点所处容器族及其交互行为在四主干下一致；差异仅来自提问角度。

## 15. 与 IP-01 / IP-02 的一致性

- 本库每个模式的「交互行为序列」均来自 IP-01 §2 维度规则；「适用触点」均来自 IP-02 §1–§6。
- 四主干同构语法下，同模式在四主干表现一致（IP-01 §5 八条一致性原则）。
- 任何 Phase 4 实现须映射到本库某一模式；新增交互范式须先登记（守 X-R3）。

## 16. Exit Criteria 自检

| 判据 | 回答 | 依据 |
|------|------|------|
| 是否覆盖 12 个要求模式？ | 是 | §1–§12（Anchor/Relation/Scale/Next/Switch/Panel/Rail/Dock/Companion/Feedback/State/Animation） |
| 是否含容器族统一规范？ | 是 | §13（Workspace/Companion/Panel/Dock/Rail） |
| 每个模式是否含 触发/序列/状态/适用/反例？ | 是 | 各节字段齐全 |
| 是否与 IP-01 规则一致？ | 是 | §14 映射总表 |
| 是否与 IP-02 触点一致（=C01–C30）？ | 是 | §14 适用触点均来自 IP-02 |
| 是否禁用弹跳缓动？ | 是 | P-Animation AN-2 / X-R2 |
| 是否禁用推荐语汇？ | 是 | P-Next / P-Feedback X-R1 |
| 是否提前设计（视觉/代码）？ | 否 | 全文仅交互模式 |
| 是否写了代码 / 颜色 / 字体？ | 否 | 全文规则与序列 |

**结论：IP-03 达成 Phase 3 交互模式库的 Exit Criteria，12 模式 + 容器族规范齐备，与 IP-01/IP-02 互一致。**
