## 一、你只需要做一件事

在 `data/examples/` 下的 **JSON 文件** 里，按下面的清单**添加关系**（`relationships` 数组里加对象）。
**不要改实体**（`entities` 数组不动）、**不要改类型**、**不要删已有内容**。

### 改哪几个文件？

| 文件 | 补什么 |
|---|---|
| `china_civilization_v1_example.json` | 中国文明（唐至清）↔ 世界的连接 |
| `textbook_cn_history_v1_example.json` | 中国史前-商周 ↔ 世界的连接 |
| `silk_road_example.json` | 丝路 ↔ 中国的连接（大部分加在这里） |
| `ancient_india_example.json` | 印度 ↔ 中国（佛教东传） |

> 关系要"成对"添加吗？**不用。** 关系是单向的（source→target），但图上两端的实体都能看到彼此。你只需要在**其中一个**文件里加关系即可，比如在 `silk_road_example.json` 里加 `han_dynasty → tp-tang`，唐朝那边自动能看到汉朝。

## 二、关系长什么样（照抄格式）

在 `relationships` 数组里，每个关系是一个对象，**必填 3 个字段**：

```json
{
  "source": "person-zhang-qian",
  "target": "china_v1:loc-changan",
  "type": "related_to"
}
```

### 三条铁律

1. **source / target 写实体 `id`**，不写中文名、不写英文名。
2. **本包实体**直接写短 id，例如 `person-zhang-qian`（丝路包内的张骞）。
3. **跨包实体**写 `包前缀:短id`，例如 `china_v1:loc-changan`（中国包的长安）。
   - 包前缀对照：中国文明包 = `china_v1`，中国史前-商周包 = `tb_cn_v1`，丝路 = `silk_road`，印度 = `ancient_india`，波斯 = `persian_empire`，希腊哲学 = `greek_philosophy`，埃及 = `egypt_technology_religion`，罗马 = `roman_empire`，希腊化 = `hellenistic_world`，早期基督教 = `early_christianity`

### 合法关系类型（18 种，不要发明新词）

`caused` `influenced` `participated_in` `located_at` `related_to` `before` `after` `contemporary_with` `part_of` `ruled` `traded_with` `invented` `discovered` `practiced` `spoke` `inherited` `conquered` `spread` `disputes` `reinterprets`

> 常用类型：`influenced`（影响）、`spread`（传播）、`before/after`（先后）、`contemporary_with`（同时代）、`traded_with`（贸易）、`related_to`（相关）、`inherited`（继承/传承）。

## 四、照着做的步骤

1. 用编辑器打开上面"改哪几个文件"里的 JSON 文件。
2. 找到 `"relationships": [ ... ]` 数组，在数组末尾（最后一个 `}` 后面）加逗号，然后粘贴新关系对象。
3. **检查 JSON 合法性**：逗号不能多不能少。可以用任意 JSON 校验工具，或直接跑第 5 步的脚本（它会报语法错误）。
4. 保存文件（**注意保持 UTF-8 编码**，文件里已有中文）。
5. 跑自检：`<python> scripts/data-patch-check.py`，看到：
   - `✅ 所有关系引用均已解析`
   - `✅ china_v1: 连接 ... 个实体 -> [...]`
   - `✅ tb_cn_v1: 连接 ... 个实体 -> [...]`
   - `⚠️ 仍存在重复: 长安/造纸术`（这两条重复提示在**去重决策前**是预期的，不算错）
   - 就算完成。

## 五、常见问题

**Q: 我怎么知道某个实体在哪个包、id 是什么？**
A: 打开目标包的 JSON，看 `entities` 数组里每个对象的 `id` 字段。跨包时在 id 前加包前缀（见铁律 3）。

**Q: 加完关系发现报"未解析引用"？**
A: 说明 source 或 target 的 id 写错了（本包短 id 打错，或跨包前缀/短 id 拼错）。对照 `entities` 数组核对。

**Q: 两个文件都要加同一条关系吗？**
A: 不需要。任何一条关系只要在任意一个文件里出现一次，全图就能看到。不要重复加，否则统计会虚高。

**Q: 中文名可以用吗？**
A: 不行。必须用 `id`（如 `person-kongzi`），因为关系是按 id 解析的。

## 六、验收标准（小梦负责）

1. `data-patch-check.py` 输出：0 error、0 未解析引用。
2. 跨包关系占比 ≥ 25%（当前 17%）。
3. 中国两包（`china_v1` / `tb_cn_v1`）均有跨包连接，且至少连到 3 个不同包。
4. 重复实体（长安/造纸术）按 PO 去重决策处理后 0 提示。
5. 冒烟验证：`/explore/china-civilization` 与 `/explore/silk-road` 页面互现关联实体。
