# M71 UX 体验测试材料 — 任务卡 / 观察清单 / 访谈提纲

> 阶段：M71 Phase 2 Exploration Validation（早期探索行为验证）
> 性质：本材料用于组织真实用户体验测试；本次执行中因无外部样本，以**内部系统化走查**补位并明确标注样本属性（非真实用户数据）。
> 定位表述：**早期探索行为验证 / 体验链路有效性评估 / 为 M72 优化提供依据**——不做"证明用户喜欢/验证商业成功"类结论。

---

## 1. 测试目标

验证探索链路 `Package → Journey → Guide → Cross Package` 是否**可理解、可走通、可持续**。形成早期假设验证：

- **H1**：用户进入官方包后会访问 ≥3 个实体
- **H2**：Guide「下一步 + 原因」会被使用并帮助决策
- **H3**：走完一个包后，用户会通过「推荐下一步」进入关联内容（跨包）

## 2. 用户任务设计（3 任务渐进）

| 任务 | 目标 | 验证点 | 预计时长 |
|---|---|---|---|
| **T1 自由探索** | 打开首页 → 选任一官方包 → 自由逛 | 自然路径、是否使用 Guide、退出点 | 5–8 min |
| **T2 定向旅程** | 指定《罗马帝国探索包》：看探索目标 → 走时间链 → 走关系链 → 展开来源 | Journey 各段可理解性、来源链是否被打开 | 8–10 min |
| **T3 跨包迁移** | 从中国包 → 按「推荐下一步」进入关联内容 | 跨包入口是否被发现、是否愿意继续 | 3–5 min |

**样本**：3–5 名体验者（内部同事 + 外部非专业用户，PO 组织）；每名约 20 min。本次执行：内部系统化走查（1 名操作者 + 浏览器自动化），样本属性如实记录。

## 3. 测试流程

```
准备（5min）→ 知情说明 + 任务卡 → T1 → T2 → T3 → 访谈（5min）→ 事件流导出 → 指标快照
```

每名体验者测试前执行 `clearEvents()`（localStorage 重置，避免旧事件污染）。

## 4. 观察指标（人工观察 + 录屏复核）

- 进入包后首动作（点击探索目标 / 滚动 / 点旅程节点 / 退出）
- Journey 各链段的**理解停留时间**与**展开行为**（来源是否被点开——`view_source` 未接入，人工观察补位）
- 退出点位置与原因（访谈确认）
- Guide「下一步」是否被点击、是否按推荐行动
- T3 跨包入口是否被自然发现

## 5. 成功/失败判定（早期验证口径）

| 判定 | 标准 |
|---|---|
| 链路可用 | ≥3/4 体验者完成 T1 且访问 ≥3 实体；≥2/4 在 T2 走完时间链+关系链 |
| Guide 有效 | ≥2/4 在 T2 主动点击 Guide「下一步」并循推荐行动 |
| 需修正 | 多数体验者 T1 即退出 / 看不懂探索目标 / Guide 从未被使用 |

> 注：以上为**内部基线参考**，非统计显著结论（样本量不足以做统计推断）。

## 6. 访谈提纲（5min）

1. 打开首页时，你第一眼看到什么？最想点哪里？
2. 「探索目标」告诉你这个包要搞懂什么了吗？
3. 时间链/关系链的箭头（早于/继承为）看得懂吗？
4. 探索向导的「下一步 + 原因」对你有帮助吗？是引导还是打扰？
5. 走到哪一步你想退出？为什么？
6. 看完一个包后，你想接着看什么？
